# 기준정보 API 재작성 계획

> 근거: [ADR 0001](./adr/0001-mdm-api-rewrite-on-spec.md) · 용어: [CONTEXT.md](../CONTEXT.md)
> 계약: `omf-mes/deliverables/openapi/mdm-기준정보.json` (0.1.0 초안)

## 범위

`mdm` 태그 **23개 경로 / 46개 오퍼레이션**. `/app`(16) · `/quality`(25) ·
`/planning`(17) · `/integration`(4) · `/audit`(1)는 다음 라운드.

| 묶음 | 대상 | 오퍼 |
|---|---|---|
| 전체 CRUD | 창고, 로케이션, 코드그룹, 코드값, 부서 | 25 |
| ERP 수신본 — 부분 편집 | 품목(본체 + 환산·외부코드·BU매핑), 작업자(자격) | 13 |
| 조회 전용 | 단위, 거래처, 법인, 사업부, 공장, 라인, 공정, 설비 | 8 |

## 확정된 것

1. `src/` 전체 삭제 후 스펙 기준 재작성. `prisma/` 는 정본이므로 유지.
2. 스펙 형태(경로·메서드·봉투·헤더)는 동결. 미결 내용은 구현하며 정하고 계약
   소유자에게 되돌린다.
3. `/mdm` 응답의 int64 는 JSON 숫자.
4. 스펙 사본을 `contracts/` 에 두고 타입을 생성해, 어긋남을 컴파일러가 잡게 한다.
   사본 갱신은 사람이 하고 그 diff 가 계약 변경 알림이다.
5. PR 단위는 "한 번에 읽고 이해되는가" 기준. 계약이 태어나는 구간은 잘게,
   패턴 복제 구간은 마스터 단위로.

## 스펙과 현행의 차이 (재작성 이유)

| 축 | 스펙 | 삭제 대상 코드 |
|---|---|---|
| 식별자 | `{warehouseId}` int64 | `:warehouseCode` 문자열 |
| 수정 | `PUT` 전체 교체 | `PATCH` 부분 |
| 중지 | `POST /{id}:deactivate` → 200 + 본문 | `DELETE /{code}` → 204 |
| 목록 | `{items, page:{page,size,total}}` | `{items,total,page,size,totalPages}` |
| 상세 | `{warehouse, editability}` + 참조 건수 | Prisma 행 그대로 (snake_case) |
| 낙관적 잠금 | `If-Match` 필수 / `ETag` 응답, `version_no` 본문 비노출 | 없음 |
| 멱등 | `Idempotency-Key` 전 쓰기 필수 | `pop` 일부만 |
| 오류 | `{errors:[{scope,code,field,uniqueScope,message}]}` | Nest 기본 |

## 순서

### 건져내기 — 완료

스펙에 없고 삭제된 코드에만 있던 규칙은 [기존 구현 도메인 규칙](./기존-구현-도메인-규칙.md)
으로 옮겼다. 인증 설계 판단은 [ADR 0002](./adr/0002-self-hosted-password-auth.md).

### PR 사다리

정독 대상은 **C·D·E·F·H·I·J 일곱 개**이고 전부 200줄 안쪽이다. 나머지는 패턴
대조로 읽는다. J 를 넘기면 남은 39개 오퍼레이션에는 새 결정이 없다.

| # | 내용 | 오퍼 | 추정 | 성격 |
|---|---|---|---|---|
| A | 골격 — 부팅되는 빈 Nest 앱 + Prisma 모듈 + health | – | ~150 | 기계적 |
| B | 계약 사본 `contracts/` + 타입 생성 | – | ~60 | 기계적 |
| C | `GET /mdm/warehouses` — `PageMeta` 봉투 · 응답 매퍼 · 검색/페이지 | 1 | ~200 | 정독 |
| D | `GET /mdm/warehouses/{id}` — `ETag` · 편집 가능성 · 참조 건수 | 1 | ~200 | 정독 |
| E | 인증 — 자격증명·해시·로그인 | – | ~200 | 정독 |
| F | 가드 — 화이트리스트 보호 + 권한 데코레이터, C·D 에 적용 | – | ~150 | 정독 |
| G | 멱등 저장소 마이그레이션 | – | ~80 | 선행 커밋 |
| H | `POST /mdm/warehouses` — 오류 봉투 `{errors:[…]}` | 1 | ~200 | 정독 |
| I | 멱등 인터셉터 | – | ~120 | 정독 |
| J | `PUT /mdm/warehouses/{id}` — `If-Match` · 충돌 원인 | 1 | ~180 | 정독 |
| K | `POST …:deactivate` | 1 | ~80 | 복제 |
| L | 로케이션 | 5 | ~250 | 복제 |
| M | 코드그룹 · 코드값 | 10 | ~350 | 복제 |
| N | 부서 | 5 | ~200 | 복제 |
| O | 조회 전용 8종 | 8 | ~250 | 복제 |
| P | 품목 본체 + 자식 3종 | 9 | ~300 | 새 의미론 |
| Q | 작업자 + 자격 | 4 | ~150 | 복제 |

**인증이 C·D 뒤에 오는 이유**: 개발 중 조회 하나 확인할 때마다 토큰을 붙이는 것이
번거롭다. 무보호 구간은 읽기 전용인 C·D 둘로 한정하고, 첫 쓰기(H) 앞에 F 를 넣는다.
쓰기는 감사 컬럼 `created_by`/`updated_by` 에 인증 주체를 기록해야 하므로 인증
없이는 만들 수 없다.
