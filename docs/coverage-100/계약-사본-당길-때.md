# 계약 사본을 당길 때 서버가 «따라» 고칠 자리

`pnpm contracts:update` 로 `contracts/` 사본을 갱신하면, 계약이 바뀐 만큼 **서버 코드도 같이
움직여야 하는 자리**가 있다. 그 목록이다. ⛔ **당기기 «전»에 이 문서를 먼저 읽는다.**

> 왜 목록이 필요한가 — 우리가 계약에 청한 것(요청서 **217·218·219·221·213**)이 실려 오면
> **그 순간 몇몇 spec 이 빨개진다.** 그것은 **의도한 것**이고, 「고쳐서 초록으로」가 아니라
> **「실린 것을 목록에서 빼는」** 손질이다. 모르면 가드를 지우게 된다.

---

## 0. 맨 먼저 — 오퍼레이션 «수»

`src/common/contract/contract-coverage.spec.ts:41` 의 `expect(registry.size).toBe(487)`.

사본을 당기면 **487 이 바뀔 수 있다.** 바뀌면 이 수와 커버리지 목표(482)를 같이 다시 잡는다.
⛔ 수만 고치고 넘어가지 마라 — **늘어난 오퍼레이션은 구현이 0건**이다.

## 1. enum 이 실려 오면 — **가드를 빼는 손질**

### 1-1. 218 · `transitionCode` 에 `C17`~`C20`

| 자리 | 무엇 |
|---|---|
| `src/common/contract/contract-lot-transition-enum.spec.ts:33` | `const KNOWN_GAP = ['C17', 'C18', 'C19', 'C20'];` |

⇒ **실린 코드를 `KNOWN_GAP` 에서 뺀다.** 그 파일 `:20` 이 그 지시를 이미 적어 두었다 —
「ⓑ 설계 변동 공지가 넷 중 일부를 enum 에 실었다 ⇒ 축하할 일이다. `KNOWN_GAP` 에서 빼라」.

⚠ 넷이 **다** 실리면 `KNOWN_GAP` 이 빈 배열이 되고, 그때는 **spec 자체를 지워도 된다.**

### 1-2. 213 · `sourceDocumentTypeCode` 에 `RECYCLE_ENTRY`

| 자리 | 무엇 |
|---|---|
| `src/common/contract/contract-recycle-entry-enum.spec.ts` | 사본에 **선반영한 값**을 지키는 spec |

⛔ **이 값은 아직 설계 변동 공지에 안 실렸다.** 공지 없이 당기면 **우리 편집이 조용히 덮이고**,
재생재가 만든 원장 행이 `GET /inventory/transactions` 응답에서 **ajv 를 깬다.**
⇒ 그 spec 이 **당기는 그 순간** 빨개진다. **빨갛다고 지우지 마라 — 공지에 안 실렸다는 뜻이다.**
공지에 실려 사본이 정식으로 그 값을 갖게 되면 **그때 지운다.**

### 1-3. 217 ⓑ · 취소 차단 사유에 「상류 문서가 소유한다」 여섯째 값

| 자리 | 무엇 |
|---|---|
| `cancel-eligibility.service.ts:121` | `STATE_LOCKED: (… ) \|\| ownedByShipment` — **지금은 `STATE_LOCKED` 에 얹어 두었다** |
| 〃 `:53` | `BLOCK_ORDER` — 차단 사유의 «우선순위» 목록 |
| 〃 차단 사유 타입 | `CancelBlockedReason` |
| 〃 spec | 같이 고친다 |

⇒ 새 값이 오면 **`|| ownedByShipment` 를 새 키로 옮기고** `BLOCK_ORDER` 에 자리를 준다.
⭐ 그래야 화면이 「출하가 소유해서 막혔다」를 **정확히** 안내한다(지금은 「상태 자물쇠」로 보인다).

## 3. 서버 코드 변경이 **0** 인 것

계약만 고쳐지면 되고 **서버는 이미 그렇게 동작한다.** 확인만 하고 넘어간다.

- **217 ⓐ** `GoodsIssue.sourceDocumentTypeCode` 에 `SHIPMENT` — 서버는 이미 그 값을 쓴다
- **219** `400` 응답 선언 — 서버는 이미 400 을 낸다
- **221 ⓑⓒ** 낡은 「값 목록 미확정」 표시 삭제 · `conflictCause` 칸 추가 — 서버는 이미 그 칸을 싣는다

## 4. 당긴 뒤 돌릴 것

```bash
pnpm contracts:check                 # 어긋났는지
pnpm contracts:update                # 받아온다
./node_modules/.bin/prisma generate  # 계약 타입이 바뀌었으면
./node_modules/.bin/tsc --noEmit
./node_modules/.bin/jest --silent    # ⭐ 여기서 위 spec 들이 빨개진다 — 의도한 것이다
./node_modules/.bin/jest --config ./test/jest-e2e.json --runInBand
```

⚠ `contracts/COMMIT.txt` 가 바뀌면 **데이터 모델 산출물의 `contract_reference_commit` 도 낡는다**
⇒ `docs/data-model/README.md` 의 재생성 절차를 한 번 돌린다(몇 분).
