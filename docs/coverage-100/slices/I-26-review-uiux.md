## 새 Major

### Major-1 — 서로 다른 단위의 배분을 개체 수로 더할 수 있다(조건부 POST)

- 위치: 초안 `:235`·`:240`; `src/production/production-result/production-result.service.ts:101`·`:106`·`:181`; `production-result-rules.ts:108`.
- 실제 경로는 배분마다 요청 `body.uomId`를 저장하고 단위의 존재만 확인한다. 슬롯 검사는 W/O 귀속·폐번만 확인한다. 같은 LOT의 배분이 동일 단위라는 보장은 없다.
- 물리는 `production_result_lot_allocation.uom_id`를 보유(`schema.prisma:2869`), 발번 quantity는 **개체 수**(`production 계약:6015`)다. 다른 단위의 수량을 합치거나 무게 수량을 개체 개수로 취급하면 잔량과 발번 상한이 틀린다. Decimal은 이 의미 차이를 해결하지 않는다.
- 권고: §5-1·§9 #7에 **배분 단위 동일성 및 개체수와의 대응**을 추가한다. 단위 정본/기존 환산 근거를 확인하고, 근거가 없는 입력은 §2 가장자리 판정으로 명시 거부하는 안을 재수립한다. 임의 `EA` 코드·환산율·새 품목 분류를 만들지 않는다.
- 재개 전 검증 이름: 「같은 LOT에 다른 uomId 배분을 합쳐 발번하지 않는다」·「단위가 개체수로 환산되지 않으면 미발행 개수로 표시/승인하지 않는다」. 이는 GET 계약 확장을 요구하지 않는다.
- 기존 I-7/LOT 집계의 같은 한계는 A에 사용자 경유로 인계하고 이 리뷰에서 해당 소스를 수정하지 않는다. 현재 POST 보류는 이 문제를 해결했다는 뜻이 아니다.

## Minor 보완

### Minor-1 — I-27 인계를 두 번째 요청의 재전송까지 구체화

- 위치: 초안 `:301`·`:433`; `contracts/app-공통.json:4497`·`:4525`·`:4526`; `src/common/idempotency/idempotency.service.ts:111`.
- 「개체별 기록 N건」은 **targets N개를 한 요청**에 보내는 뜻이다. 건별 N회 호출은 app 계약이 명시적으로 피한 부분 실패를 만든다.
- ①의 `items` 전체를 ②의 `targets[{targetTypeCode:'SERIAL_NUMBER',targetId,lotId}]`로 인계한다. ①·②는 서로 다른 키를 쓰고 각 단계의 키·본문·귀속값은 재전송 동안 유지한다. GET 첫 페이지로 성공 배치를 재구성하지 않는다.
- ① 응답 유실은 ① 동일 키 재생, ② 응답 유실은 ② 동일 키 재생이다. ②의 응답 유실을 새 재발행으로 처리하면 회차가 늘거나 재발행 사유422에 막힌다. 기록 성공 뒤 인쇄 실패만 K-7 재발행으로 간다.
- I-27 인계 검증에 「N개 단일 targets」·「② 성공 응답 유실 후 동일 회차 재생」을 추가한다. I-26 조회 PR에 I-27 구현을 합칠 이유는 없다.

### Minor-2 — 세션 외에도 브라우저 헤더 전송 제한을 배포 노트에 명시

- 위치: 초안 `:295`·`:303`; `src/common/http/cors.ts:38`; `src/auth/terminal-token.ts:27`; `src/auth/authentication.guard.ts:42`.
- CORS 허용 목록에는 `Authorization`·`X-Worker-No`가 없다. 교차 오리진 브라우저 셸은 계정 쿠키가 있어도 POST의 단말·사번 헤더 요청이 preflight에서 막힌다. 직접 HTTP E2E 통과와 다르다.
- 배포 조건에 세션 및 동일 오리진/공용 담당 헤더 조정을 함께 기록한다. Electron/native 전송 전체가 막혔다고 일반화하지 않는다. 공용 인증·CORS 소스는 이 슬라이스에서 임의 수정하지 않는다.

### Minor-3 — 실제 소비자와 빈 목록 의미를 인계에 넣기

- 위치: 초안 `:197`·`:303`·`:427`; `derived-permissions.ts:142`·`:260`; `plan-uiux.md:375`.
- P-02-12 `:27`·`:76`은 긴급 생산도 정상 LOT 완료·인식표 흐름을 재사용한다. POST 보류는 이 진입 경로에도 전파된다. U25의 `M-01-02`·ETag 오기를 실제 소비 경로/선택 If-Match로 정정한다.
- GET 권한표의 P-04-04는 실제 화면 `:78`·`:89`·`:90`에서 **포장 단위/PACKING_LABEL**을 다룬다. 이 표만으로 시리얼 소비자나 발번 대상이라고 확정하지 말고 매핑 불일치로 남긴다. 권한표를 고치거나 새 GET403을 추가하지 않는다.
- GET200 `items=[]/total=0`은 저장된 개체0이다. 양품0·미발행 가능·API 미지원 중 어느 뜻인지 대신 판단하지 않는다. 선택 LOT 상세 `withProgress=true`와 필터 없는 해당 LOT `page.total`을 함께 사용한다.
- 상태 원문은 표시만 한다. 상태를 NORMAL 등으로 번역·분기하거나 상태/검색 필터의 total을 기발번 전체로 쓰지 않는다. 초안의 기존 테스트로 대부분 검증 가능하다.

### Minor-4 — 통합 목표의 기준값 갱신

- 위치: 초안 `:429`; 현재 `docs/coverage-100/plan.md:170`·`:173`.
- I-30 완료1건 보류가 정본에 이미 반영되어 현재 목표는479/487이다. 다른 조건 불변이면 I-26 POST 보류 뒤 **478/487**이며 초안의480→479를 그대로 적용하면 한 건이 빠진다. 공식346/487은 목표가 아니며 이번 리뷰에서 재측정하지 않았다.

## 기존 갈림길의 최소 해소 조건

1. **상태 본길**: 생성 시 required 문자열의 정확한 값/원천 또는 서버가 고를 수 있다는 명시 위임을 확보한다. 코드 그룹 신설·LOT 품질 상속·nullable는 현재 근거로 해소안이 아니다. `plan.md:21`의 required 상수 예외는 이 누락을 자동으로 해소했다고 간주하지 않고 R-n으로 범위를 명확히 한다.
2. **채번**: 상태와 별개로 전역 형식·공장/LOT 구분·기간축과 예약 결번/성공 배치 비연속을 R-n으로 확정한다. P-02-05 `:184`의 연속성 요구를 이미 충족했다고 단정하지 않는다. 미리보기 API를 추가하지 않는다.
3. **수량**: 기존 LOT 배분합은 유지하되 Major-1의 단위 경계를 판정하고, 모든 상태의 기발번 누계·소수·동일 LOT 병렬 요청을 묶어 검증한다. 정정 뒤 배분 잔존은 문의044의 한계로 표시한다.
4. **조건부 헤더**: 정상 If-Match의 대상/검사 또는 신규 생성 선례의 적용을 확정한다. 초안 `:286`의 정상값400은 온라인 사용 가능성을 줄이는 새 선택이다. `material-return.controller.ts:52`의 받되 무시 선례와 공유계약 B-1-1 `:891`을 비교한 R-n 없이는 채택하지 않는다.
5. **사용 흐름**: GET만 배포한 단계는 조회만, POST 재개 뒤에도 발번 성공·발행기록 성공·인쇄 성공을 각각 알린다. 오프라인에는 확정 serialNo가 없으며 연결 뒤 ①→② 순서를 지킨다. I-27 범위 재판정·Minor-1 인계로 복구 경로를 닫는다.

위 조건은 POST 재개 판단의 구체 항목이다. GET에는 새 상태·마이그·채번이 필요 없으므로 3관점 통합 후 독립 PR로 진행할 수 있다.
