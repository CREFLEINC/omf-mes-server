# I-30 독립 통합 리뷰

| §0의 검토축 | 판정 | 통합 판단 |
|---|---|---|
| 1. 원인코드 본길 — `:complete` 유보가 맞는가 | **유보 유지** | 지정 원천의 정의·조회 경로가 없고 품질 원천 사용은 금지되어 있다. O9만 유보하고 O7의 비null 원인 입력은 명시 거부한다. 전체 레인 중단·확정 건너뜀으로 확대하지 않는다. |
| 2. A15 3칸을 넘어선 실제 저장 결손과 과거 행 | **수정** | 8칸 추가·2칸 nullable 완화, 보고 계정과 귀속 사번 분리, 백필0은 유지. 측정값 정밀도 경계와 실제 인증 전제를 추가해야 한다. |
| 3. 조회가 I-11·I-31·I-32와 이어지는 실제 축 | **유지** | 최신은 inspectedAt+PK, 미발행은 다형 source와 고장 직접 FK, 비가동은 닫힌 구간 합계다. 다중 지시·소수 분 null은 미확정임을 인계하며 정상적인 미연결/0분과 구분한다. |
| 4. 트랜잭션·상태·오류·귀속의 경계 | **수정** | 전달받은 tx 사용·FOR UPDATE→version→state·재전송 우선은 유지. 공용 코드검증 함수의 타입 불일치와 사번/계정 누락 지문을 구현 전에 해소해야 한다. |
| 5. 채번·알림·PR 크기 | **수정** | EQI/MLF 등록·별도 채번 연결·결번 허용·알림 의사만 저장·첨부 제외를 유지. 로컬 검증 추가분을 PR⑤/⑥ 예산에 반영하고 회귀 파일·조건부 완료 PR의 병합 순서를 고정한다. |

대상은 `I-30.md` 673줄 전체·두 브리프·정본·실제 코드·고정 계약이다. 다른 관점 리뷰는 읽지 않았다.
`specs/_shared/services/`는 실제 rg 탐색에서 없었으며, `contracts/equipment-05설비툴.json`의 9건과 연결 스키마/헤더, 설계 사본의 `design/wiki/api-contracts/`·`decisions-policy/공유계약.md`를 사용했다.
계획자의 DB 관측·파일 기준량을 뒤집는 주장은 없으며 DB 재측정·E2E·마이그 적용은 하지 않았다.
**계획 수정사항: Blocker 0 / Major 4 / Minor 2 / Nit 0. 실제 PR 승인·게이트 통과 판정은 아니다.**

## 1. 버그 / 정확성

- **[Major M1] 공용 코드값 검증 함수를 그대로 tx에 호출할 수 없다.**
  `I-30.md:308,349,360`은 모든 업무 SELECT를 tx로 실행하면서 `assertCodeValues`를 재사용한다.
  그러나 `src/common/master/code-reference.ts:24`의 인자는 `PrismaService`이며 `Prisma.TransactionClient`와 호환되지 않는다.
  `this.prisma`를 넘기면 계획의 같은 tx 원칙을 깨고, 타입 단언으로 덮으면 실제 의존성을 숨긴다.
  공용 수정0을 유지하려면 I-30 내부 검증이 tx의 `code_value.findMany`를 사용하도록 구체화하고 활성값·그룹 검증을 보존한다. 공유 함수 변경을 택하면 별도 소유 조율·범위·예산이 먼저 필요하다.

- **[Major M2] “계정 없는 작업자”와 “계정 세션 없는 요청”을 구분해야 한다.**
  `I-30.md:133,362,436,487`의 세션 없으면 null·현장 귀속·201만으로 무로그인 HTTP 흐름이 성립하지 않는다.
  `src/auth/authentication.guard.ts:37`은 로그인 외 계약 API를 모두 검사하고 세션 부재에 401을 낸다. `src/auth/session-resolver.service.ts:46`은 SESSION 쿠키만 해석한다.
  WorkerNo 계약(`contracts/equipment-05설비툴.json:3004`)은 현장 계정 로그인 없음과 귀속 필수를 명시하지만 단말 토큰 경로는 이 계획이 만들지 않는다.
  현재 범위에서는 호출용 계정 세션+계정 연결 없는 worker의 조합으로 E-I12/E-B11을 검증하고, 무로그인 현장 사용은 미지원 배포 제한·인증 선행 과제로 적는다. 기존 인증을 임의 면제하지 않는다.

- **[Major M3] 측정값을 “그대로” 저장한다는 계획에 DB 정밀도 경계가 없다.**
  `I-30.md:350,353`과 달리 저장소는 `numeric(20,6)`이다(`prisma/schema.prisma:4195`, `prisma/migrations/20260826000000_data_model_v4/migration.sql:687`).
  요청은 범위·소수 자릿수 없는 double이다(`contracts/equipment-05설비툴.json:3142`). 예컨대 `1.1234567`은 저장 중 반올림되고 `1e14`는 범위를 넘는다.
  `src/common/contract/contract-validator.ts:17,56`의 double은 무연산 format이고 `src/common/errors/prisma-error.ts:32`은 수치 초과를 업무 오류로 변환하지 않는다.
  소수 6자리 초과·정수부 14자리 초과의 가장자리 정책을 명시한다. 권고는 2단계②의 필드 400 RANGE이며, 조용한 반올림 없이 헤더·라인·멱등 기록 모두0을 단언한다. 물리 확장을 선택하면 SQL·예산을 다시 확정한다.

- **[Minor N1] 과거 행 사전 점검은 null 외의 계약 불일치도 포함해야 한다.**
  `I-30.md:147,206`은 헤더 필수3칸의 null만 세지만 `judgment_code`는 CHECK 없는 문자열이고 응답은 PASS/FAIL enum이다(`prisma/schema.prisma:4174,4198`, 계약:3137).
  헤더와 라인의 미등록 판정값도 사전 SELECT·뷰 불변식에 추가한다. nullable을 가짜 값으로 보완하지 않는 결정은 유지한다.
  새 handled_by 관계에는 SQL 기본 동작과 같은 `onDelete: NoAction, onUpdate: NoAction`을 명시해 드리프트0 조건을 구체화한다(`I-30.md:171,200`, 기존 관계 `prisma/schema.prisma:4096`).

## 2. 보안 / 귀속

- **[Major M4] 다른 귀속의 동일 멱등키를 성공 재생하는 기대값은 수정해야 한다.**
  `I-30.md:334,339,468`은 method/path/body만 같은 경우 다른 사번·계정에도 최초 응답을 돌려준다.
  `src/common/idempotency/idempotency.service.ts:60,111`은 지문만 비교하고 콜백 전에 재생한다. 따라서 사번 부재·미등록도 최초 성공 뒤에는 서비스 검증을 통과한 것처럼 보이며, 다른 계정 요청은 자기 처리를 하지 않고 앞선 사람의 처리를 성공으로 받는다.
  O3/O6의 사번 필수·형식 검증은 replay 전에 수행한다. 새 로컬 context의 지문에 원문 `workerNo`와 실제 호출 `actorUserId`, O7/O8 및 향후 O9의 actorUserId를 포함한다. 형식이 유효한 다른 귀속은 기존 ConflictResponse 409, 동일 귀속 재전송은 최초 응답으로 확정한다.
  If-Match는 지문에서 제외하고, POST409 미선언은 기존 계획대로 문의한다. 사번을 비밀번호·세션 등 인증 수단으로 승격시키는 변경은 아니다.

## 3. 테스트 / 회귀 / 병합

- **[Minor N2] “부팅 영향 파일” 대신 소유 PR별 검증 대상을 고정한다.**
  `I-30.md:514,563,567,569`는 파일 이름·완료 코어의 선행 조각을 구현 시점으로 남긴다.
  회귀는 실제 `test/production-precheck-decision.e2e-spec.ts`로 I-11 FK 소비를 확인하고, PR④는 `test/document-state.e2e-spec.ts`와 기존 채번 단위 전체를 포함한다. 인증/권한을 건드리는 안으로 확대하면 `test/authentication.e2e-spec.ts`·`test/permission-gate.e2e-spec.ts`도 통합자가 병합 직전 1회 실행한다.
  ①→②→③, R-n/A 조율→④, ①②④→⑤, ②③④→⑥, ③④⑥→⑦ 순서는 타당하다. 조회①은 마이그 전 모델로 빌드돼야 한다.
  ⑧은 원인 원천 마이그/FK 확정→A 전이 전용 PR 병합→완료 도메인 PR로 명시하고 코어와 도메인을 한 PR로 합치지 않는다. 최신 main 반영 후 자기 등록과 타 레인 등록을 함께 검증한다.
  기존 실측 323/287/284/131/89줄은 유지한다. M1·M3·M4의 로컬 코드 추가를 파일별 예산에 넣어 350/400, 코어 PR 전체200을 지킨다. 초과하면 구현 브리프를 먼저 분할한다.

## 4. 컨벤션 / 가독성

`coding-rules`의 TypeScript·커밋 규칙과 `pr-review`의 네 영역을 대조했다. repository 계층을 추가하지 않는 파일 배치, 실패의 명시적 전파, 한국어 근거·테스트 이름은 적절하다. 신규 코드·커밋이 없으므로 포맷·커밋 준수를 검증 완료로 표현하지 않는다.

## R-n 반영 제안과 필수 테스트

| 제안 | 반영할 결정·테스트 |
|---|---|
| R-원인 | **O9 유보 유지**. 최소 해소 조건은 설비 원인 마스터의 소유·행 식별 키/타입·선택 목록 경로·신규 쓰기 검증 규칙 확정이다. 기존 품질 원천 또는 공통코드를 택한다면 고정 계약과 화면의 충돌을 해소할 사용자/설계 결정이 필요하다. 원천명만 답하거나 HYD_LEAK 예시 하나로는 부족하다. 유효값이 단지0개인 상황과 원천 미정은 구분한다. |
| R-tx | M1 반영 후 `코드값 검증과 응답 되읽기가 받은 tx만 사용한다`, 기존 E-I20/E-B17/E-B24의 멱등 완료 저장 실패 전체 롤백. |
| R-귀속 | M2/M4 반영. `계정 세션+계정 미연결 worker는201`, `계정 세션 없으면 현재401`, `동일키라도 사번 생략은400 REQUIRED`, `같은 키의 다른 사번·다른 계정은409이며 업무0`, `동일 귀속 재전송은 첫 응답`. |
| R-수치 | M3 반영. `소수6자리 값은 정확히 왕복`, `7자리·1e14는400 RANGE이고 헤더·라인·멱등0`. DB 반올림을 기대값으로 쓰지 않는다. |
| R-과거행 | N1 반영. `과거 헤더/라인의 미등록 판정은 PASS로 도출하지 않는다`; 실제 배포 대상 사전 점검 결과가 있어야 조회 배포를 승인한다. |
| R-경계 | 기존 E-I22·E-B03~08·E-C07 유지. 완료가 W/O·세션·비가동·보전지시·설비 상태·재고·알림에 쓰기0임을 연결 픽스처로 단언한다. |
| R-분할 | N2 및 로컬 코드 추가분 재예산. 채번 충돌은 번호 유일키만 전체 재시도하고 최초+3 소진 오류를 단언한다. +8과 조건부+1을 분리하고 최종 숫자는 main에서 센다. |

**결론:** 8건 진행+완료1건 유보의 구조는 유지할 수 있다. 위 Major는 구현 브리프 확정 전에 반영하고, 인증·원인·알림·첨부의 미지원 범위를 도메인 API 구현 완료와 구분해 마감표에 남긴다.
