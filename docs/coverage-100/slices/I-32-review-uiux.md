## 판정 — Blocker 0 · Major 3 · Minor 1

### Major 1 — ORM의 ms 한계를 정상 입력 거부 규칙으로 바꾸면 안 된다

D:311·D14/D21은 `.123001`을 400으로 거부하고 기존 µs 행의 조회도 실패시킨다. C:4368·4416의 date-time에는 ms 제한이 없고 S:4152/4153은 `Timestamptz(6)`이다. `src/common/contract/contract-validator.ts:60`의 addFormats 및 로컬 `node_modules/ajv-formats/dist/formats.js:98`도 소수부 `\d+`를 검사한다. 저장소가 표현할 수 있는 정상 시각을 Date 편의 때문에 막으면 현장이 입력한 구간을 저장·재조회할 수 없다.

최소 수정: 입력 문자열을 바인딩해 SQL timestamptz로 저장하고, **목록·상세·잠금 재조회·쓰기 응답·멱등 재생까지** µs를 잃지 않는 문자열 매퍼를 계획의 기본안으로 둔다. 비교·길이는 DB의 정확한 값으로 계산한다. Date 객체를 거쳐 이미 잘린 뒤 확인하지 않는다. 물리 표현 범위를 넘는 비영 소수부는 별도의 가장자리로 판단한다. 신규 정밀도 칼럼·백필은 필요 없다.

검증 이름: `µs 입력 .123001을 POST→GET→PUT→GET→동일키 재생에서 같은 instant로 보존한다`; `기존 µs 행은 목록·상세 모두 정상 반환하며 원본을 숨기지 않는다`.

### Major 2 — 미래 검증의 기준 시계가 빠져 기본 [지금] 입력이 막힐 수 있다

D:71·§6-2 단계5·D20은 미래를 거부한다고만 한다. P:190의 미래 입력 거부는 확정이지만 공유:1872·1889는 단말 시각을 보존하고 **단말이 5분 빨라도 구간의 차는 정확하다**고 명시한다. 서버 now와 비교하면 단말 10:05/서버 10:00의 정상 `[지금]`도 400이 된다. 오프라인 지연에 따라 같은 입력의 성공 여부까지 달라진다.

최소 수정: **화면의 단말 로컬 시계 기준 미래 검증**과 서버의 `endedAt>=startedAt` 검증을 구분한다. 서버에서도 미래를 거부하려면 비교시계를 어떤 계약 입력으로 아는지 확정해야 한다. 현재 입력으로 단말 시계를 알 수 없다는 한계를 적고, 서버 수신 now·임의 허용오차·오차헤더를 기본값으로 발명하지 않는다. 이 결손은 close 본문 결손과 별개다.

검증 이름: `단말이 5분 빠른 정상 지금 입력을 서버 now만으로 거부하지 않는다`; `단말 로컬 미래 입력은 인라인 오류이고 저장 시각은 보정하지 않는다`; `종료 역전은 startedAt·endedAt 두 필드 PAIR다`.

### Major 3 — 이미 확정된 경미 정지·폐지 사유 표시를 다시 미정으로 돌렸다

D:319·460·463·§7-3·702가 정책 공장 범위·사유/minor 행 구성·미분류 표시를 재질문한다. W:148~157은 **minor를 별도 줄로 나누며 일반 사유와 건수를 섞으면 평균이 왜곡된다**고 확정했고, W:243·253은 **폐지 사유는 미분류로 묶되 원본 코드를 보인다**고 정했다. W:304는 minor 임계는 **공장 단위면 충분**하다고 명시한다. C:4518·4530의 actual 포함/기본5/응답 임계 표시도 닫힌 규칙이다.

최소 수정: ‘별도 표시할지/공장 범위를 쓸지/폐지 사유를 미분류로 보일지’는 0단계 해소로 옮긴다. 일반 사유 행에 minor를 섞어 같은 건수를 재표시하는 안은 제외한다. 원본코드 보존과 미분류 표시를 동시에 달성할 응답 사용 방식을 적는다. 신규 reasonCode 문자열은 만들지 않는다. **기간 중 정책 변경·복수공장의 단일 threshold 표현·reasonCode 자체가 null인 옛행의 봉투**만 실제 미정으로 남긴다.

검증 이름: `minor는 actual에 포함되지만 일반 사유 건수와 섞이지 않는 별도 줄이다`; `폐지 사유는 미분류 표시와 원본코드를 함께 보존한다`; `공장 정책·미설정5·설정0을 구별한다`.

### Minor 1 — summary 보류의 본길/가장자리 분류를 좁혀야 한다

D:466·§9는 기간 선택·integer 반환·minor 행 구성을 본길로 한꺼번에 묶는다. 기간 경계를 가로지르는 구간, 소수분, WEEK, 복수 정책은 **특정 자료/입력에서** 갈리므로 README §2의 가장자리 검토를 먼저 해야 한다. L-3-1은 날짜 양끝 포함을 이미 확정했으므로 이를 다시 질문하지 않는다. 다만 이 사실만으로 summary 전부를 구현 가능하다고 결론내리지도 않는다.

최소 수정: `기간 선택 축/교차행 clip`, `정수분 변환`, `열린 세션`, `캘린더`, `보전 완료 원천`별로 정상 입력과 예외 입력을 나누고, 정상 입력에서 계약 필드 전부를 낼 수 있는지를 먼저 증명한다. I-31 API 미구현·전용 DB 0행은 **계산 원천이 없다는 증거가 아니다**. 반복 문의와 불필요한 선행 병합 대기를 줄이는 정정이다.

### 축2 오류 판정 보완

close의 409 설명(C:1990)은 상태 잠김·참조 존재를 **400**이라 구체적으로 적었고, 422 항목은 일반 업무 오류다. 따라서 ‘이미 닫힘’은 **400 STATE_LOCKED**를 우선 후보로 잡고 응답표의400 누락을 문서 문의한다. 헤더 형식400은 `optimistic-lock.guard.ts:58` 등 횡단 선례와 같은 봉투로 기록한다. ‘422가 목록에 있으니 잠김도422’만으로 닫지 않는다. 409는 실제 저장 충돌이며 ConflictResponse의 `conflictCause/message`만 사용한다. 이는 실패 가장자리 판정이며 close의 발생시각 결손을 해소하지 않는다.

### 축4 실제 원천을 사용하는 한계

- `src/production/work-session/work-session.service.ts:74`는 입력 없는 equipment를 null로 저장한다. 배정표 JOIN으로 메우면 한 세션을 복제하거나 설비미지정 경고를 지운다. STOPPED여도 ended_at null이면 열린 세션이다.
- `W-05-09-작업캘린더설정.md:164`는 정상시간 원천을 shift로 정한다. `work-calendar.service.ts:285/380`은 적용 교체 시 옛행을 삭제하고 조회는 효력일을 안 거른다. 재료 실재와 과거 집계 재현성은 별개다. PARTIAL의 **교대별 배분은 필요 없음**도 같은 화면 §5-4가 이미 정했다.

## 화면 연결과 검증 인계

목록의 openOnly=true 기간생략은 P 상단 진행 중 구획의 본길이다. 다른 경우 기간쌍 필수, 공장 로컬 To 익일 경계, 원본행/전체count 보존을 유지한다. 상세 ETag→PUT→상세 재조회 체인과 실패 시 입력 유지가 필요하다. 집계 경고의 ‘보기’는 O1에 plant/group 질의가 없으므로 요약의 범위를 그대로 보존할 전달 규약이 아직 필요하다; 이를 위해 계약 질의를 임의 추가하지 않는다.

O5 유보 동안 P의 ‘지금 종료’, O2 유보 동안 W의 요약·탭 및 P의 온라인 오늘 합계는 완결됐다고 보고할 수 없다. 목록 페이지를 화면이 합산하거나 PUT을 오프라인 close의 대체로 호출해 완결을 꾸미지 않는다. W는 종료·수정 컨트롤 없는 조회 전용이며 PUT 권한은 P 소관으로 보완한다.

현재 계정 인증·X-Worker-No CORS 한계는 I-30 R-4/R-12 및 문의054/092를 승계한다. 계정 미연결 worker 허용과 무로그인 요청 허용은 다르다. 배포 검증 이름은 `활성 계정+계정미연결 사번 생성 성공/세션없음·단말만·만료401`, `공용 CORS 보완 후 X-Worker-No preflight 허용`이다.

추가 필수 검증: `동일설비 동시open 하나 성공·닫힌겹침 모두 성공`, `종료/메모 수정 실패와 멱등완료 실패는 모두 rollback`, `required결손은 숨김 없이 실패·정상환경 조회 성공`, `현재 구간·전날 open·다른 공장 날짜·µs 경계`, `작업세션 Σ와 설비별 union은 서로 다른 계산`, `groupBy별 해당배열만`, `완료 보전은 보고일·예정일·downtime 건수로 대체하지 않는다`.

최종 권고: **4건 진행 방향은 유지하되 Major 1·2를 P0/쓰기 계획에 먼저 반영한다. close는 입력원천 규약까지 유보. summary는 Major 3·가장자리 재분류 후 최소 정상 경로가 서는지 통합 R에서 재판정한다.** I-30 날짜 helper는 계획뿐이므로 실재 없는 import/재사용을 적지 않는다. 실제 구현·테스트 통과·커버리지 증가를 주장하지 않는다.
