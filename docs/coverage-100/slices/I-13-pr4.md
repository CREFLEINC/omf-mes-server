### ① 「`PUT …/lines` 가 오늘 도달 불가」가 사실인가 — **뜻을 두 겹으로 갈라야 한다**

| ⭐ **화면**(M-01-10 · W-04-11 · 오프라인 큐) | ⛔ | ⛔ | ⛔ | ⛔ |

**HTTP 축 근거** — `POST /logistics/stock-transfers` 가 생성·반출을 한 번에 한다(`stock-transfer.service.ts:101` `shipped_at: occurredAt` 무조건) · `stock_transfer` 를 만드는 계약 오퍼레이션은 둘뿐이고(01 `POST` · 04 `POST /logistics/stock-reinstatements`) 후자는 **미구현**이며 계약이 「이동 중 구간이 없는 **한 번의 행위**」라 못박았다 · `shipped_at` 을 널로 되돌리는 코드 **0건** ⇒ **모든 `stock_transfer` 행이 `shipped_at IS NOT NULL`** 이다. 그래도 `PUT` 은 그 전표들 위에서 **정상 호출되고 400 을 낸다.**

⭐ **3 이 2 «뒤»다** — 계약이 If-Match 를 필수로 못박았고 형제 둘(`goods-issue-update.service.ts:224-238` · `inventory-adjustment-update.service.ts:194-207`)이 같은 순서다(RFC 9110 의 선행조건 평가 순서도 이쪽이다).
⚠ **그 대가를 알고 고른다**(R-9) — 이 오퍼레이션에서는 **409 의 「다시 읽어 오면 풀린다」가 사실이 아니다.** 재조회 뒤에도 3단계가 400 `STATE_LOCKED` 다(계약이 400 을 「고쳐야 풀린다」, 409 를 「다시 읽으면 풀린다」로 갈라 적었고 `assertUpdated` 문구도 「다시 불러온 뒤 저장하세요」다). 형제 출고의 400 조건(승인 완료)은 **일부 전표에만** 참인데 여기는 **오늘 존재하는 모든 전표에 언제나 참**이라 어긋난 토큰은 100% 거짓 안내를 받는다. ⇒ **G-1 예외 자리**로 문서에 남기고(**162 ⓓ**) **e2e 42 가 「409 → 재조회 → 400」을 못박는다**.

### 4-3. 4단계를 «무엇으로» 닫는가 — 명시적 파열

```ts
// ⛔ 오늘 여기 닿을 수 없다 — 반출 전 상태를 만드는 오퍼레이션이 계약 487건에 0건이다
//    (POST 가 생성·반출을 한 번에 하고 x-internal-note 가 :depart 를 없앴다 · 통보 123).
//    ⭐ 400 으로 «같이» 닫지 않는다 — 그러면 shipped_at 을 아예 안 읽는 구현과 모든
//    테스트가 같아져 자물쇠가 조용히 사라져도 아무도 모른다(변이 ②).
throw new Error('반출 전 재고 이동 전표가 실재한다 — 계약 전제가 깨졌다(문의 123).');
```

| 대안 | 버리는 이유 |
|---|---|
| 같은 400 `STATE_LOCKED` | ⛔ **반증 불가를 만든다**(변이 ②). 그리고 화면에 **거짓**을 말한다 — `STATE_LOCKED` 는 「재로드해도 안 풀리는 잠김」인데 `shipped_at IS NULL` 은 계약이 **「바꿀 수 있다」고 말한 유일한 상태**다 |
| `shipped_at` 을 안 읽고 무조건 400 | 계약 문장(「반출이 **끝난** 라인은」)보다 강하다. ⛔ 통보 123 은 **C 대역**이라 A2 가 못 고친다 |
| 치환 본체를 짓는다 | R-4(3:0) 뒤집기 · PR +≈104줄 · `CLAUDE.md` 금지 |
| `NotImplementedException`(501) | ⛔ **선례 0건.** 계약 응답 선언(200/400/403/409) 밖의 «정상» 상태 코드를 새로 여는 것이다. 500 은 「서버가 스스로 깨졌다고 말하는 것」이라 선언 밖이어도 뜻이 맞고, **저장소가 그 모양을 이미 33곳에서 단언**한다 |

**근거는 「선례와 같은 모양」이 아니다**(R-2) — `master-write.ts:57-59`·`goods-issue.controller.ts:148-154` 는 **가드-계약 배선 불일치**이고 이쪽은 **데이터 상태**다. 서는 근거는 **「저장소가 «도달 불가한 상태»에 500 을 쓰고 그것을 단언한다」**(`.expect(500)` **33건 · 13 e2e 파일** · 재측정 2026-09-09)와 **「501 선례 0」** 둘이다.
**화면 비용은 0** — `error.filter.ts:66-73` 이 `{errors:[{scope:'screen', code:'INTERNAL_ERROR', message:'요청을 처리하지 못했습니다.'}]}` 만 내보내고 **던진 문장은 응답에 안 실린다(로그뿐)**. 부르는 화면이 0이라 오늘 보이는 사용자도 0이다.

### 4-4. ⭐ **`$transaction` + `FOR UPDATE` 로 잠근다**(R-4 — 초안을 되돌렸다)

```ts
// 형제 둘과 같은 첫 문장 — inventory-adjustment-update.service.ts:194-207 의 복제.
const locked = await this.prisma.$transaction(async (tx) => {
  const [row] = await tx.$queryRaw<{ shipped_at: Date | null; version_no: number }[]>`
    SELECT shipped_at, version_no
      FROM logistics.stock_transfer
     WHERE stock_transfer_id = ${BigInt(stockTransferId)}
       FOR UPDATE`;
  if (row === undefined) throw new NotFoundException('없는 재고 이동입니다.');
  if (row.version_no !== version) assertUpdated(0);   // 409
  return row;
});
```

**왜 되돌렸나** — 초안 §4-4 의 제목 「읽기는 «트랜잭션 없이» 한다」가 **거짓**이었다. `runIdempotent`(`master-write.ts:26-45`) → `idempotency.service.ts:119` 는 `work()` 를 **언제나** `$transaction` 안에서 돌린다(그 파일 주석: 「한 오퍼레이션 = 한 트랜잭션 = 한 멱등 기록 … 구조설계 C-5」). 잠금을 빼면 실제로 일어나는 일은 「트랜잭션이 없다」가 아니라 「**읽기가 그 트랜잭션 «밖» 커넥션으로 나간다**」다.

**그래서 나는 결함**(통합 M-1 의 실패 예) — `version_no=1` 을 잠금 없이 읽는 사이 다른 세션의 `:arrive` 가 커밋해 `version_no` 를 **2** 로 올리면(`transfer-arrive.service.ts:146` `increment: 1`), 낡은 토큰으로 온 호출이 **stale 한 1 로 대조를 통과해 400 을 받는다**. 기대는 **409** 다. 순서 보장(§4-2 「3 이 2 뒤」)이 **경쟁 구간에서만 조용히 뒤집힌다** — 변이표 ⑤⑥⑦ 은 순차 시나리오만 재므로 이 변이는 전부 초록이다.
어긋나던 자리 셋: C 의 `I-13.md` §6-2 스케치(`SELECT … FOR UPDATE` · R-4 로 확정된 절) · 형제 출고 `lockHeader` · 형제 조정 `lockHeader`(**404 → 409 순서까지 같은데 잠금만 달랐다**). 되돌림 비용 **≈+6줄**.

⚠ `runIdempotent` 의 `work` 는 **`tx` 를 안 받는다**(`master-write.ts:26-44` — `() => work()`). 서비스가 `this.prisma.$transaction` 을 자기 안에서 여는 것이 **선례와 일치**한다(`stock-transfer.service.ts:70` 도 같은 모양).
⚠ 실패는 멱등 기록에 안 남는다 — `idempotency.service.ts:119-143` 이 `idempotency_record` INSERT 를 `work()` 와 **같은 `$transaction`** 안에서 하므로 던지면 함께 롤백된다. ⇒ **같은 키로 재전송해도 다시 400**(e2e 40 이 잰다).

### 5-1. 무엇이 오늘부터 틀리나(실측)

### 5-3. ⚠ 함께 «사실로만» 적을 것 — `occurred_at asc` 는 **반출** 원장을 집는다

이동 한 건이 남기는 원장 둘(`ST-…` 반출 · `ST-…-A` 도착) 중 **반출**이 뽑힌다.
⇒ 반출 직후 전표는 `status_code='REGISTERED'` 인데 진행 조회에는 **`POSTED` 줄이 이미 선다**. `processedColumn:'received_qty'` 는 아직 0이다.
