### 리뷰가 반드시 볼 자리 5개

1. 감사 기간이 `gte/lt` 반개구간이고 `occurred_at` 파티션 조건이 항상 들어가는가.
2. 감사 응답의 required 5칸과 선택 5칸이 물리 컬럼에서 정확히 투영되고 JSON 키를 손실하지 않는가.
3. 예비품 엑셀의 확실한 열 셋만 읽으며 다중 공장에서 공장을 추정하지 않는가.
4. 부분 실패가 성공 행을 되돌리지 않고, 같은 파일 안 중복과 DB 중복을 행 오류로 돌려주는가.
5. multipart 멱등 지문이 파일 바이트를 포함하고 10 MiB 상한·무파일·손상 파일을 400으로 막는가.

## 2. 3관점 계획

### 2-1. API 관점

- 감사 조회 DTO는 계약 질의 9칸을 전부 선언한다. 필수 시각은 계약 가드가 검증하고 서비스는 파티션 조건을 누락하지 않는다.
- `where`: `occurred_at: { gte, lt }` + 선택 필터 다섯. 정렬 `occurred_at desc, audit_event_id desc`; 공용 `pageRequest`와 `pagedResponse` 사용.
- 응답은 BigInt 식별자를 안전한 number로 바꾸고 Date를 ISO 문자열로 바꾼다. nullable 필드는 `null`을 보존한다.
- 예비품 import는 `FileInterceptor('file')`, 10 MiB 상한, `@Contract`, `runIdempotent`를 사용한다. 파일 SHA-256을 지문 재료로 넘길 수 있도록 공용 helper에 선택 인자를 추가한다.
- XLSX 파서는 첫 시트·머리글 별명 방식이다. 파일 오류와 머리글 결손만 요청 400, 자료 행 오류는 `BatchResult.failed`다.

### 2-2. UI/UX 관점

- 감사 목록은 최신 변경부터 안정적으로 보이며 같은 시각은 큰 ID부터 정렬된다.
- 조회 필터는 독립 적용한다. 빈 결과는 `200 { items: [], page }`이며 대상 존재 여부를 추정하지 않는다.
- `beforeValue`·`afterValue`는 알 수 없는 키도 그대로 보존해 화면의 원문 표시 규약을 지원한다.
- 업로드 실패 index는 머리글 다음 첫 행이 0이다. 사용자가 행을 바로 찾도록 `key=sparePartCode`, 필드별 오류를 반환한다.
- 빈 행은 실패 행으로 세지 않는다. 코드나 명칭 중 하나만 비면 해당 자료 행을 `REQUIRED`로 실패시킨다.

### 2-3. 통합 관점

- 감사 기능은 새 `AuditModule`로 분리해 `AppModule`에 등록한다. 예비품 import는 기존 `MdmModule`과 `SparePartService`에 붙인다.
- 두 API는 공용 파일 충돌을 최소화하도록 별도 PR로 낸다. ①은 `app.module.ts`, ②는 `mdm.module.ts`를 건드린다.
- 스키마 변경이 없으므로 migrate/generate 게이트는 필요하지 않다. 타입·린트·단위·해당 e2e·계약 커버리지·회귀 e2e를 실행한다.
- import는 금형 선례처럼 행을 순차 처리해 같은 파일의 중복을 결정적으로 잡는다. 예상 가능한 행 오류만 실패 목록으로 바꾸고 원인 불명 오류는 삼키지 않는다.
- 멱등 재생은 파싱·DB 쓰기보다 먼저 판단되어야 한다. 단 파일 digest 계산은 메모리 업로드 직후 수행한다.

## 3. 재수립 결론

| R | 발견/판정 | 계획 반영 |
|---|---|---|
| R-1 | 감사 `To` 경계는 계약 문자가 비었지만 저장소 date-time 쌍 선례가 `lt`다 | 통보 270, 단위/e2e 경계 행 |
| R-2 | 페이지가 없으면 파티션 전건을 읽지만 계약이 page/size를 제공한다 | 공용 페이지 helper 사용, `count(where)` 동일성 변이 점검 |
| R-3 | JSON은 화면이 모르는 키도 보여야 한다 | 재구성·키 필터 없이 원문 투영 테스트 |
| R-4 | 예비품 열 전체는 미정이나 코드·명칭은 확정이고 금형 별명 파서가 선례다 | 통보 271, 확실한 열 셋만 구현 |
| R-5 | import 경로에는 plantId 입력이 없다 | 공장코드 열 우선, 없으면 단일 공장만 허용 |
| R-6 | multipart `request.body`만으로는 같은 키의 다른 파일을 구분하지 못한다 | 파일 SHA-256을 선택 지문 본문으로 전달 |
| R-7 | DB 유일 제약 오류를 그대로 던지면 BatchResult가 깨진다 | 선검사 + P2002를 행별 `UNIQUE_VIOLATION`으로 번역 |
| R-8 | 파서가 계약 가드를 우회하므로 길이·공백 검사가 자동 적용되지 않는다 | 행 검증으로 필수·50/200자 상한 고정 |
