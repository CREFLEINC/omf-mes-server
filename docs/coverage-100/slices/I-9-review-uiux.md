## 2. ⭐ 「한 출고 = 수령 하나」 ↔ 「라인 일부만」 — ⛔ 양립하지 않는다

**화면 §5-6 「1라인 이상 수령」의 뜻 = «수령 수량이 입력된 라인 ≥ 1»(버튼 활성 조건)이지 «본문에 실은 라인 수»가 아니다.**
ⓐ `M-01-09:184-191` 표 머리가 **「액션 | 활성 조건」**이고 다른 행이 전부 활성 조건이다(스캔=항상 · 수량 입력=라인 매칭됨 ·
사유=`variance_qty ≠ 0` 일 때 노출) ⓑ 그 행이 인용한 **C-3**(`공유계약.md:1652`)은 「건별 저장 + **마지막 일괄 완료**」 —
확정 버튼 규약이다 ⓒ 레이아웃 `M-01-09:48` 이 「GI-…0042 · **5라인**」으로 **출고 전 라인을 그린다**.
⇒ §3-3 ⓐ 의 ⭐「모든 출고 라인을 다 실을 필요 없다 — 화면이 「1라인 이상」이라 적었다」는 **오독**이다.

**하류가 못 고친다.** `P-02-03:64` ⌜수령량은 **`M-01-09` 가 입력한다. 이 화면은 읽기만 한다** — 계약에 수령 라인을 갱신할
오퍼레이션이 없다(GET 2 · POST 1 · **PUT·PATCH 0건**)⌝ · `:68` 「기록 전용이다. 수령 검증은 정정하지 않는다」. 그리고
`P-02-03:45·49` 가 **「MAT-C 50 → 0 ⛔ 미수령」**을 그린다 ⇒ 설계가 상정한 미수령 표현은 **«라인 생략»이 아니라 «수량 0»**이다
(계약 `receivedQty.minimum = 0` · `ck_shopfloor_receipt_qty` 가 0 을 허용 · 사유 `MISPLACED` 실재).
⇒ 계획자안(부분 실림 허용 + 헤더 축 400)은 **안 실린 라인을 영구 미수령으로 굳히고 투입 화면에 영원히 「미수령」으로 남긴다** —
되돌릴 오퍼레이션이 0 이라 §2 2단계 기준 2 의 「완화로 되돌린다」가 성립하지 않는다.

**권고 = 대안 ⓐ(전 라인 필수).** 본문 라인 집합이 그 출고의 `goods_issue_line` **전건과 같아야 하고** 빠지면 400 `LINE_REQUIRED`.
미수령 라인은 `receivedQty: 0` + 사유로 싣는다. §2 판정: 1단계 **가장자리**(전 라인을 실은 호출은 결과가 같다) → 2단계
**기준 2**(거부→허용이 완화) · **기준 5**(새 개념 0 — 이미 읽는 출고 라인 집합을 대조할 뿐). **화면 변경 0**(§3 이 이미 전 라인을 그린다).
⛔ **대안 ⓑ(라인 축 중복 금지 · 둘째 전표 허용)는 지금 쓰지 않는다** — `M-01-09:84` §4-B 「`goods_issue_id` FK NOT NULL — **1:1**」·
`:225` §8 #2 「**1:1 로 시작**」과 어긋난다. ⚠ 다만 `M-01-09:180` §5-5 가 ⌜한 출고 전표가 여러 W/O 라인을 담으면 **수령 전표를
나눠야 한다**⌝ 로 분할을 «예고»하므로, 헤더 축 400 이 그 길을 닫는다는 사실을 §8-3 에 적고 「§8 #2 회신이 «분할»이면 헤더 축 →
라인 축으로 바꾼다」를 되돌림 한 줄로 남긴다. `FOR UPDATE` 는 ⓐ 에서도 그대로 필요하다.
⇒ **테스트 이름 2 추가**: `출고 라인 5행 중 3행만 실으면 400 LINE_REQUIRED` · `미수령 라인을 receivedQty 0 + 사유로 실으면 201`.

## 3. `issuedQty` 대조 400 — ✅ 유지(화면 근거로 더 세진다) · ✏ 문구

**「오프라인 단말이 되읽은 값이 낡을」 경로가 실측으로 없다.** ⓐ 게이트가 `POSTED` 만 받는다 ⓑ `POSTED` 전표는 **라인 치환이
400 `STATE_LOCKED`**(`goods-issue-update.service.spec.ts:228`·`:247`) ⓒ 화면이 같은 말을 적었다 — `M-01-09:224` §8 #1
⌜`postImmediately: true` 라 전표가 항상 전기완료이고 **전기된 전표의 라인은 바꿀 수 없다** · ⛔ 라인 치환(`PUT …/lines`) 불가⌝
ⓓ 정정 경로는 **출고 취소 → 새 출고**라 `goods_issue_line_id` 가 새로 난다. ⇒ 같은 라인의 `issue_qty` 가 단말 등 뒤에서 바뀌지
않으므로 400 은 「업무를 없애는 거부」가 아니다(I-4 §5-3 단서 미해당). 기준 4 도 같은 답이다 — `M-01-09:74` §4-A 「출고 수량 =
읽기 전용 — 출고에서」라 **덮어쓰면 화면이 본 차이와 저장된 차이가 갈린다**.
칸 이름 ✅ `goods_issue_line.**issue_qty**`(`schema.prisma:781`) ↔ `shopfloor_receipt_line.issued_qty`(`:1394`).
코드 실재 ✅ `REQUIRED:9`·`RANGE:10`·`INVALID:13`·`STATE_LOCKED:17`·`LINE_REQUIRED:24`(`error-codes.ts`).
✏ **메시지를 갈라 적는다** — 「이미 수령한 출고」와 「전기되지 않은/취소된 출고」가 같은 `STATE_LOCKED` 인데 `M-01-09:195-204`
§6 예외표에 대응 행이 **없다**. 문구 셋을 계획서에 못박고 「화면 §6 에 행 셋이 는다」를 §8-3 에.

## 4. 출고 상태 게이트 `POSTED` 만 — ✅ · ✏ 화면 정합 한 줄
