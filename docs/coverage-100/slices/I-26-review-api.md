## 1. 버그 / 정확성

### M-1 [Major] 즉시 GET의 µs 경계·허용 날짜 형식 처리 계획 누락

- 지적: `I-26-draft.md:192`·`:320`·`:402`. 반열림 연산자만 정했고 정밀도/정규화 및 검증 이름은 빠졌다. 예산 비교 대상 `production-result-query.service.ts:39`·`material-return-query.service.ts:39`는 `new Date()`로 경계를 만든다.
- 새로 직접 대조한 사실: `prisma/schema.prisma:3683`의 produced_at은 **Timestamptz(6)**이며 고정 계약`:4075`·`:4084`는 date-time이다. 따라서 `.000000Z` 저장 행을 from=`.000001Z`로 조회할 때 Date 절삭이면 잘못 포함되고, to=`.000001Z`이면 잘못 제외된다. items와 total에 같은 잘못된 where를 써도 오답은 그대로다.
- 형식도 함께 고쳐야 한다. I-28 실재 HTTP 근거(`docs/coverage-100/slices/I-28-get-code-review.md:22`·`:30`)는 문자열 직결만 하면 Ajv가 받는 `+0700`·단일 공백류가 Prisma에서 실패함을 보였다. 그 실험을 여기서 재실행했다고 주장하지 않는다.
- 권고: 양 경계를 **µs 격자로 올림 + 허용 형식 정규화**한 문자열로 조회한다. `src/app/notification/notification-time-boundary.ts:2`·`:13`의 순수 함수가 실제 선례다. I-28 도메인 service를 호출하거나 validator가 받는 입력을 축소하지 않는다.
- R에서 국소 함수 복제 또는 순수 함수의 작은 공용 이관 중 소유·diff를 보고 정한다. GET180 예산/테스트 목록을 함께 수정한다. 응답 producedAt의 기존 Date 직렬화와 **필터 판정 정밀도**는 별개로 명시한다.

### M-2 [Major] raw 배분 수량을 개체 수로 사용할 단위 조건 누락 — POST 재개 전

- 지적: `I-26-draft.md:225`·`:235`·`:240`. `SUM(allocated_qty) - COUNT(serial_number)`를 단위 확인 없이 비교하면 서로 다른 단위의 수량을 개체 수에 직접 더한다.
- 근거: `schema.prisma:2869` 배분 uom_id와 `:3522` LOT uom_id는 별개다. `production-result.service.ts:106`은 요청 uomId를 각 배분에 저장하며 `:181`은 존재만 확인한다. `:153`의 슬롯 조회도 단위 대조를 하지 않는다. baseline `migration.sql:1674`는 FK만, `:2902`의 지연 트리거는 실적별 숫자 합만 검사한다.
- 반례: 같은 LOT에 `10 EA`와 `2 BOX` 배분이 들어와도 초안은 12개로 계산한다. 소수도입 여부와 무관한 차원 오류다. `mdm.item_uom_conversion`(`schema.prisma:1841`)이 있다는 사실만으로 목표 개체 단위/유효일/환산 정책이 정해지지는 않는다.
- 권고: 잠근 LOT·배분들의 단위를 읽고, **개체 단위 원천과 허용 조합을 명시**한다. 혼합/환산 불가 상태를 조용히 합산하지 말고400 `INVALID` 등 기존 봉투로 거부하는 가장자리안을 R에서 판정한다. 전품목 대상 원칙을 임의 품목분류 게이트로 바꾸거나 환산율을 지어내지 않는다.
- 이는 기존 I-7 코드를 이 PR에서 고치라는 요구가 아니다. 그 데이터의 신규 소비자인 발번이 추가로 지켜야 할 전제다. 기존 단위 검증·DB 제약 또는 개체 환산 근거가 확인되면 이 판정은 뒤집을 수 있다.

## 2. 보안

추가 지적 없음. GET403 미선언/인증 유지, POST 사번 귀속과 계정 감사 분리, derived 권한 재사용, 단말×공정 기능 구성, 멱등 actor/query 포함을 대조했다. 새로운 인증 경계나 공용 권한 변경을 요구하지 않는다.

## 3. 테스트

계획 리뷰이므로 실행0. 기존 초안의 정상/빈 목록/AND/페이지·동시 LOT/배치 롤백/멱등 결과 실패 이름은 적절하다. 다음 누락을 해당 PR의 파일 단위 검증 계획에 넣는다.

- GET: DB에 실제 µs 행을 두고6/7/9/10자리 from/to·0꼬리·날짜 캐리에서 **ID와 page.total**을 기대값과 비교한다. 한쪽 경계만 제공 및 NULL produced_at도 유지한다.
- GET: 고정 validator가 허용하는 T/t/공백류·Z/z·±HH:MM/±HHMM/±HH 조합을 실제 HTTP로 확인한다. 정규화 단위 테스트만으로 Prisma 전달 호환을 닫지 않는다.
- POST 재개: 같은 LOT에 단위가 다른 두 실적, 동일단위지만 개체 단위 매핑 불명, 환산 부재를 테스트하고 실패 시 **개체·멱등 기록0증가**를 확인한다. 단위 해소 뒤 기존 Decimal2.5/잔량1.5 사례를 유지한다.
- TraceModule 변경은 새 시리얼 E2E와 기존 trace-lot 부팅 회귀가 필요하다. 시간 함수를 공용으로 이관할 때만 기존 알림 시간 E2E도 영향 회귀로 추가한다.
