### 4-1. `GET /quality/disposition-candidates` — 원천 둘의 UNION × **불량창고 축** (⭐ R-4 로 다시 씀)

> ⛔ **초판은 「`mdm.warehouse` 에 불량창고를 가리는 칸이 0개」를 전제로 썼다. 거짓이다**(R-4 · 세 관점 독립 일치).
> `is_defect Boolean @default(false)` 가 **baseline 뒤 마이그**(`20260828000000:25`)로 섰고 `schema.prisma:2314` 에 있으며
> `warehouse.service.ts:104` 가 **이미 그 축으로 목록을 거른다.** 그리고 **계약이 세 칸을 그 축으로 정의했다** —
> `warehouseId` 「목록은 `GET /mdm/warehouses?isDefect=true` 가 준다」 · `quantity` 「그 LOT 이 **불량창고에 들어온 수량**이다」 ·
> `receivedAt` 「**불량창고에 들어온 날**」.

```
WITH cand AS (
  -- RETURN: 반품 입고로 들어온 LOT
  SELECT gl.lot_id, 'RETURN' AS source_code, g.goods_receipt_id, g.goods_receipt_no,
         <원 출하 거래처> AS partner_name, NULL::bigint AS inspection_result_id
    FROM logistics.goods_receipt_line gl
    JOIN logistics.goods_receipt g ON g.goods_receipt_id = gl.goods_receipt_id
   WHERE g.receipt_type_code = 'RETURN'
  UNION ALL
  -- PRODUCT: OQC 확정 불합격
  SELECT req.lot_id, 'PRODUCT', NULL, NULL, NULL, r.inspection_result_id
    FROM quality.inspection_result r
    JOIN quality.inspection_request req ON req.inspection_request_id = r.inspection_request_id
   WHERE r.status_code = 'CONFIRMED' AND req.inspection_type_code = 'OQC'
     AND r.overall_judgment_code = <불합격> AND req.lot_id IS NOT NULL
)
SELECT … FROM cand c
  JOIN LATERAL (                                   -- ⭐ 불량창고 잔액만 본다
    SELECT b.warehouse_id, b.uom_id,
           sum(b.on_hand_qty)          AS qty,
           max(b.last_transaction_at)  AS received_at      -- ⭐ R-18 · 두 갈래 공통
      FROM inventory.inventory_balance b
      JOIN mdm.warehouse w ON w.warehouse_id = b.warehouse_id AND w.is_defect = true
     WHERE b.lot_id = c.lot_id AND b.on_hand_qty <> 0      -- ⭐ I-20 R-22
     GROUP BY b.warehouse_id, b.uom_id
     ORDER BY sum(b.on_hand_qty) DESC LIMIT 1
  ) bal ON TRUE
```

- ⭐ **`warehouseId`(required)를 「조용히 고르는」 문제 자체가 사라진다** — 모집단이 이미 불량창고 잔액이다. ⛔ **초판의 「잔액 창고가 둘 이상이면 목록에서 뺀다」를 폐기한다**: ⓐ 계약이 그 모양을 직접 금지했다(「⛔ 화면이 응답을 걸러 … **목록이 페이지 단위라 성립하지 않는다**」) ⓑ §2 2단계 **기준 4 는 「값을 조용히 도출하지 않는다」이지 「행을 조용히 없앤다」가 아니다** — 없애는 쪽은 `L-8` 과 정면으로 부딪힌다 ⓒ ⭐ **부적합 등록의 «유일한» 진입을 막는다**(`W-04-07` 하나가 부적합을 만든다) — 게다가 그 상태를 **우리 시스템이 스스로 만든다**: `W-04-11` 이 **부분 재등록**을 허용하므로 200 중 100 만 완제품창고로 돌아가면 그 LOT 은 즉시 「창고 둘」이 되어 **남은 100 의 부적합 등록이 영영 막힌다.**
- ⚠ **불량창고가 둘 이상인 LOT** 은 `ORDER BY sum(on_hand_qty) DESC LIMIT 1` 로 **가장 큰 불량창고 하나**를 싣는다 — 행을 없애지 않는다. 화면이 `warehouseId` 로 좁히면 그 창고로 다시 거른다.
