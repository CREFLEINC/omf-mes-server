## 4. 공통코드 시드 — 실측

두 이슈가 요구한 **42그룹 173값** 중 시드(`prisma/seed.ts` 40그룹 + 베이스라인 마이그레이션 20그룹)에
이름이 있는 것은 **7그룹뿐이고, 그 7그룹은 전부 값이 다르다.**

| 그룹 | 시드 현재 | 이슈 요구 |
|---|---|---|
| `EQUIPMENT_STATUS` | NEW·NORMAL·MAINTENANCE·BREAKDOWN·DISPOSED | IN_SERVICE·DISPOSED (계약이 「2값·늘리지 않는다」) |
| `EQUIPMENT_TYPE` | MACHINE·INSPECTION·UTILITY | INJECTION_MOLDING·PRESS·WATER_HEATER (+ `INSTRUMENT_TYPE` 분리) |
| `PROCESS_TYPE` | INTERNAL·OUTSOURCED | MACHINING·ASSEMBLY·INSPECTION·PACKAGING — **축 자체가 다르다** |
| `INSPECTION_FREQUENCY` | 4값 | 8값 |
| `QUALIFICATION_TYPE` | 2값 | 4값 |
| `STORAGE_CONDITION` | NORMAL·COLD·FROZEN·HAZARD | REFRIGERATED·FROZEN·ROOM_TEMPERATURE·MOISTURE_CONTROLLED·HAZARDOUS |
| `WORK_SESSION_EVENT_TYPE` | START·**PAUSE**·RESUME·END | START·**STOP**·RESUME·END·CONTROL_OVERRIDE |

`PROCESS_TYPE`은 v4가 외주 축을 `routing_operation.is_subcontract`로 따로 뺐으므로 시드의
INTERNAL/OUTSOURCED가 이중 표현이 됐다. `WORK_SESSION_EVENT_TYPE`은 **시스템 소유 그룹**이라
값이 동작을 가른다 — 이름 충돌 중 가장 위험하다.

⛔ **답이 오기 전에 `upsert`로 덮지 않는다.** 되돌릴 수 없다.
그리고 `mdm.code_group`에는 **그룹별 편집 가능 플래그가 없어** 「시스템 소유」를 표시할 자리 자체가 없다.

「멱등 헤더가 있는 쓰기는 `app.idempotency_record`와 연결한다」고 적은 것이 산출물에서 지켜지지 않았다.
지금은 222건이 연결된다.

### 남은 결손

- **`updated_at` 트리거 20개 누락** — 컬럼 보유 93표 중 트리거 73개.
  v4 신규 18표 + `app.user_credential` + `quality.defect_record`.
  DDL·마이그레이션이 똑같이 빠뜨리므로 **산출물 불일치가 아니라 모델 자체의 결손이다.**
- **`api-table-map`이 헤더+라인 동시 INSERT를 표현하지 못한다** — `SUPPORTING` 역할의 `access`가 전부 `READ`.
  `POST /logistics/inbound-receipts`에 `trace.lot`이 빠져 있다.
  **코어(재고 posting·lot 계보) PR을 이 표로 착수하면 lot 생성·hold·재고 전기를 설계에서 누락한다.**
- `04-verification-report.md`의 17개 PASS 중 이 저장소만으로 재현 가능한 것은 소수다 —
  XLSX 3건은 `openpyxl`·`recalc.py`·LibreOffice가 필요하고, DB 검증 항목은 DB가 필요하다.
  「7/7 게이트」는 같은 `workbook-data.json`에서 나온 Expected와 Actual을 비교하는 자기참조 검사다.

## 7. 확인 못 한 것

1. **운영 DB 실데이터** — 전 판정이 문서·소스 수준이다. 백필이 필요한 마이그레이션
   (`#50` 축 전환, `EQUIPMENT_STATUS` 2값화, `STORAGE_CONDITION` 값 교체)의 비용을 지금 산정할 수 없다.
2. 되돌림 문서 9번(권한 코드 이름 체계) — 결론에 이르지 못했다.
3. `#42`의 「8건」에서 여덟 번째가 무엇인지 — §I 대장은 7항목만 열거한다.
4. `WAREHOUSE_TYPE`에 `DEFECT`·`REWORK`가 왜 시드에 들어갔는지 — 결정 근거를 찾지 못했다.
5. 출하 시간대 슬롯의 시간대 규약 — `time without time zone`인데 `shipment_request`에 `plant_id`가 없다.
   현재 CHECK가 자정 넘김을 금지하므로 야간 슬롯을 담지 못한다.
6. 04 제품출하 도메인의 계약↔물리 차이 3건(`salesOrderId`·`shippingInspectionStatusCode`·`pickedQty`) —
   이번 범위 밖이라 깊이 파지 않았다. 착수 전 별도 확인이 필요하다.
