# 자체 비밀번호 인증을 쓴다

정본 물리 모델에 자격증명 저장소가 없었다 — 요구사항 `1-2 사용자·권한 관리`가 권한만
다루고 로그인 수단을 언급하지 않아 설계에서 빠졌다. 외부 IdP 도입은 현장 인프라가
확정되지 않아 선택지가 아니었다. 자체 비밀번호 인증을 쓰고 `app.user_credential` 을
후속 마이그레이션으로 보완한다 (2026-07-28 확정).

`app_user` 에 컬럼을 더하지 않고 별도 테이블로 둔 이유: 자격증명의 수명주기가 계정
정보와 다르고, 정본 테이블 형태를 건드리지 않아 모델링 측 갱신과 충돌이 적으며,
나중에 LDAP/AD 로 전환하면 이 테이블만 걷어내면 된다.

> `app.user_credential` 은 구현 측 추가분이다. 모델링 정본 SQL 에 역반영이 필요하다.

## Consequences

세부 선택과 그 이유. 재작성 시 그대로 따른다.

| 항목 | 선택 | 이유 |
|---|---|---|
| 해시 | Node 내장 `scrypt` (N=2^15·r=8·p=1) | argon2id 가 최신 권고지만 npm 구현이 네이티브 빌드를 요구한다. 배포가 오프라인 설치 패키지라 빌드 툴체인 의존을 늘리지 않는다. scrypt 도 메모리 하드 KDF 다 |
| `maxmem` 명시 | 필수 | `128*N*r`=32MB 가 Node 기본 maxmem 과 같아, 지정하지 않으면 `ERR_CRYPTO_INVALID_SCRYPT_PARAMS` 로 해싱이 통째로 실패한다 |
| 해시 저장 형식 | `scrypt$N$r$p$salt$hash` | 자기서술적이라 파라미터·알고리즘을 바꿔도 옛 해시를 읽으며 점진 재해싱할 수 있다 |
| 로그인 실패 응답 | 사유를 구분하지 않음 | 없는 계정 / 틀린 비밀번호 / 자격증명 미발급이 같은 메시지다. 계정 존재 여부가 새면 열거 공격의 출발점이 된다. 없는 계정도 미끼 해시로 검증에 준하는 시간을 쓴다 — **완전히 같지는 않다.** 실제 계정 경로에 실패 카운터 UPDATE 가 하나 더 있어 약 4ms 느리다(scrypt 50ms 기준). 네트워크 지터에 묻히는 크기라 그 이상 맞추지 않는다 |
| 계정 잠금 | **보류 — 실패 횟수만 센다** (2026-08-05) | 아래 참조 |
| 토큰 검증 | 매 요청 계정 재확인 | 토큰 발급 뒤 계정이 정지·해지될 수 있다 |
| `JWT_SECRET` | 없거나 32자 미만이면 기동 실패 | 기본값을 두면 약한 키로 조용히 운영에 올라간다 |
| 최초 관리자 | 시드가 `admin` 생성. 설치 스크립트가 확인 입력받아 `.env.prod`에 보관한 `ADMIN_INITIAL_PASSWORD`를 사용 | 설치 관리자가 확정한 비밀번호를 유지하며 첫 로그인 변경을 강제하지 않는다. 직접 시드할 때 값이 없거나 비어 있으면 무작위 생성 후 1회 출력한다 |

보호는 **화이트리스트**다 — `@Public()` 이 붙지 않은 모든 엔드포인트가 토큰을 요구한다.
새 엔드포인트를 만들며 보호를 깜빡해도 막힌 상태로 시작한다. 공개는 로그인과 헬스체크뿐이다
(헬스체크는 컨테이너가 토큰 없이 호출한다).

## 계정 잠금 보류 (2026-08-05)

원래는 "연속 5회 실패 → 15분 잠금"이었으나 재작성 시 **잠금 판정을 넣지 않기로 했다.**
`failed_attempt_count` 는 올리고 성공하면 0으로 되돌린다 — 잠글 때 근거가 되고, 그전에도
"이 계정에 시도가 쌓이고 있다"를 DB 에서 볼 수 있다.

그동안 무차별 대입을 막는 것은 `scrypt` 의 시도당 비용(N=2¹⁵·64MB)뿐이다. 온프레미스
설치형이라 외부 노출이 아니지만 내부망에서도 자동화 시도는 가능하다. 잠금을 붙일 때는
`locked_until` 컬럼이 이미 있으므로 판정 한 줄이면 된다.

## 미구현으로 남긴 것

| 항목 | 상태 |
|---|---|
| 계정 잠금 | 위 참조 — 컬럼은 있고 판정만 없다 |
| 데이터 접근범위 적용 (RLS 등) | 범위를 저장할 뿐 조회를 걸러내지 않는다 |
| 토큰 무효화 (로그아웃·강제 만료) | JWT 라 만료 전까지 유효하다. 계정 정지는 매 요청 확인으로 즉시 반영된다 |
| POP 사번 경량 인증 | 별도 경로. `worker_no` 기반이며 관리 화면 계정과 이원화된다 (REQ-PR-0023) |

계약 문서(`mdm-기준정보.json`)에는 `securitySchemes` 도 `401` 응답도 없다. 인증 방식에
대해 스펙은 아무 말도 하지 않으며, `403 권한 없음`만 61개 오퍼레이션에 정의한다.
따라서 인증의 재건 근거는 이 ADR 이다.
