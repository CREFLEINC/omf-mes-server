# 응용 코드를 버리고 스펙 기준으로 다시 쓴다

`deliverables/openapi/mdm-기준정보.json` 이 요구하는 계약과 기존 `src/` 는 필드
이름이 아니라 **식별자 세계관**이 다르다. 기존 코드는 코드 문자열이 식별자이고
(`getWarehouse(warehouseCode)`, `resolveForWarehouse(legalEntityCode, plantCode, …)`),
스펙은 id 가 식별자이며 코드는 서버가 수정 가능 여부를 판정해 주는 표시 필드다
(`editability.codeEditable`). 이 차이는 어댑터나 응답 매퍼로 좁혀지지 않고 서비스
시그니처 전체에 걸쳐 있다. 점진 수정은 고칠 때마다 다시 어긋난다.

따라서 `src/` 전체를 삭제하고 스펙 기준으로 새로 쓴다. `prisma/schema.prisma` 와
마이그레이션은 남는다 — 스펙 스스로 "정본은 물리 모델이며 이 문서는 그것을 옮긴
것"이라 선언했고, 마이그레이션은 forward-only 다.

## Considered Options

- **기존 위에 얇은 어댑터** — `If-Match`·`editability`·참조 건수·`PUT` 전체 교체는
  서비스 계층을 바꿔야 하는 것들이라 어댑터로 흡수되지 않는다.
- **`/mdm` 을 병행 표면으로 추가** — 같은 도메인에 규칙이 다른 두 표면이 남고
  삭제 시점을 정할 주체가 없다.
- **`master-data` 만 삭제하고 `pop`·`auth` 는 유지** — 이들도 정본 없이 만들어져
  결국 같은 어긋남을 겪는다. 두 번 지우느니 한 번에 지운다.
- **물리 모델부터 재설계** — 스펙이 물리 모델을 정본으로 선언했고 마이그레이션이
  forward-only 라 계약 소유자 합의 없이는 불가.

## Consequences

- **재건 근거가 있는 것**: `mdm` 46개(이번 범위), `/app` 태그 16개(다음 라운드).
- **재건 근거가 없는 것**: `auth`(로그인·JWT·터미널 토큰), `pop`(작업시작·생산실적).
  스펙이 아직 없다. `auth` 는 mdm API 의 403·권한 검사가 전제하므로 먼저 필요하고,
  스펙 대신 **삭제 전 코드를 근거로** 다시 짓는다. `pop` 은 자체 스펙이 나올 때까지
  기능이 없는 상태로 둔다.
- 기존 서비스에는 스펙에 없는 도메인 규칙이 박혀 있었다 — 외부창고의 거래처 필수
  (`ck_external_warehouse_partner`), 로케이션 상위 순환 방지, 수용량/단위 쌍,
  사용 중지 시 하위 활성 로케이션 검사. 스펙은 이들을 `400 ErrorItem{code}` 형태로만
  말한다. **삭제 커밋 전에 규칙과 테스트 이름을 문서로 건져낸다.**
- 스펙 초안은 **형태(경로·메서드·봉투·헤더)만 동결**로 취급한다. 미결 항목
  (편집 권한 매트릭스 §8-8, `editability` 판정 규칙 §8-7)은 구현하면서 정하고
  계약 소유자에게 되돌린다.
