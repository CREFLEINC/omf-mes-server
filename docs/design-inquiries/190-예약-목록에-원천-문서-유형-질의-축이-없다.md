# 190. 재고 예약 목록에 **원천 문서 «유형» 질의 축이 없다** — 제품 피킹이 예약을 걸면 자재 예약과 섞이고 계약 enum 을 런타임에 벗어난다

**구분: 통보**(회신을 기다리지 않는다) · ⭐ **이슈 #409 가 I-22 에 넘긴 「⚠ 인계」의 답입니다**

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /inventory/reservations`(01 자재창고 · **이미 배포됨** · I-8) · `POST /logistics/shipment-requests/{id}/lines/{lineId}:pick`(04 · I-22 가 만든다) |
| 구현 상태 | **구현 예정(I-22 PR ①·⑥)** — 계획서 `docs/coverage-100/slices/I-22.md` §11 ② · §1-5 · §6 |
| 판정 | §2 **1단계 본길** → 계약이 「가리킬 표가 늘면 계약을 고친다」라 «스스로» 적어 0단계에서 닫힘 ⇒ **`SHIPMENT_REQUEST_LINE` 을 쓰고 통보** |
| 되돌릴 때 | 판별자 값을 바꾸면 예약 INSERT 한 줄과 e2e 한 건. **질의 축은 계약이 열어 주셔야 합니다** |

## 무슨 일이 일어나나

04 제품 피킹(`:pick`)이 **`inventory_reservation` 행을 만듭니다.** 계약이 그렇게 적었습니다 —
`POST …:pick` description 「서버가 이 피킹의 결과로 `inventory_reservation` 을 **걸고 푼다**(01 자재창고 계약 · `M-01-08` §5-5 와 같은 규약)」 ·
`GET /logistics/shipment-lot-allocations` `x-internal-note` 「제품 피킹은 배분을 만들지 않는다 — … **서버가 그 결과로 `inventory.inventory_reservation` 을 건다**」.

그 행의 판별자에는 **`SHIPMENT_REQUEST_LINE`** 이 들어갑니다(`sourceDocumentId` = `shipment_request_line_id`).

## ⛔ 그런데 두 가지가 막힙니다

| # | 실측 | 결과 |
|:-:|---|---|
| 1 | `InventoryReservation.sourceDocumentTypeCode` 의 **`enum` 이 `["PRODUCTION_ORDER"]` 하나**입니다 | 배포된 `GET /inventory/reservations` 가 **계약 enum 밖의 값을 내리기 시작**합니다 |
| 2 | 같은 오퍼레이션의 질의 축이 **여덟**(`itemId`·`lotId`·`warehouseId`·`sourceDocumentId`·`statusCode`·`openOnly`·`page`·`size`)인데 **`sourceDocumentTypeCode` 가 없습니다** | **자재 예약과 제품 출하 예약이 한 목록에 섞이고 화면이 걸러 낼 축이 없습니다** |

⭐ 계약 자신이 그 문장을 미리 적어 두었습니다 — 같은 칸의 description 「**A-10 다형 참조 판별자**이고 값은 «대상 테이블 이름»이다 … 지금은 하나다 — 생산오더. ⚠ **값이 하나라고 축이 없는 것이 아니다** — 가리킬 표가 늘면 **계약을 고친다**」.

## ⇒ 우리가 정한 것

- 판별자 값은 **`SHIPMENT_REQUEST_LINE`**(라인 축 — `picks[]` 가 라인 단위이고 `ShipmentRequestLine.pickedQty` 가 그 합입니다).
- 예약 유형은 **`SHIPMENT`**(시드 `RESERVATION_TYPE` 에 「출하예약」으로 이미 있습니다).
- 상태는 **상수 `'REGISTERED'`**(그 칸은 `x-no-code-key` 로 「예약의 유효·소진은 수량 축이 담고 이 칸을 움직이는 오퍼레이션이 없다」라 닫혔습니다).
- ⭐ **`:pick` 이 걸자마자 «푸는» 쪽(ⓒ안)으로 갑니다** — `consumed_qty = reserved_qty` 라 **`openOnly=true` 가 제품 예약을 즉시 걸러 냅니다.** 걸기만 하는 안이었다면 출하가 끝날 때까지 「열린 예약」으로 남아 `M-01-08` 목록을 오염시켰을 것입니다.

## 📨 알려 드리는 것

1. **`InventoryReservation.sourceDocumentTypeCode` 의 `enum` 에 `SHIPMENT_REQUEST_LINE` 을 더해 주십시오.** 계약에서 만든 클라이언트가 지금은 그 값을 못 읽습니다.
2. ⭐ **`GET /inventory/reservations` 에 `sourceDocumentTypeCode` 질의 축을 열어 주십시오.** 없으면 `M-01-08`(자재 출고 피킹)의 예약 목록에 제품 출하 예약이 섞여 나옵니다. `openOnly` 로는 「아직 안 나간 것」만 갈리지 유형이 안 갈립니다.
