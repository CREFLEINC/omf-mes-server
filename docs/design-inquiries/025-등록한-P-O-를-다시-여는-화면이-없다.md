# 25. 등록한 P/O 를 다시 여는 화면이 화면 인벤토리에 없다 — 수정·라인 치환·재상신이 갈 곳이 없다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `PUT /logistics/purchase-orders/{id}` · `PUT …/{id}/lines` · `POST …/{id}:request-approval`(반려 후 재상신) — 그리고 `W-01-11` §5-3 이 요구한 「목록·상세의 ERP 미매칭 배지」가 붙을 `GET /logistics/purchase-orders`·`…/{id}` |
| 구현 상태 | **구현함(계약대로 7건 전건)** — 화면이 없다고 오퍼레이션을 닫지 않는다. 403 권한은 `W-01-11`(그 자원의 마스터를 소유하는 화면)로 등록한다 |
| 판정 | 서버 갈림길이 아니다(§2 절차를 돌릴 자리가 없다 — 어느 쪽을 골라도 서버 동작이 같다). **설계가 화면을 세울지 답해야 닫히는 결손**이라 「알려둘 것」이 아니라 문의로 세운다. 같은 갈래가 `plan.md` §7 에 이미 있다(「`POST /production/material-returns` 소유 화면」 I-10 · 「수리 `:return` 뒤 재투입 등록처」 I-25) |
| 되돌릴 때 | 화면이 서면 서버는 그대로다. 권한 매핑(`manual-permissions.ts` 3줄)의 화면 ID 만 바뀐다 |

## 무엇이 문제인가

**실측** — 01 자재창고 도메인 화면 **26장**(관리웹 12 · 모바일 12 · POP 2)에 **구매발주 목록·상세 화면이 없다**(화면 인벤토리 전수).
- `W-01-09` 는 **ASN(입하 예정)** 목록이고 P/O 는 「진행」 열의 분모(`received_qty / ordered_qty`)로만 쓴다.
- `W-01-11` 은 §3 이 **단일 폼**이고 §5-4 가 「등록 후 `W-01-03` 으로 복귀」다 — **기존 P/O 로 되돌아오는 진입이 없다.**
- `W-01-13`(물류 문서 진행현황)은 P/O 를 9종에 넣어 **조회**는 덮지만, 액션은 취소뿐이고 P/O 는 `TYPE_NOT_CANCELABLE` 이다.
- `W-02-01` 「P/O 수신·조회」는 `planning.production_order`(생산오더)라 **다른 표**다.

그런데 계약과 화면 명세가 재진입을 전제한 자리가 넷이다.

| 요구한 문장 | 걸리는 오퍼레이션 | 붙을 화면 |
|---|---|:-:|
| `W-01-11` §5-3 「**목록·상세에서 「ERP 미매칭」 배지**를 붙인다」 | `GET …` · `GET …/{id}` | 없다 |
| `W-CO-09` §5-8 「번복은 **새 요청**이다 — 상신자가 **대상 화면에서 다시 올린다**」 | `…:request-approval`(반려 후) | 없다 |
| 계약 `PurchaseOrderUpdate`(공급사·발주일·입고예정일 수정) | `PUT …/{id}` | `plan-uiux.md` U4 화면 열이 「—」 |
| 계약 `PUT …/{id}/lines`(라인 전체 치환) | `PUT …/{id}/lines` | U4 가 `W-01-11` 로 적었으나 §5-1 의 「라인 추가·삭제」는 **등록 «전» 폼 안의 행위**라 `POST` 본문으로 간다 |

⚠ 계약 `GET …/{id}/lines` 의 근거가 「`W-01-11` §4-B」인데 **§4-B 는 폼의 필드 표**다 — 계약 자신이 재진입 화면 대신 폼 표를 가리킨 자리다.

## 지금 서버는

7건 전건을 계약대로 연다. 권한은 「`W-01-11` 이 P/O 라는 자원의 마스터를 소유한다」를 근거로 세 오퍼레이션(`PUT` 둘 · `:request-approval`)을 `manual-permissions.ts` 에 등록한다 — 계약이 403 을 선언했으므로 미등록이면 500 이 난다.

## 요청

1. **등록한 P/O 를 다시 여는 화면**(목록·상세 또는 `W-01-11` 의 재진입 모드)을 세울 것인지 알려 주십시오. 세운다면 화면 ID 를 주시면 권한 매핑을 그 화면으로 옮깁니다.
2. 세우지 않는다면 — **반려된 P/O 를 어떻게 다시 올리는지**(`W-CO-09` §5-8 의 「대상 화면」이 어디인지)와 **ERP 미매칭 배지를 어느 화면이 보이는지** 알려 주십시오.
3. 곁들여: `GET /logistics/purchase-orders?q=` 「발주번호 검색」의 대상을 **MES 번호(`purchase_order_no`) 하나**로 구현했습니다(번호가 둘이라 조용히 둘 다 검색하지 않았습니다). 전산(ERP 연계)담당이 **ERP 번호로 찾는 자리**가 필요하면 화면과 함께 정해 주십시오.

우리 권고안(회신이 없으면 이대로 갈 값): **7건 전건 열어 두고 화면은 기다린다.** 서버를 열어 두는 쪽이 되돌리기 싸고(닫으면 화면이 생길 때 다시 열어야 한다), 1차 배포 노트에 「P/O 수정·재상신은 API 만 있고 화면이 없다」를 남깁니다.
