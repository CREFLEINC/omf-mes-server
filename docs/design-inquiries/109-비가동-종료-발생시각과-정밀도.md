# 109. 비가동 ‘지금 종료’는 서버 최초 처리시각을 사용한다

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 2026-09-09 사용자 결정 완료, 설계팀 회신을 기다리지 않음 |
| 걸리는 오퍼레이션 | POST `/maintenance/downtimes/{downtimeId}:close` |
| 구현 상태 | 서버 최초 처리시각 기준으로 close 1건 구현 재개 |
| 판정 | 종료 발생시각 입력이 없는 고정 계약을 유지하고, 이 operation만 서버 처리시각을 쓰는 예외로 확정 |
| 되돌릴 때 | 향후 실제 단말 발생시각 입력이 계약에 추가되면 신규 요청부터 그 값을 사용한다. 기존 저장 종료시각은 단말 발생시각으로 소급 복원할 수 없음 |

고정계약 equipment-05설비툴.json:1920은 지금 종료·오프라인 큐·If-Match 선택을 명시하지만 requestBody가 없다. 공유계약 C-12:1862는 시작과 끝을 같은 단말 시계로 기록하며 서버가 덮지 않는 규칙을 유지한다. 오차 전송/보정/경고는 범위에서 철회했다.

단말 시작10:00·오프라인 종료버튼10:05·서버 도착10:30이라면 **요청에10:05가 없다**. 이번 결정은 서버가 최초로 처리한10:30을 종료시각으로 저장하고 전송 지연25분을 허용한다. 시작+임의 길이나 단말의 버튼 시각을 소급 추정하지 않는다.

## 결정과 설계 문서 반영 요청

1. `endedAt`은 같은 멱등 요청을 서버가 최초로 처리할 때 서버 clock을 한 번 읽어 저장한다.
2. 같은 `Idempotency-Key` 재전송은 최초 저장한 종료시각과 응답을 재생하며 재전송 시각으로 갱신하지 않는다.
3. 새 요청 body·시각 header를 추가하지 않고 선택 `If-Match`와 작업자 귀속 계약을 유지한다.
4. 이 operation은 시작·종료를 같은 단말 시계로 기록한다는 공통 C-12의 명시적 예외다.
5. 설계팀은 OpenAPI의 ‘지금 시각’을 **서버 최초 처리시각**으로 명확히 하고, 오프라인 전송 지연 허용·C-12 예외·멱등 재생의 최초시각 유지를 관련 설계 문서에 반영한다.

이 문서는 회신을 요구하는 질의가 아니라 결정 통보다. 설계 문서 반영을 구현 또는 배포 선행조건으로 두지 않으며, 추후 Lane B 통보와 함께 일괄 정산한다.

## 생성·수정에 적용하는 시각 판정

- PostgreSQL timestamptz(6)에 맞게 문자열 바인딩·epoch µs 문자열/BigInt·UTC ISO6로 입력→저장→잠금→응답→멱등 재생을 보존한다. Date 절삭·AT TIME ZONE·서버 보완0.
- 소수6자리까지 정상이며7번째 이후 비영 값만400 RANGE. 뒤가0뿐이면 instant가 같아 허용한다. -1µs는1969-12-31T23:59:59.999999Z다.
- P-05-02 §6-1의 미래 인라인 검사는 화면의 단말 로컬 now 책임으로 판정했다. C-12의5분 빠른 동일 시계 사례를 서버 now로 거부하지 않는다. 서버는 유효 instant·물리정밀도·ended>=started를 검증한다. **직접 HTTP의 미래값은 그 이유만으로 차단하지 않는 한계**를 화면 담당에게 인계한다. 임의 오차폭/보정헤더0.
- durationMinutes는0·60·90초에서0·1·null이며 정수화/반올림0(기존095). required integer summary에는 null 해법을 복사하지 않는다(112).

close의 이미 닫힘은 구체409 설명 ‘업무 상태 잠김은400’을 일반422보다 우선해400 STATE_LOCKED로 확정했다. 고정 응답 목록의400 누락도 설계 문서 정합성 보완 대상으로 함께 통보하되 구현 선행조건으로 두지 않는다.

## R14 구현 전 실측 보완: 문법 허용과 동일순간 보존

Ajv가 허용한0년/offset+23:59는 PostgreSQL 문자열cast에서오류, 윤초60초는익일로접히며소수윤초는오류임을상수SELECT로확인했다. 따라서단순원문바인딩대신정수초+별도µs의정확한epoch를PG지원UTC문자열로표현한다. ISO0년은1BC로표기하고offset을먼저UTC로변환하되소수는절삭하지않는다.

PG가별도순간으로보존하지못하는윤초는400 RANGE로명시거부(가장자리②·④). UTC정규응답의연도가계약4자리0000..9999밖이되는입력도400 RANGE이며기존DB의표현불가는500이다. **윤초/연도표현한계는일반단말의µs를ms로줄여도된다는뜻이아니다.** 같은순간·µs왕복테스트를추가하고조용한날짜보정0을유지한다.
