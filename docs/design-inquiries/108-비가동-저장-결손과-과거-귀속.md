# 108. 비가동의 필수 귀속·메모·버전과 기존 행의 저장 결손

| 칸 | 내용 |

| 상태 | 계획 확정·미적용. 추가3/완화1, 삭제·백필0. 정상 환경 구현4건 진행 |
| 판정 | README §2 0단계 계약 원천에 물리를 맞춤. 과거 결손행만 가장자리→②명시 실패·④임의 도출 금지 |

Downtime.recordedByWorkerNo는 required이며 생성 X-Worker-No가 원천인데 물리에는 저장칸이 없다. remarks와 version_no도 없어 각각 nullable text·nullable varchar(50) 사번·default1/positive CHECK 버전을 추가한다. 계약에 없는 downtime_type_code는 NOT NULL만 완화하고 신규 null을 저장한다. reasonCode와 type을 복제하거나 ACTUAL 같은 값을 만들지 않는다.

기존 reason_code는 nullable이며 created_by/closed_by는 계정 축이다. 이를 사번·입력자로 해석하지 않는다. 과거 사번/사유 결손은500 INTERNAL_ERROR이고 해당 행을 목록/total에서 숨기지 않는다. 배포 전 실제 DB 사전조회와 구 작성자 확인이 필요하며, 로컬0행이 운영0행을 뜻하지 않는다. 근거는 I-32 §1-4·§2·§3 및 고정계약 equipment-05설비툴.json:4258다.

**과거 필수 사유·입력 사번을 보완할 권위 있는 원천/담당 또는 응답 계약 조정이 있는지 확인해 달라.** 새 API용 nullable 추가만으로 기존 환경의 배포를 승인하지 않는다. 승인된 이관 원천이 생겨도 이번 마이그에 추정 백필을 포함하지 않는다.

workSessionId는 응답에만 있고 작성 주체/물리 칸이 없다. 현재 null을 반환하며 최근 세션·계획 장비로 연결하지 않는다. 이 칸의 작성 주체를 세울지 또는 걷을지 결정이 필요하다. 시각 µs가 있다는 사실은 결손이 아니며 정상 보존 대상이다(109).

시각 원천이 해소된 close만 종료 사번 칸을 별도 추가한다. 최초 사번을 종료자의 사번으로 덮지 않고, 활성 계정 주체와 계정 미연결 worker를 구분한다. 공용 로그인/CORS는 기존054·092, 로컬 지문과 전달tx는096 인계 원칙을 따른다.
