# 183. 처분 판정 대상 목록의 **「상태」가 화면에선 네 갈래인데 서버 축은 하나**다 — 계약 질의 칸이 모자란다

**구분: 통보**(회신을 기다리지 않는다 — ⚠ 다만 **우리가 정할 수 없는 자리**가 하나 섞여 있어 그 부분은 요청입니다)

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /quality/disposition-candidates`(질의 `withoutNonconformanceOnly` · 응답 `nonconformanceId`·`nonconformanceStatusCode`) |
| 구현 상태 | **구현 예정(I-21 PR ③)** — 계획서 `docs/coverage-100/slices/I-21.md` §4-1 |
| 판정 | §2 **1단계** — 계약이 준 질의 칸 그대로 구현한다. **없는 축은 지어내지 않는다**(F-6) |
| 되돌릴 때 | 질의 칸 `nonconformanceStatusCode` 를 열어 주시면 **`WHERE` 한 줄**이다 |

## 무엇이 어긋나나

화면은 **네 갈래**를 그립니다 — `W-04-07` §5-7 「상태 **네 갈래**(**부적합 없음** / 의뢰 전 / 판정 대기 / 판정 완료)」 · §3 목업 「상태 [ 의뢰 전 ▾ ]」.

계약 질의는 **`withoutNonconformanceOnly` 불리언 하나**뿐입니다. 그리고 **같은 계약이 클라이언트 필터를 금지했습니다**:

> ⛔ 화면이 응답을 걸러 「아직 안 만든 것」을 고르지 않는다 — **목록이 페이지 단위라 성립하지 않는다**

⇒ **「의뢰 전 / 판정 대기 / 판정 완료」 셋은 오늘 만들 수 없습니다.** 서버에 축이 없고 화면이 접는 것은 계약이 막았습니다.

## ⚠ 그리고 축이 하나 더 어긋납니다

우리 `withoutNonconformanceOnly` 는 **`NOT EXISTS(nonconformance_lot … WHERE nc.closed_at IS NULL)`** 입니다 — 즉 「**열린** 부적합이 없음」입니다(같은 대상을 두 번 등록하는 것을 막는 축이라 그렇게 읽었습니다).
그런데 응답 칸은 다릅니다 — `nonconformanceId` = 「**이미 만들어진** 부적합. **null 이면 아직 만들지 않았다**」.

⇒ **종결된 부적합만 있는 LOT** 은 우리 필터에서 「부적합 없음」으로 «남는데», 응답에는 `nonconformanceId` 와 `nonconformanceStatusCode='DECIDED'` 를 실어야 합니다. 화면 배지 넷 중 「부적합 없음」과 「판정 완료」가 **한 행에 겹칩니다.**

⚠ 그리고 **부적합이 «여럿»일 때 어느 것을 싣는지**가 계약에 없습니다. 우리는 등록에서 **「같은 LOT 에 열린 부적합은 하나」**를 409 `DUPLICATE_KEY` 로 강제하므로 **열린 것은 언제나 0 또는 1**이지만, **종결된 것은 여러 건**일 수 있습니다.

## ⇒ 우리가 정한 것

1. **`withoutNonconformanceOnly` 는 「열린 부적합이 없음」으로 둡니다** — 그 축이 「같은 대상을 두 번 등록하는 것을 막는다」는 계약 설명과 맞습니다.
2. **응답의 `nonconformance*` 3칸은 「가장 최근에 만들어진 부적합」**을 싣습니다(열린 것이 있으면 그것, 없으면 마지막 종결분).
3. **나머지 세 갈래 필터는 만들지 않습니다.** 클라이언트가 접는 것도 계약이 금지했으므로 **`W-04-07` 의 상태 드롭다운은 「부적합 없음 / 전체」 두 값으로 반쯤 열립니다** — 배포 노트에 적습니다.

## 📨 요청

**질의 파라미터 `nonconformanceStatusCode`(또는 `nonconformanceStatus` enum 4값)를 열어 주십시오.**
그러면 `WHERE` 한 줄로 화면의 배지 넷이 그대로 섭니다. 지금은 **화면 설계(§5-7 네 갈래)와 계약(불리언 하나)이 어긋난 채**입니다.
⚠ 함께 정해 주실 것 — **종결된 부적합만 있는 LOT 을 「부적합 없음」으로 볼 것인가**(우리는 그렇게 읽었습니다).
