# 199. 「배정 수량 **≥ 1**」을 **「0 을 거부한다」**로 읽었다 — 계약도 물리도 안 막는 «순수 서버 규칙»이다

**구분: 통보**(회신을 기다리지 않는다)

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /logistics/shipment-requests` |
| 구현 상태 | **구현 예정(I-22 PR ⑤)** — `allocatedQty > 0` 을 400 `RANGE` 로 막는다 |
| 판정 | §2 **0단계**(화면 §5-7 이 조건을 적었다) + **2단계 기준 2**(거부하는 쪽 — 거부→허용이 호환 완화) |
| 되돌릴 때 | 손검사 한 줄 |

## 근거와 공백

`W-04-01` §5-7 액션 표: 「**편성** \| 라인 ≥ 1 AND **배정 수량 ≥ 1** AND 출하 희망일 입력」.

그런데 **막는 곳이 어디에도 없습니다**:

| 자리 | 실측 |
|---|---|
| 계약 `ShipmentRequestLineCreate.allocatedQty` | `minimum`·`exclusiveMinimum` **키 없음** |
| 계약 `.requestedQty` | 같음(**키 없음**) |
| 물리 `shipment_request_line.allocated_qty` | `app.qty_t NOT NULL DEFAULT 0` — **`> 0` CHECK 없음** |
| 물리 `ck_shipment_request_qty` | `shipped ≤ allocated ≤ requested` 만 본다 |

⇒ **계약 가드도 DB 도 0 을 막지 않습니다. 서버 손검사가 «유일한 그물»입니다.**
(참고 — `requested_qty > 0` CHECK 는 baseline 에 있습니다. `allocated_qty` 만 없습니다.)

## ⇒ 우리가 정한 것

- **「≥ 1」을 정수 하한이 아니라 「0 은 안 된다」로 읽습니다.** 수량 칸이 `numeric(20,6)` 이라 정수 1 하한은 뜻이 없습니다(0.5 EA 배정이 막힐 이유가 없습니다).
- 라인마다 **`allocatedQty > 0`** 과 **`requestedQty > 0`** 을 400 `RANGE` 로 막습니다.
- `allocatedQty = requestedQty`(한계와 같은 값)는 **통과**합니다.
- ⛔ `lines` 의 `minItems: 1` 은 **계약 가드가 이미 막으므로** 서비스에서 다시 세지 않습니다.

## 📨 알려 드리는 것

1. **계약 `allocatedQty`·`requestedQty` 에 `exclusiveMinimum: 0` 을 달아 주십시오.** 그러면 계약에서 만든 클라이언트가 서버 왕복 전에 막을 수 있습니다.
2. 「≥ 1」이 **정수 1** 을 뜻하는 것이라면 알려 주십시오 — 그때는 `>= 1` 로 바꿉니다.
3. ⚠ 참고로 **물리에도 `allocated_qty > 0` CHECK 가 없습니다.** 데이터 모델 쪽에 함께 알려 주시면 좋겠습니다.
