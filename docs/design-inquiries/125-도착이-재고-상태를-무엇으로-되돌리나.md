# 125. 도착이 재고 상태를 무엇으로 되돌리는지 아무 문서도 적지 않았다 — 고정하면 보류 재고가 이동 한 번으로 가용이 된다

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 반출 라인의 상태를 그대로 되돌리는 보수적 선택이라 원장에 잘못된 상태가 남지 않는다. 뒤집으면 한 줄 완화 |
| 걸리는 오퍼레이션 | `POST /logistics/stock-transfers/{stockTransferId}:arrive` |
| 구현 상태 | **미구현**(I-13 PR ③ 예정) — 반출 전기(`IN_TRANSIT` 로 세우는 쪽)는 병합됐다(`main`) |
| 판정 | `coverage-100/README.md` §2 1단계 **가장자리**(출발이 `AVAILABLE` 이 아닌 호출에서만 갈린다) → 2단계 **기준 4**(값을 조용히 도출하지 않는 쪽) |
| 되돌릴 때 | 「`AVAILABLE` 로 고정하라」면 `transfer-posting.ts` 의 도착 끝점 한 줄(완화) · 「이동이 상태를 바꾸는 축을 세우라」면 계약 요청·응답에 재고 상태 칸 신설(스키마 축 추가) |

## 무엇이 문제인가

ⓐ 반출은 도착 창고의 **`IN_TRANSIT`** 차원에 잔액을 세운다 — 이미 병합된 코드가 그렇다(`src/logistics/stock-transfer/transfer-posting.ts:26,158-161`) · 시드 `INVENTORY_STATUS` 4값에 `IN_TRANSIT` 실재(psql 실측 2026-09-07).
ⓑ 도착이 그것을 **무엇으로 되돌리는지 계약이 침묵한다.** 원장 끝점 4칸(`to_warehouse_id`·`to_location_id`·`to_quality_status_code`·`to_inventory_status_code`)이 `StockTransferArrive`·`StockTransfer`·`StockTransferLine` **세 스키마 어디에도 없다**(전수 실측 · `contracts/logistics-01자재창고.json:14083,13973,14237`). ⇒ 화면이 이 값을 **볼 수도 고를 수도 없다**.
ⓒ 통합 계획서 초안은 **`AVAILABLE` 고정**이라 적었다 — 3관점 재검토(R-2)로 그 자리를 고쳤으나(`docs/coverage-100/plan-integration.md:325` 「⛔ ~~`AVAILABLE` 고정~~ — 고정하면 **보류 재고가 이동만으로 가용이 된다**(세탁)」) **그 판단의 근거가 계약이 아니라 구현 선례와 화면**이라 설계 회신이 필요하다.
ⓓ 그런데 **이미 구현된 두 전표가 정반대를 못 박았다** — 「⭐ 품질·재고 상태를 **바꾸지 않는다** — 적치는 옮길 뿐 판정하지 않는다. 바꾸면 잔액이 다른 차원으로 넘어가 「적치했더니 검사 대기가 정상이 됐다」가 된다」(`src/logistics/putaway/putaway-posting.ts:52-53`) · 「⭐ 도착 두 칸은 `from` 과 «같은 값»이다 — 이동에서 품질·재고 상태가 바뀌는 축이 계약에 없다」(`src/logistics/goods-issue/issue-posting.ts:196-198`).
ⓔ 화면은 **보류 LOT 이동을 정상 경로로 열어 두었다** — `M-01-10` §5-3 이 「보류 중인 LOT입니다. 이동은 별개로 기록됩니다 (**✓설계확정 결정 14**)」를 **경고 + 진행 가능**으로 적었다(`.design-reference/…/screens/01/M-01-10-재고이동불량반출.md:172-189`). ⇒ `ON_HOLD` 출발이 실제로 도달하는 형상이고, `AVAILABLE` 로 고정하면 **화면이 통과시킨 보류품을 서버가 이동 한 번으로 가용으로 세탁한다**.
ⓕ 같은 화면 §8 #5 는 「**Hold LOT 이동 허용 정책** — (U-C1). 판정 위치만 확정」으로 정책 자체를 **아직 미정(조정)** 으로 남겨 두었다(같은 파일 `:256-265`).

## 지금 서버는

- 반출 전기(병합됨)는 도착 끝점을 `{도착 창고, 라인 `to_location_id`, 출발과 «같은» 품질 상태, `IN_TRANSIT`}` 으로 쓴다 — 품질 상태는 손대지 않는다.
- 도착 전기(미구현)의 계획은 **반출 원장 라인을 되읽어** `from` 4칸을 그대로 복제하고(`stock_transfer_line.issue_transaction_line_id` → `inventory_transaction_line.to_*`), `to.inventoryStatusCode` 를 **그 반출 라인의 `from_inventory_status_code`** 로 되돌리는 것이다. 품질 상태는 그대로 둔다.
- 흔한 경우(`AVAILABLE` 출발)의 결과는 초안과 **같다** — 갈리는 것은 `ON_HOLD`·`BLOCKED` 출발뿐이다.
- 보류 LOT 을 **막지 않는다** — 출고는 `assertLotNotBlocked` 를 부르는데 이동은 부르지 않는다(근거: 위 ⓔ).

⇒ **묻는 것**: 재고 이동이 재고 상태를 바꾸는가 — 「바꾸지 않는다(출발 상태로 되돌린다)」가 맞는가, 아니면 도착을 `AVAILABLE` 로 고정하는 것이 의도인가. 후자라면 **보류·차단 재고를 이동으로 해제하는 것이 정상 업무인지** 함께 답해야 한다.
