# 092. 고장 보고 성공과 알림·사진 미지원

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/maintenance/breakdowns` · 고장 조회 |
| 구현 상태 | 의사/본문 저장 예정. 알림 발생0·Zalo전송0·고장 첨부는I-34 건너뜀 |
| 판정 | 0단계 I-28 발생기 제외·I-34 바이너리 제외·고정 계약 default true |
| 되돌릴 때 | 이벤트 정본/발생 규약 및 첨부 판별자/저장소 확정 뒤 별도 범위로 연결. 현재 보고 원문은 보존 |

BreakdownCreate.notifyAssignee는 생략=true이고 false는 보존한다. 계약 `app-공통.json:2004`는 고장POST 뒤라는 사건명별 발생지점을 적지만 eventCode 문자열은 미정이다(099). 발생지점이 전혀 없다고 설명하거나 임의 코드/수신자/장비담당역할로 발생기를 만들지 않는다.

고장첨부POST는 I-34 배정·건너뜀이고 CD-ATTACHMENT-TARGET-TYPE에 고장값이 없다. 현재 attachments=[]는 지원 경계이며 모든 실제 사진을 읽었다는 뜻이 아니다. 임의 payload/targetType/storageKey로 연결하지 않는다.

**요청: 현장 화면에서 본문 접수201과 알림·사진 미지원 상태를 분리해 안내해 달라.** 지금 범위에서 ‘연결되면 사진/알림이 전송된다’는 약속은 성립하지 않는다. 본문은 접수됐으며 급한 건 직접 연락 안내가 필요하다. 발생/첨부 구현은 별도 확정된 범위를 요청한다.

공용 배포 인계: `common/http/cors.ts:38` allowedHeaders에 X-Worker-No가 없다. 해결 전 현장 호출은 동일오리진/프록시 조건이며 교차오리진 preflight 보완은 공용담당의 별도 작업이다. 단말만의 인증 미지원은054를 따른다. B가 공용 auth/CORS를 임의 수정하지 않는다.

흔적: I-30 R-12·§7·E-B12. 보고 성공 뒤 notification/event/integration/downtime/첨부 생성0, notify생략/false 보존을 단언한다. 화면전체 완료와8 API 구현완료를 구분한다.
