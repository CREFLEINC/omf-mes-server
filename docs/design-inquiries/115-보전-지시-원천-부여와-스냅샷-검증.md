# 115. 보전 지시 원천·유효 부여·스냅샷 검증

계약은 한 요청에 한 대상, 그 대상의 복수 촉발을 받는다. EQUIPMENT 항목은 전체 마스터가 아니라 **현재 유효 부여층**의 항목이다. 실제 InspectionAssignmentService는 직접부여 우선, 없으면 조상 중 처음 부여가 있는 층을 사용한다. 그 층의 부여가 비활성이라고 상위로 우회하지 않는다. MOLD는 마스터 없는 자유 항목 이름이다.

**확인 요청:** 이미 발행된 고장/점검 원천을 다른 지시에 다시 연결하는 정상 후속작업이 있는가? 제공한 PM 도래 축·누계 snapshot이 저장 직전값과 다르면 거부할지, 명시적으로 최신값으로 대체할지 고정 계약에 정해 달라. EQUIPMENT PM_DUE의 별도 도래 계산 원천이 있다면 알려 달라.

고정 이후 W-05-02의 최신 snapshot 대체 문구를 a6a87e1 계약에 소급 적용하지 않는다. 제공값 mismatch는422 INVALID, 생략은NULL이며 조용한 최신값 대체0. MOLD BOTH의 대표축은 기존 문의4/O-5의 잠정 선례이지 실제 먼저 도달한 시각을 입증한 결과가 아니다. 설비 PM에 툴 샷 기준을 강제하지 않는다.

열린 MOLD PM이 있으면 같은 target 잠금 안에서422, 설비 원천 재선택도현재후보 제외 원칙에 따라422. 단 물리 N:M은 보존해 trigger의 source 전역UNIQUE를 신설하지 않는다. 취소 지시도 발행 흔적이며 고장 직접 FK+다형 trigger UNION·복수단수ID NULL은 **095**와 같다.

부여 검증은 현재 writer와 직렬화한다. E/M NO KEY UPDATE·후보 조상 전부(빈 중간층 포함) 정렬 SHARE·재해석·경로 변경시전체tx유한재시도로 낡은 집합 승인을 막는다. 실제부여교체·부모재연결·예비품FK의 잠금 근거는 I-31 R6/096이며 새로운 업무 제한의 근거로 쓰지 않는다.

소비자 인수: 현재 maintenance-order의 전체 항목 lookup을 effective 목록과 대조, 예방 baseDate 조건부필수·원천선택 실패 입력보존·재조회. 실제 API 성공과 후보화면 인수를 분리한다. E-O03/04/15/16 및 source/trigger 다형 ID·취소 N:M 회귀에 연결한다.
