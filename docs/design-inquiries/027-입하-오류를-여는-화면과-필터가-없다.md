# 27. 입하 오류를 기록한 뒤 담당자가 그것을 여는 화면·필터가 없다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /logistics/inbound-receipt-lines/{id}/variances` · `GET …/{id}/variances` · `GET /logistics/inbound-receipts`(목록 10필터) |
| 구현 상태 | **구현함(계약대로)** — 차이 등록·조회를 열고, 목록 필터는 계약의 10개만 |
| 판정 | `coverage-100/README.md` §2 1단계 **본길**(오류를 기록한 모든 입하가 걸린다) → 서버 갈림길이 아니라 **착지 화면이 없는 결손**이라 문의. 025(P/O)의 입하판 |
| 되돌릴 때 | 화면이 서면 서버는 그대로다. 필터가 필요하면 `GET /logistics/inbound-receipts` 에 차이 축 하나(계약 추가)를 더한다 |

## 무엇이 문제인가

`M-01-06`(입하 오류 등록, 모바일) §5-3 이 「**반품·폐기 판단은 관리웹에서 담당자가 한다**」고 적었다. 그런데 그 담당자가 오류를 **찾아 들어갈 자리가 없다** —

| 자리 | 실측 |
|---|---|
| `GET /logistics/inbound-receipts` 목록 10필터 | `statusCode`·`supplierId`·`receiptDateFrom/To`·`supplierLotMissing`·`labelIssued`·`q` … — **차이(variance) 축이 0** |
| `GET …/inbound-receipt-lines/{id}/variances` | **라인 id 를 아는 자에게만** 열린다 — 어느 라인에 오류가 있는지 알 길이 앞에 없다 |
| `W-01-05`(공급사 반품 처리 — 「반품으로 넘긴다」의 착지) | LOT·재고 축이고 `inbound_variance` 를 **한 번도 안 본다**(전문 grep 0건) |
| `W-01-10`(정상품 입하 처리) · `M-01-06`(입하 오류 등록) | `W-01-10` 은 입고 확정 축 · `M-01-06` §3 은 쓰기 폼이라 오류 «목록» 구획이 없다 |
| `W-01-13`(물류 문서 진행현황) | 9종 전표의 상태만 — 라인 차이는 대상이 아니다 |

⇒ 오류를 등록하면 `inbound_variance` 에 행이 서지만 **관리웹 어디에도 떠오르지 않는다.** 「담당자가 판단한다」의 착지가 없다.

## 지금 서버는

- 차이 등록을 계약대로 연다: `varianceTypeCode`(시드 3값) 검증 · `reasonCode` 는 있을 때만 검증(계약 「⛔ 선택이다」) · `varianceQty` 상한 없음(무발주 라인엔 비교 축이 없다) · **`received_qty`·라인 상태·LOT·원장은 건드리지 않는다**(기록 전용). 없는 라인은 404(계약 미선언).
- 403 권한은 `M-01-06`(계약 description 이 그 화면을 유일한 소유자로 적었다).
- 목록 필터에 차이 축을 **더하지 않았다** — 계약 밖 파라미터를 지어내지 않는다(§2 2단계 기준 4).

## 요청

1. **입하 오류를 관리웹에서 어느 화면이 보이는지** 정해 주십시오 — `W-01-10` 에 「차이 있음」 배지·필터를 더하는가, `W-01-05`(반품) 가 차이를 읽는가, 별도 목록인가, `W-01-13` 에 얹는가.
2. 그에 맞춰 **서버 조회 축**을 알려 주십시오 — `GET /logistics/inbound-receipts?hasVariance=` 류의 헤더 목록 필터 하나면 충분한지, 차이 자체를 가로질러 보는 `GET /logistics/inbound-variances` 가 필요한지.
3. 곁들여: `InboundVariance.approvalRequestId` 가 응답에 있는데 **채우는 경로가 계약에 0건**입니다(반품·폐기 승인과 잇는 자리로 보입니다). 그 흐름이 1차인지 알려 주십시오.

우리 권고안(회신이 없으면 이대로 갈 값): **등록·조회는 열어 두고 필터는 기다린다.** 조회 축 추가는 호환 확장이라 나중에 싸게 붙습니다. 1차 배포 노트에 「입하 오류는 API 로 기록되지만 관리웹 목록에 뜨지 않는다」를 남깁니다.
