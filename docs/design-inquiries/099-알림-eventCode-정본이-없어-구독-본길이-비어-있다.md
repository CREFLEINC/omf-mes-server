# 099. 알림 사건명은 있지만 eventCode 정본이 없다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | GET `/app/notification-events` · GET/PUT `/app/notification-subscriptions` |
| 구현 상태 | **보류3건 확정(I-28 R-1). 핸들러·운영 코드·시드 미생성** |
| 판정 | README §2 0단계 계약 확인→1단계 본길: 모든 정상 호출의 이벤트 식별을 결정하는 코드에 계약도 침묵하므로 해당 operation 건너뜀 |
| 되돌릴 때 | 정본 코드↔이름 목록 확인→계획 R 갱신→조건부 마이그/GET/PUT 구현. 발생기 완료를 기다릴 필요는 없음 |

## 확인된 근거

- 고정 계약 `a6a87e1`, `contracts/app-공통.json:1980,2004,5053`: 계약이 이벤트 목록을 소유한다. description의 빈 발생표와 x-internal-note의 고장·적정타수·P/O변경·연계실패·결재도착 사건명은 공존하지만 **코드 문자열 미확정**이 명시돼 있다.
- `prisma/schema.prisma:3848`: notification_event는 aggregate·occurred_at을 가진 발생 이력이고 event_name이 없다. 전용 DB의 발생/구독/알림 각각0행은 정본 정의0개라는 뜻이 아니다.
- 구독 저장행 SELECT 자체는 가능하다. 다만 정본 이벤트 선택→미설정 개별 GET→If-Match 최초 PUT의 정상 경로를 만들 식별 원천이 없다.

## 지금 선택한 경계와 요청

저장 알림 GET2·읽음2·eventCode를 받지 않는 수신자 preview1은 진행한다. 빈 카탈로그를 성공으로 돌리거나 사건명을 영문 코드로 번역하지 않는다. 임의 문자열마다 설정을 만들거나 PUT 전건400 껍데기를 커버리지로 세지 않는다.

**확인 요청: 권한 있는 정본의 eventCode↔eventName 목록과 그 소유 위치를 알려 달라.** 이것이 최소 해소 조건이다. 미설정 토큰은100의 가장자리 판정으로 처리하며 별도 회신을 필수로 기다리지 않는다. 검교정 배치·임박 일수·전화번호·Zalo전송기·발생 훅은 지금 해소 조건이 아니다.

화면 제한: W-CO-03 제목/유형 선택, W-CO-11 이벤트 선택/설정은 아직 완결되지 않는다. 알림 발생과 Zalo 전송도 만들지 않는다. `I-28.md` §3·R-1 및 독립 리뷰3개가 근거다. 설계 저장소에는 직접 글을 쓰지 않았고 계약 사본도 갱신하지 않았다.
