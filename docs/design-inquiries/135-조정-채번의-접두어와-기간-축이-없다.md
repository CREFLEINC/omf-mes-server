# 135. 조정 채번의 접두어·규칙이 없고, 기간 축으로 쓸 날짜가 등록 본문에 하나도 없다 — 하노이 새벽 등록은 «전날» 번호를 받는다

> ⭐ 새 문의를 세우는 대신 **기존 문의 14**(채번 규칙 없는 표)의 표에 `inventory_adjustment_no` 한 행을 더하는 것으로 갈음할 수 있다. 다만 조정에는 그 표의 다른 행에 없는 물음이 하나 더 있다 — **등록 본문에 날짜가 0개**다.

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 규칙이 `app.numbering_rule` 에 등재되면 코드 변경 0 이고, 이미 나간 번호는 그대로 둔다 |
| 걸리는 오퍼레이션 | `POST /inventory/adjustments` |
| 구현 상태 | **미구현** — 등록이 아직 없고 `DEFAULT_PREFIX` 에 조정 항목이 없다(`src/core/numbering/numbering.service.ts:9-38` 실측 · 조정 0건) |
| 판정 | `coverage-100/README.md` §2 **1단계 가장자리** → 2단계 **기준 5**(개념을 안 늘리는 쪽 — 저장소 기본 패턴을 따르고 새 규칙을 만들지 않는다). 0단계 선례는 `APPROVAL_REQUEST`(`AP`)·`MATERIAL_RETURN`(`MR`) — 둘 다 규칙 미등재인 채 기본 패턴으로 섰다 |
| 되돌릴 때 | 접두어·패턴이 정해지면 `app.numbering_rule` 에 **행 하나를 넣는다**(코드 변경 0 — 규칙이 등재되면 `DEFAULT_PREFIX` 표를 안 본다) |

## 무엇이 문제인가

**ⓐ 규칙 표에 조정이 없다.**
`app.numbering_rule` 오늘 실측 6행 — `GOODS_RECEIPT`·`MATERIAL_ISSUE_REQUEST`·`PRODUCTION_RESULT`·`PUTAWAY_TASK`·`STOCK_TRANSFER`·`WORK_ORDER`. `INVENTORY_ADJUSTMENT` 는 **없다**. 코드 쪽 기본 접두어 표(`numbering.service.ts:9-38`)에도 조정이 없다 — 그 표의 머리 주석은 ⌜없는 유형은 던진다 — **접두어를 지어내지 않는다**⌝ 다.

**ⓑ 계약 example 과 저장소 기본 패턴의 형식이 다르다.**
계약 `InventoryAdjustment.inventoryAdjustmentNo` 의 example 은 `IA-2026-000031`(`contracts/logistics-01자재창고.json:9750-9755`) — 연도 + 6자리 일련이다. 저장소의 다른 미등재 유형은 전부 `{PREFIX}-{YYYYMMDD}-{SEQ4}` 로 섰다(`GI`·`PP`·`SR`·`MC`·`MR` — `numbering.service.ts` 주석). **example 은 형식을 확정한 것이 아니라 자리채움**이라는 것이 지금까지의 판정인데, 조정도 같은지 확인이 필요하다.

**ⓒ ⭐ 기간 리셋 키로 쓸 날짜가 등록 본문에 하나도 없다.**
`InventoryAdjustmentCreate` 의 프로퍼티는 `inventoryCountId`·`reasonCode`·`sendToErp`·`lines` **넷**뿐이다(`contracts/logistics-01자재창고.json:9810-9852`). `businessDate` 도 `occurredAt` 도 등록일도 **없다**. 그래서 기간 키를 **서버 시각(UTC)의 오늘**로 잡을 수밖에 없고, 현장이 하노이(UTC+7)라 **00:00–07:00 에 등록한 조정은 번호에 «전날» 날짜가 박힌다**. `approval_request` 채번(`AP`)이 이미 같은 자리에 서 있다.
⚠ 이 표는 `business_date` 를 싣지 않으므로 공유계약 C-8 의 대상 3표가 아니다 — 원장에 실리는 `businessDate` 는 `:post` 의 `PostRequest` 가 따로 받는다. 여기서 갈리는 것은 **번호에 찍히는 날짜**뿐이다.

## 지금 서버는

- **아직 없다.** 등록이 미구현이라 조정 번호를 만드는 코드가 0 이다.
- 계획된 동작은 `DEFAULT_PREFIX` 에 `INVENTORY_ADJUSTMENT: 'IA'` **한 줄**을 더해 `IA-{YYYYMMDD}-{SEQ4}` 로 채번하고, 기간 키는 **서버 UTC 오늘**, `plantId` 는 `null`(헤더에 공장 축이 없다 — 문의 133)로 두는 것이다. 접두어 `IA` 는 계약 example 에서 땄다.
- 채번은 트랜잭션 **밖**에서 하므로 등록이 실패하면 그 번호는 결번으로 남는다(형제 전표와 같다).

⇒ **묻는 것**: 조정 번호의 **접두어와 패턴**이 `IA-{YYYYMMDD}-{SEQ4}` 로 맞는가(계약 example `IA-2026-000031` 이 형식 확정이 아닌가) · 기간 리셋 키를 **서버 UTC 날짜**로 두어 하노이 새벽 등록이 전날 번호를 받는 것을 받아들이는가.

**기존 문의에 더할 것**: 문의 **14**(채번 규칙 없는 표)의 표에 `inventory_adjustment_no` 한 행 — ⌜`app.numbering_rule` 미등재 · 계약 example `IA-2026-000031` 은 형식만 · 기간 축이 될 날짜가 등록 본문에 0개라 서버 UTC 오늘로 잡는다⌝.
