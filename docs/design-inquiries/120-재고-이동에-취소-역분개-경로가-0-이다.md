# 120. 재고 이동에 취소·역분개 경로가 0 이다 — 원장을 «두 번» 남기는데 되돌릴 오퍼레이션이 없다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /logistics/stock-transfers` · `POST …/{stockTransferId}:arrive` · `document-progress` 4건(`GET` 목록·상세 · `:request-cancel` · `:cancel`) |
| 구현 상태 | **반출 등록은 구현·병합함**(`main` · 원장 1단째까지) · **`:arrive` 는 미구현**(I-13 PR ③) · 취소는 **짓지 않았다** — `cancelable:false` 를 그대로 두고 `transitions.ts` 에 취소 두 액션을 안 붙였다 |
| 판정 | `coverage-100/README.md` §2 **0단계**(선례 — 계약 원문이 「취소 실행 경로가 있는 것만 닫았다」로 «의도»를 말한다) |
| 되돌릴 때 | 취소 유형을 열면 ⓐ 계약 enum 3값 → 4값 ⓑ `document-type-registry.ts` 한 줄(`cancelable:true` + `cancelledStatus`) ⓒ `transitions.ts` 에 취소 두 액션 ⓓ 역분개 두 벌(반출·도착) — **원장 축이라 코어 PR** |

## 무엇이 문제인가

ⓐ 취소 실행 경로의 `documentTypeCode` 는 **3값**이고, 그 값 목록 자체가 답이라고 계약이 적었다 — 「취소할 수 있는 문서 유형만 받는다 — 입하·입고·출고 3종. ⛔ 조회 축(DocumentProgress)의 9종 중 취소 실행 경로가 있는 것만 닫았다 — 값 목록 자체가 「어느 유형이 취소를 받는가」를 말한다(공유계약 A-10 보강 · omf-mes#352)」(`contracts/logistics-01자재창고.json:6771` `parameters[0].description` · enum `["INBOUND_RECEIPT","GOODS_RECEIPT","GOODS_ISSUE"]`). 같은 계약의 조회 축 enum 9값에는 `STOCK_TRANSFER` 가 **있다**.
ⓑ 그런데 이 6건은 한 문서에 원장을 **두 번** 쌓는다 — 반출에서 `{출발 위치} → {도착 창고·계획 도착 위치·IN_TRANSIT}`, 도착에서 `{IN_TRANSIT} → {최종 도착 위치}`(`docs/coverage-100/slices/I-13.md` §3-0·§3-5). 원장 헤더는 `block_ledger_header_mutation` 이 UPDATE·DELETE 를 막으므로 **지워서 되돌릴 수 없다**.
ⓒ 화면 `M-01-10` §8 은 미결 6건에 「이동 중 분실·손상」만 적고 **오등록 취소를 한 줄도 말하지 않는다**(`.design-reference/omf-mes/design/wiki/screens/01/M-01-10-재고이동불량반출.md:256-265`). §5-6 액션 7종에도 취소가 없다.
ⓓ 취소 실행 계약 원문은 「전기된 문서는 원장에 역트랜잭션을 만든다」로 역분개를 **취소 경로 안에서만** 규정한다(`contracts/logistics-01자재창고.json:6771` `post.description`). 이동은 그 경로에 없으므로 역분개를 부를 주체가 없다.
ⓔ 코어에는 역처리 도구가 이미 있다 — 역처리 번호 접미 `-R` · 멱등키 접두 `REVERSAL:`(`src/core/inventory-posting/reversal.ts:9,11`). **쓸 자리만 없다.**

## 지금 서버는

- `document-type-registry.ts:68-71` 의 `STOCK_TRANSFER` 는 `cancelable:false` · `cancelledStatus:null` 이다 — `:cancel` 을 이 유형으로 부르면 **경로 파라미터 enum 에서 400** 이고 서버 코드까지 오지 않는다.
- `transitions.ts` 에 `logistics.stock_transfer.status_code` 축을 신설하면서 전이를 **하나**만 넣는다(`transfer-arrive` : `REGISTERED → POSTED`). `DOCUMENT_CANCEL_ACTIONS` 를 붙이지 않는다(`I-13.md` §8-2).
- 그래서 잘못 반출한 물건은 **재고 조정(I-14)** 으로만 잔액을 되돌릴 수 있고, 그때 원 이동 전표는 `REGISTERED`/`POSTED` 인 채 남아 진행 조회에 계속 뜬다.

⇒ **묻는 것**: `STOCK_TRANSFER` 를 취소 실행 축(enum 4값)에 넣어 반출·도착 두 원장의 역분개를 세울 것인가, 아니면 **「이동은 취소하지 않는다 — 재고 조정으로 되돌린다」를 규약으로 못 박을 것인가**(그러면 오등록 전표가 남는 것이 정상이라는 뜻이 된다).
