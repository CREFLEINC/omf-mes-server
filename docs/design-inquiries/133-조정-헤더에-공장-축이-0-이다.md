# 133. 조정 헤더에 공장 축이 0 이라 원장 헤더의 `plant_id` 를 라인 위치에서 역산한다 — 두 공장에 걸친 조정은 400 이다

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 가장자리(두 공장에 걸친 조정)이고 거부하는 쪽이라 완화가 싸다 |
| 걸리는 오퍼레이션 | `POST /inventory/adjustments` · `PUT /inventory/adjustments/{id}/lines` · `POST /inventory/adjustments/{id}:post` · `GET /inventory/adjustments` |
| 구현 상태 | **미구현** — 조회 3건만 병합됐다(`main`). 등록·치환·전기는 아직 없다 |
| 판정 | `coverage-100/README.md` §2 **1단계 가장자리**(라인이 두 공장에 걸칠 때만 갈린다) → 2단계 **기준 2**(거부하는 쪽 — 서버가 하나를 고르면 원장 헤더가 잔액과 다른 공장을 적고, 그것이 조용히 남는다) |
| 되돌릴 때 | 「헤더에 공장·창고 축을 둔다」면 마이그 2칸 + 계약 스키마 2칸 + 화면 입력 자리. 「첫 라인의 공장을 쓴다」면 400 분기 하나를 지운다 |

## 무엇이 문제인가

**ⓐ 조정 헤더에 조직 축이 하나도 없다.**
`inventory.inventory_adjustment` 는 12칸인데 `plant_id`·`warehouse_id`·`business_unit_id` 가 **0** 이다 — `inventory_adjustment_id`·`inventory_adjustment_no`·`inventory_count_id`·`reason_code`·`approval_request_id`·`status_code`·`adjusted_at`·감사 4칸·`version_no`(`prisma/schema.prisma:464-482`). 계약 `InventoryAdjustment` 8칸에도 없다(`contracts/logistics-01자재창고.json:9733-9809`). 형제 전표는 다 갖는다 — `goods_issue` 는 `source_warehouse_id` 를, `inventory_count` 는 `warehouse_id` 를 갖는다.

**ⓑ 그런데 원장 헤더는 공장을 NOT NULL 로 요구한다.**
`inventory.inventory_transaction.plant_id` 는 **NOT NULL** 이다(DB `information_schema.columns` 실측). 전기하려면 값이 반드시 필요하다.

**ⓒ 고를 여지를 두면 원장이 거짓을 적는다.**
코어는 잔액의 조직 3축(법인·사업부·공장)을 **엔드포인트 창고에서 다시 푼다**(`src/core/inventory-posting/inventory-posting.service.ts:305-312`). 그래서 원장 헤더의 `plant_id` 와 라인 잔액의 공장이 갈리면 **헤더가 잔액과 다른 공장을 적은 채 남는다**. 「첫 라인의 공장을 쓴다」로 고르면 그 어긋남이 조용히 생긴다.

**ⓓ 계약·화면 어디에도 「조정은 한 공장 안에서만」이라는 문장이 없다.**
화면이 여러 공장을 한 전표에 담게 그리지도 않았다 — 실사 경유는 실사가 창고 하나라 자연히 한 공장이고(`W-01-04-재고실사.md:10` ⌜실사 개시(창고·유형·계획일 입력 …)⌝), 직접 등록 라인 표에는 **창고·공장 열이 아예 없다**(`W-01-12-재고조정.md:46` — 위치·품목·LOT·장부·실물·차이·사유). 그러나 「그리지 않았다」는 「금한다」가 아니다.
목록 질의에도 공장·창고 축이 **없어** 화면이 공장별로 조정을 찾을 길도 없다.

## 지금 서버는

- **아직 없다.** 등록·치환·전기가 미구현이다.
- 계획된 동작은 이렇다 — 라인의 `location_id → warehouse.plant_id` 로 공장을 역산하고, **라인이 두 공장에 걸치면 400 `INVALID`**(field 는 처음 어긋난 라인 · 등록은 `lines[i].locationId`, 치환은 본문 칸 이름이 `items` 라 `items[i].locationId`).
- ⚠ **400 은 공장 축만 본다.** 사업부·법인은 창고가 각자 알고 코어가 창고별로 다시 풀므로, 한 조정이 두 사업부에 걸쳐도 잔액은 옳다 — 거기까지 막지 않는다.

⇒ **묻는 것**: 조정 헤더에 **창고·공장 축을 둘 것인가**, 아니면 「조정은 한 공장 안에서만」을 계약이 명시할 것인가(전자면 목록 질의에도 그 축을 열 것인지 함께).

「알려둘 것」으로 함께 보내는 것(문의 아님): 조정 목록 질의(`GET /inventory/adjustments`)에 **`q`(번호 검색)·창고·품목·LOT 축이 0** 이다 — 형제 출고 목록은 `q` 를 갖는다. 화면이 조정 번호로 찾을 길이 없다.
