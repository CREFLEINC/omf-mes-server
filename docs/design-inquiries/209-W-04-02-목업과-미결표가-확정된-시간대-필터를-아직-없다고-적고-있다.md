# 209. `W-04-02` 의 **목업과 미결 표가 «확정된» 시간대 필터를 아직 「없다」고 적고 있다** — 같은 문서 안에서 갈렸다

> **구분: 통보**(회신을 기다리지 않는다 — `coverage-100/README.md` §2 1-1단계)

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /logistics/shipment-requests` · `GET /logistics/shipment-requests/summary`(**둘 다 I-22 · 구현 예정**) |
| 구현 상태 | **서버는 그대로 만든다** — 계약·물리·화면 §5-2 가 모두 확정 쪽이다. 이 통보는 **화면 문서 두 줄을 고쳐 달라**는 것이다 |
| 판정 | §2 **0단계** — 같은 문서의 **§5-2 가 2026-08-31 에 확정**했고 날짜가 가장 새것이다. 고를 것이 없다 |
| 발견 경위 | I-22 3관점 재수립(UI/UX 관점) · `slices/I-22.md` §9-4 |

## 무엇이 문제인가

`W-04-02`(출하예정목록) **한 문서 안에서 시간대 필터의 상태가 갈린다.**

| 자리 | 문장 | 날짜 |
|---|---|---|
| §개요 `:6` | 「시간대 슬롯 필터는 ✅ **2026-08-31 고정 3구간(오전·오후·야간)으로 확정해 제공한다**(§5-2)」 | **2026-08-31** |
| `:11` | 「✅ 인벤토리 근거가 … **확정됐다**」 | 〃 |
| **§5-2 `:103`** | 「✅ **시간대 슬롯 필터 — 고정 3구간으로 확정**」 + 「필터는 `GET /logistics/shipment-requests?timeSlotCode=`(공통코드 `SHIPMENT_TIME_SLOT`)로 제공한다 — `MORNING`·`AFTERNOON`·`NIGHT`」 | 〃 |
| ⛔ **목업 `:41`** | 「ⓘ **시간대 필터는 저장 자리가 없어 제공하지 않습니다**」 | **낡음** |
| ⛔ **미결 표 `:173`** | 「시간대 필터 ⏳ **형태 결정 후 둔다**(§5-2 — **사람 결정 대기**)」 | **낡음** |

⇒ 확정을 적은 자리가 셋, **확정 «전»을 적은 자리가 둘**이다.

## 서버·계약·물리는 이미 확정 쪽이다 (실측)

| 축 | 실측 |
|---|---|
| 계약 질의 칸 | `timeSlotCode` 가 **두 오퍼레이션**에 실재 — `GET /logistics/shipment-requests` · `…/summary` |
| 물리 칸 | **`logistics.shipment_request.ship_time_slot_code`**(`schema.prisma:1345` · 마이그 `20260901040000` 이 세웠다) |
| 형제 화면 | `W-04-01` `:158` 「`W-04-02` 시간대 필터 — ✅ `timeSlotCode` 쿼리 파라미터로 **가능**」 |

⇒ **저장 자리도 있고 질의 칸도 있다.** 목업의 「저장 자리가 없어」는 **오늘 사실이 아니다.**

## ⚠ 왜 알리는가 — 이 두 줄이 «클라이언트를 멈춘다»

화면 문서는 **클라이언트 팀의 구현 정본**이다. 목업 안에 회색 안내문으로 「**제공하지 않습니다**」가 박혀 있고 미결 표가 「**사람 결정 대기**」라고 적혀 있으면, **§5-2 를 안 열어 본 사람은 그 필터를 만들지 않는다.**

⛔ 그러면 **서버가 내는 질의 칸을 아무도 안 부르는 상태**가 된다 — 계약·물리·서버가 다 서 있는데 화면만 비는 자리다.

## ⇒ 요청

**두 줄을 §5-2 에 맞춰 주십시오.**

- `:41` 목업 ⓘ — 「시간대 필터는 저장 자리가 없어 제공하지 않습니다」 → **드롭다운(전체·오전·오후·야간)** 으로
- `:173` 미결 표 — 「⏳ 형태 결정 후 둔다 · 사람 결정 대기」 → **✅ 2026-08-31 확정**으로

⛔ **서버는 이 회신을 기다리지 않는다** — I-22 가 `timeSlotCode` 를 계약대로 구현한다.
