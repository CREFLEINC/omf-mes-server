# 205. **부분 배정 작업지시가 「피킹중 ⛔」 배지를 못 단다** — 상시 구조인데 차단 사유가 목록에서 사라진다

**구분: 통보**(회신을 기다리지 않는다) · ⭐ **통보 203 과 같은 축(`shipmentProgressCode`)의 «다른» 함정입니다**

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /logistics/shipment-requests`(+`/{id}`) — `shipmentProgressCode` |
| 구현 상태 | **구현 예정(I-22 PR ③)** — **계약 문자 그대로** 구현하고 이 사실을 알린다 |
| 판정 | §2 **1단계 본길** → 계약이 식을 «명시»해 0단계에서 닫힘 ⇒ 그대로 두고 **통보** |
| 되돌릴 때 | `PICKING` 의 조건에서 `A = R` 을 빼면 판정 함수 한 줄 |

## 계약 식

> `PICKING` = **배정 합이 요청 합과 같고**(A = R) 피킹 합이 배정 합보다 작다(P < A)

## ⛔ 부분 배정은 그 조건을 못 만족합니다

`W-04-01` §5-1 이 못박았습니다 — 「⚠ **부분 배정이 정상이다** — 가용이 모자라면 배정을 줄이고 나머지는 다음 작업지시로 간다. 화면이 그것을 막지 않는다.」

그런 건(`A < R`)은 **`A = R` 이 영영 거짓**이라 `PICKING` 을 지날 수 없습니다.

⚠ 다만 **「영영 `PARTIALLY_ALLOCATED` 에 머문다」는 아닙니다** — `PICKED`(`P = A ∧ S = 0`)는 `A = R` 을 요구하지 않으므로 피킹을 다 끝내면 「뒤가 이긴다」로 `PICKED` 가 덮습니다.
**갇히는 구간은 「부분 배정 + 피킹 «진행 중»(`0 < P < A`)」 하나**입니다.

## ⇒ 그런데 그 한 구간이 화면을 막습니다

- ⭕ **출하 확정은 안 막힙니다.** 진입 필터를 계약이 수량 축으로 못박았기 때문입니다 — `pickingCompleteOnly` 「⭐ **`W-04-04` 출하 처리의 진입 필터다** — 출하는 이 화면이 만들므로 `/logistics/shipments` 로는 진입할 수 없다」.
- ⛔ **막히는 것은 「차단 이유 배지」입니다.** `W-04-04` §5-4: 「⚠ **막힌 이유를 목록에서 보인다** — 「검사대기 ⛔」·「피킹중 ⛔」 … ⭐ **배지의 원천을 못박는다** — 「피킹중」은 `ShipmentRequest.shipmentProgressCode` = **`PICKING`** 이다.」
  §3 목업이 실제로 `● SR-…0461 A사 **피킹중 ⛔**` 를 그립니다.

⇒ 부분 배정 + 피킹 진행 중인 건은 **「부분 편성」으로 뜨고**, 운영자는 **`W-04-01`(배정을 더 넣는다)로 잘못 갑니다.** 실제로 해야 할 일은 `M-04-01` 로 가서 피킹을 끝내는 것입니다.
`W-04-02` §5-4 가 「뭉치면 **왜 막히는지 목록에서 알 수 없다**」로 막으려 한 실패의 다른 모양입니다.

## 📨 알려 드리는 것

**`PICKING` 의 조건에서 `A = R` 을 빼 주시거나**(= 「피킹 합이 배정 합보다 작고 배정 합이 0 보다 크다」), **`W-04-04` §5-4 의 배지 원천을 수량 축으로 바꿔 주십시오.**
부분 배정이 **상시 구조**라고 `W-04-01` §5-1 이 못박은 이상, 그 구간에서 차단 사유가 안 보이는 것은 화면 설계 의도와 어긋납니다.
