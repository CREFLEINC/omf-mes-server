# 62. 적치를 «누가» 했는지 남을 칸이 0 이다 — `X-Worker-No` 는 required 인데 담을 곳이 담당자 축뿐이다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /logistics/putaway-tasks/{putawayTaskId}:complete` · `…:complete-temporary` |
| 구현 상태 | **구현함(I-12 · 사번은 존재만 확인하고 버린다 · `assigned_worker_id` 에 쓰지 않는다)** |
| 판정 | `coverage-100/README.md` §2 1단계 가장자리 → 2단계 **기준 4**(헤더의 사번을 담당자 칸에 조용히 도출하지 않는다 · 057 과 같은 판정) |
| 되돌릴 때 | 완료자 칸(`completed_by_worker_id`)을 열면 마이그 한 줄 + 서비스 한 자리 · 「담당자 칸에 쓰라」면 서비스 한 자리(완화) |

## 무엇이 문제인가

ⓐ `X-Worker-No` 가 두 POST 다 **required** 인데 `putaway_task` 의 작업자 칸은 `assigned_worker_id`(«담당자» 축 · 목록 질의 `assignedWorkerId` 가 그 뜻으로 쓴다)뿐이라 **완료자를 담을 칸이 0** 이다. 조용히 `assigned_worker_id` 에 쓰면 담당자 축이 오염된다(담당자가 아닌 사람이 완료한 건이 담당자로 바뀐다).
ⓑ `M-01-05` §5-2-1 이 「임시 적치가 발생하면 관리자에게 **알린다**(승인 아님)」라 적었는데 알릴 자리가 없어 「목록에 남는 것」으로 물러났고(`M-01-05:166` `#90`), 그 목록도 «누가 뒀는지»를 못 보인다.
ⓒ `plan.md` §5 규칙 9 의 「받아서 버리는 사번」 자리가 여기서 둘 더 는다(I-11 의 셋에 이어).

## 지금 서버는

- 두 POST 는 `X-Worker-No` 가 없으면 400 `REQUIRED`, `mdm.worker.worker_no` 에 없으면 400 `INVALID`(`assertWorkerNo` 조회형 사본) 를 내고 값은 버린다.
- `completed_at` 은 본문 `occurredAt`(단말 시각)이고 `updated_by` 는 세션 `app_user` 다 — 「누가」는 로그인 사용자까지만 남는다.

⇒ **묻는 것**: 완료자 칸을 열 것인가(열면 `PutawayTask` 응답에도 실을지) · 열지 않으면 두 POST 의 `X-Worker-No` required 를 내릴 것인가.

「알려둘 것」으로 함께 보내는 것(문의 아님): 권장이 있는 지시에 `confirmedNoRule=true` 가 오면 서버는 **그 플래그를 읽지 않는다**(위치가 맞으면 통과 · 틀리면 400 `INVALID` field `actualLocationId`) · 400 코드 이름은 `INVALID`(`plan-api.md` 의 `RECOMMENDED_LOCATION_MISMATCH` 는 예약만).
