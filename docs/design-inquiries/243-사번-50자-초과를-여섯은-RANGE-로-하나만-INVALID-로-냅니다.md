# 243. 사번 **50자 초과**를 여섯 자리는 `RANGE` 로, **한 자리만 `INVALID`** 로 냅니다

**구분: 통보**(회신을 기다리지 않는다 — 오류 코드 하나의 불일치입니다. 어느 쪽으로 맞출지만 정해 주시면 바꿉니다)

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | **횡단** — `X-Worker-No` 헤더를 파싱하는 **7자리**(설비 고장·가동중지·점검·툴 사용·발행 보고·제품개체 등) |
| 구현 상태 | **그대로 간다** — 오늘 응답을 안 바꿨다 |
| 판정 | §2 **1-1단계 통보** — 계약에 근거가 없고(`maxLength: 50` 만 적혀 있다) **클라이언트가 보는 오류 코드**라 우리가 조용히 바꿀 자리가 아니다 |

## 무엇이 났나

계약은 `X-Worker-No` 에 **`maxLength: 50`** 만 적었다. 50자를 넘겼을 때 **어느 오류 코드로 거절할지**는 안 적었다.

서버는 그 판정을 **일곱 자리**에서 각각 한다(헤더를 컨텍스트로 조립하는 층이라 도메인마다 있다). 그중:

| 자리 | 50자 초과 시 |
|---|:-:|
| 가동중지 · 점검 · 툴 사용 · 발행 보고 · 발행 쓰기 · 제품개체 (**여섯**) | **`RANGE`** |
| **설비 고장**(`breakdown-write-context.ts:31`) | ⛔ **`INVALID`** |

⚠ **그리고 그 이탈이 e2e 로 «굳어» 있다** — `test/maintenance-breakdown.e2e-spec.ts:567` 이
`['W'.repeat(51), 'X-Worker-No', 'INVALID']` 로 단언한다. 반면 가동중지·점검 e2e 는 `'RANGE'` 로 단언한다.
즉 **우리 시험이 양쪽을 다 「맞다」고 잠가 두었다.**

## ⇒ 우리가 한 것

⛔ **조용히 맞추지 않았다.** 클라이언트가 오류 코드로 분기하고 있으면 한쪽 화면의 메시지가 바뀐다.

대신 **갈림 자체를 세게** 했다 — `worker-no.spec.ts` 가 일곱 자리를 훑어 「여섯은 `RANGE`,
하나는 `INVALID`」를 단언한다. ⛔ 누가 「고쳐서 초록으로」 만들면 **그 단언이 빨개진다** —
이 통보의 답이 오기 전에는 못 고친다는 뜻이다.

## 📨 알려 드리는 것

**어느 쪽으로 맞출까요?** 저희는 **`RANGE`** 로 봅니다 — 여섯 대 하나이고, 길이 위반의 뜻에 더 맞습니다.
정해 주시면 한 줄(+e2e 한 줄)로 바꿉니다.

⚠ 급하지 않습니다. 다만 **클라이언트가 `INVALID`/`RANGE` 로 분기하고 있는지**는 확인이 필요합니다.
