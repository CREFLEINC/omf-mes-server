# 088. 불량(`DEFECTIVE`) LOT 의 **재검 합격 확정**이 막힌다 — 「불량은 발신 전이 0」의 필연

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/quality/inspection-results/{inspectionResultId}:confirm` (I-19 PR ④) |
| 구현 상태 | 구현함(§2 0단계 선례 + 2단계 기준 1·2) — 대상 LOT 이 전이표의 `from` 밖이면 **400 `STATE_LOCKED`**. 트랜잭션 전체가 되돌아간다(결과는 `DRAFT` 로 남는다) |
| 판정 | 0단계 — I-19 §3-2 갈래표 ⑥ 이 같은 사건(`SCRAPPED` LOT)에 이미 **400 `STATE_LOCKED`** 를 적었다. 2단계 **기준 1**(아무 상태도 안 쓴다) · **기준 2**(거부하는 쪽 — 거부→허용은 호환 완화) |
| 되돌릴 때 | 전이를 열어 준다면 `transitions.ts` 의 `inspection-accepted.from` 에 `'DEFECTIVE'` 한 값(+ 전이 코드 지정), 그리고 이 오퍼레이션의 400 갈래 e2e 한 건을 뒤집는다. 서비스 코드 변경 **0** |

## 사실 — 계약 두 문장과 계약 세 칸이 서로 반대를 가리킨다

**막는 쪽**(I-19 §0-재수립 R-1 이 이 근거로 `from` 을 좁혔다)

- `contracts/quality-03품질.json:4472` — 「**불량(Hold)은 발신 전이가 0**」
- `contracts/shipment-04제품출하.json:431` — 「⭐ **이 경로에서만** 반영 목적의 **Hold → 정상** 전이가 허용된다(B-13)」 ⇒ 예외는 재고 재등록(I-23) **하나**
- 화면 정본 `W-03-02` §5-5 도식 — 「Hold 수신 C6·C8·C9 / **발신 (없음)**」

**여는 쪽**

- 계약 `InspectionResultCreate` 가 `inspectionRound`·`previousResultId`·`reinspectionReasonCode` **세 칸으로 재검 사슬을 정면으로 설계**했다.
- `W-01-01` §5-3 — 「재검사가 데이터에 설계돼 있다. 화면은 이전 회차를 읽기 전용으로 보여주고 **새 회차를 추가한다**」.
- `W-01-01` §5-1 — 1회차 **불합격이면 LOT 은 `DEFECTIVE`** 다(C6). 그 LOT 의 2회차가 합격이면 옮길 곳이 `NORMAL` 인데 그 발신이 0 이다.

⇒ **1회차 불합격 → 2회차 합격**이라는 재검의 대표 시나리오가 LOT 축에서 성립하지 않는다.

## 우리가 한 것

품질 축 코어(`LotQualityStatusService.moveWithin`)는 `from` 밖 LOT 을 **건너뛴다** — C14 가 W/O 의 생산LOT «전체»를 옮기므로 `SCRAPPED` 하나가 섞였다고 확정이 통째로 막히면 안 되기 때문이다(I-19 R-7). 그 필연으로 **단건 대상**에서도 「안 옮겨졌다」가 조용히 성공이 될 수 있다.

조용한 200 은 고르지 않았다 — 판정은 「합격」인데 LOT 은 「불량」으로 남아 **결정 10 「상태 이중 보유 없음」**(공유계약 B-8)이 깨지고, 화면은 합격 토스트를 본 뒤 LOT 상세에서 불량을 본다. ⇒ 단건 대상이 안 옮겨지면 **400 `STATE_LOCKED`** 로 거절하고 확정 자체를 되돌린다.

⚠ 그 결과 **`DEFECTIVE` LOT 은 재검 결과를 확정할 수 없다.** 오늘 우리 서버에서 그 요청은 400 이다.

## 요청 — 셋 중 하나로 확정해 달라

1. **재검 합격 전이를 연다** — `DEFECTIVE → NORMAL` 을 검사 확정에 허용하고 **전이 코드**를 지정해 달라. `C7`(재판정 합격)은 `W-03-02` §5-4 가 `:release` 전용으로 못박아 그대로 못 쓴다. `lot_status_event.transition_code` 는 NOT NULL 이라 값이 없으면 못 쓴다(문의 089 · 발행 예정 · 같은 자리).
2. **재검 합격은 `:confirm` 이 아니라 `POST /quality/lot-holds/{lotHoldId}:release`(C7)로 푸는 것이 정본이다** — 그렇다면 「검사 결과 확정」과 「보류 해제」가 **두 오퍼레이션**이라는 뜻이고, 화면(`W-01-01`)이 재검 확정 뒤 `W-03-02` 로 넘어가는 흐름을 그려 달라.
3. **「불량은 발신 0」을 그대로 유지한다** — 그러면 재검 사슬은 **검사 결과 표에만 남고 LOT 축은 1회차 판정에 고정**된다. 이때 우리가 400 을 내는 것이 맞는지(=화면이 「이 LOT 은 재검 확정을 할 수 없습니다」로 안내), 아니면 확정만 시키고 LOT 은 그대로 두는 200 이 맞는지 골라 달라.

⚠ 이 물음은 **미발행 · I-19 §9-2 후보 14**(확정 전이의 출발 상태를 계약이 안 적었다)의 «답이 온 뒤»가 아니라 **그 답의 일부**다 — 둘을 묶어 봐 달라.
