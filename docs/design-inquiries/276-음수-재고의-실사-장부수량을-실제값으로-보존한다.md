# 276. 음수 재고를 실사 장부수량에 어떻게 보존할지 결정이 필요하다

| 칸 | 내용 |
|---|---|
| **구분** | ⭐ **질의** — MES 핵심 재고 사실과 고비용 물리·계약 변경이 함께 걸린다 |
| 걸리는 오퍼레이션 | `POST /inventory/counts` · `GET /inventory/counts/{id}/lines` |
| 구현 상태 | 비음수 창고의 개시는 구현한다. 음수 묶음이 하나라도 있으면 400으로 전체 생성 거부(임시 fail-closed) |
| 판정 | 음수 재고를 누락·절단하면 장부 사실이 왜곡된다. 실제값을 보존하려면 공용 `qty_t`에서 해당 컬럼을 떼고 계약 minimum도 바꿔야 하므로 두 조건이 모두 참이다 |
| 회신 전 경계 | 실사 라인과 멱등 기록은 0건으로 롤백한다. 음수 묶음을 조용히 빼거나 0으로 저장하지 않는다 |

## 확인된 충돌

1. `item.negative_stock_allowed=true`이면 `inventory_balance.on_hand_qty`는 실제로 음수가 될 수 있다.
2. `inventory_count_line.system_qty`는 공용 비음수 도메인 `app.qty_t`라 음수를 저장하면 DB `qty_t_check`가 거부한다.
3. 계약 `InventoryCountLine.systemQty.minimum: 0`도 음수를 금지한다.
4. 따라서 「실제 음수 보존」은 계약 한 칸 정정만이 아니라 컬럼 도메인 분리와 기존 데이터·소비자 영향 검토가 필요하다.

## 설계팀에 묻는 것

음수 잔액이 있는 창고에서 실사를 시작할 때 어느 동작이 정본인지 결정해 주십시오.

1. **권고안 — 실제 음수 보존:** `system_qty`만 signed decimal로 바꾸고 계약 minimum을 제거한다. 실사 차이는 실제 장부와 실물의 차이로 계산한다.
2. **음수 묶음 제외:** 해당 `(location,item,lot,uom)`을 실사 대상에서 뺀다. 실사 완료가 창고 전건 완료를 뜻하지 않게 된다.
3. **개시 거부:** 음수 잔액을 먼저 조정해 0 이상으로 만든 뒤 실사를 시작한다. 그동안 해당 창고 전체 실사가 막힌다.

회신 전에는 2처럼 사실을 조용히 잃지 않도록 3의 fail-closed만 적용한다. 회신이 1이면 전용 마이그레이션·계약 정정 후 음수 E2E를 활성화한다.
