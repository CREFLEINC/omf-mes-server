# 272. 실사 개시의 스냅샷·채번·상태·정렬을 서버가 정했다

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 회신을 기다리지 않는다 |
| 걸리는 오퍼레이션 | `GET /inventory/counts` · `POST /inventory/counts` |
| 구현 상태 | I-15에서 구현 예정 |
| 판정 | MES 실사 기능에 가깝지만 계약의 빈 구현 세부를 채우는 저비용 결정이다. 서버 코드·테스트만 바꾸면 되며 기존 실사 데이터는 0건이다 |
| 되돌릴 때 | 스냅샷 GROUP BY, 번호 접두어·기간키, 시작 상태, 정렬 상수와 테스트를 바꾼다 |

## 결정

1. 개시 라인은 해당 창고 `inventory_balance.on_hand_qty`를 `(locationId,itemId,lotId,uomId)`로 합산해 만든다. 라인에 없는 품질·재고상태·소유·파트너·취급단위 축은 합친다.
2. 합계 0은 제외하고 네 축 안정 정렬로 `lineNo`를 1부터 부여한다.
3. 실사 번호는 `INVENTORY_COUNT` 기본 접두어 `IC`, 창고의 공장 범위, 요청 `plannedDate` 기간키를 쓴다.
4. API 이름이 “실사 개시”이므로 생성 상태는 `IN_PROGRESS`다. `PLANNED`는 기존·외부 적재 행 조회용으로 유지한다.
5. 목록 정렬은 `plannedDate DESC, inventoryCountId DESC`; 날짜 From/To는 둘 다 포함이다.
