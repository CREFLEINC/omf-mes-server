# 181. `W-03-10`(처분 판정 처리)이 **권한 도출 원천에 없다** — 판정 저장이 그 화면 담당자에게 403 이다

**구분: 통보**(회신을 기다리지 않는다 — `coverage-100/README.md` §2 1-1단계 「본질 아님 × 비용 낮음」)

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /quality/nonconformances/{nonconformanceId}/disposition-decisions`(403 선언) · `GET …/{id}/disposition-decisions` · `GET /quality/nonconformances` · `GET /quality/nonconformances/{nonconformanceId}` |
| 구현 상태 | **구현 예정(I-21 PR ⑦)** — `manual-permissions.ts` 에 **4행**(단독 커밋) |
| 판정 | §2 **0단계 선례** — 표 자신이 절차를 적어 두었다(「§3 은 화면 «액션»만 적으므로 … **도출되지 않는 자리는 `manual-permissions.ts` 에 근거와 함께 적는다**」) |
| 되돌릴 때 | 요구서 §3 이 갱신돼 도출표가 그 화면을 담으면 **수동표 4행을 지운다**(겹침 검사가 그때 알려 준다) |

## 무엇이 문제인가

`src/common/permissions/derived-permissions.ts` 는 **요구서 §3(화면 → 엔드포인트)** 에서 기계로 만든다(`scripts/permissions/derive-map.py`). 실측:

| 오퍼레이션 | 오늘 요구하는 권한 | 계약·화면이 말하는 호출자 |
|---|---|---|
| `POST …/{id}/disposition-decisions` | **`['P-02-13']`** | 계약 「**`W-03-10` 「판정 저장」**」 |
| `GET …/{id}/disposition-decisions` | `['P-02-13','P-04-03']` | 계약 「**`W-03-10`** 상세에서 …」 |
| `GET /quality/nonconformances` | `['P-02-13','W-04-07','W-04-11']` | `W-03-10` ① 판정 대기 목록 |
| `GET /quality/nonconformances/{id}` | `['P-02-13','W-03-09','W-04-07']` | 계약 「**부르는 화면은 `W-03-10`**」 |

⭐ **`W-03-10` 이 이 11 오퍼레이션 어디에도 없습니다.** 화면 자체는 등재돼 있는데(`src/common/permissions/permissions.ts:87` 「처분 판정 처리(재작업/폐기/정상)」) **그 코드를 요구하는 오퍼레이션이 0개**이고 `manual-permissions.ts` 에도 0건입니다(전수 grep).

**원인은 시각차입니다** — `W-03-10` 은 **DR-008 확정 3-A 로 2026-08-13 에 «신설»된 화면**이라(그 화면 스펙 머리글) 도출 원천인 요구서 §3 보다 **새것**입니다. 그래서 한 줄도 안 도출됐습니다.

**결과**: 판정 저장은 계약이 **403 을 선언**했고(`responses = 201·400·403·404·409`) 가드가 그 자리에서 돕니다(`permission.guard.ts:37-41`).
⇒ **`W-03-10` 권한만 가진 품질담당·품질책임자는 처분을 저장할 수 없습니다(403).**
⇒ 반대로 **`P-02-13`(POP · PQC 제품 검사 · 검사 결과 입력)** 권한자가 관리웹 처분 판정을 저장할 수 있게 됩니다.

## ⇒ 우리가 한 것

`manual-permissions.ts` 에 위 네 오퍼레이션마다 **`'W-03-10'` 을 더합니다**(공용 파일이라 **단독 커밋**).

✅ **겹침 검사에 걸리지 않습니다** — `operation-permissions.spec.ts:27-36` 은 「같은 키에 **같은 권한**을 다시 적는 것」만 막고, **같은 키에 «다른» 화면 코드를 더하는 것은 문서화된 정상 경로**입니다(`operation-permissions.ts:10-24` 가 두 표를 **합집합**으로 겹치고, 주석이 `GET /app/users` + `W-CO-02` 를 선례로 적어 두었습니다).

**e2e 로 잠급니다** — 「**`W-03-10` 권한만 가진 계정이 201 을 받는다**」. ⛔ `P-02-13` 계정으로 시험하면 이 구멍이 안 잡힙니다.

## 📨 알려 드리는 것

**요구서 §3(화면 → 엔드포인트)에 `W-03-10` 을 넣어 주십시오.**
원천이 낡은 채로 두면 **다음 도출에서 이 네 줄이 다시 사라집니다**(수동표는 도출표를 덮지 않고 합집합이라 조용히 살아남지만, 같은 유형의 신설 화면이 또 나오면 같은 사고가 반복됩니다).
⚠ **DR-008 이후 신설된 화면 전부**를 함께 보시는 편이 좋습니다 — 우리는 이 슬라이스에서만 쟀습니다.
