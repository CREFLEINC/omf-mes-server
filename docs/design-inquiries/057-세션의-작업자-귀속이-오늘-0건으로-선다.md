# 57. ⭐ 세션의 작업자 귀속이 오늘 0건으로 선다 — REQ-PR-0023 이 화면·계약 어디에도 착지하지 못했다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /production/work-sessions` · `POST …/{workSessionId}/workers` · `POST …/workers/{workSessionWorkerId}:leave` |
| 구현 상태 | **구현함(I-11 · `X-Worker-No` 는 존재만 확인하고 버린다 · 참여자 자동 등록 ✕ · 참여·이탈 권한은 `manual-permissions.ts` 에 `P-02-01` 임시 등록)** |
| 판정 | 헤더는 `coverage-100/README.md` §2 1단계 가장자리 → 2단계 **기준 4**(헤더의 사번을 참여자로 조용히 도출하지 않는다) · 권한 등록은 §2 **0단계 선례**(`PUT /logistics/goods-issues/{id}/lines` — 부르는 화면이 0건이어도 가드가 등록을 요구한다) |
| 되돌릴 때 | 「헤더 사번을 참여자로 등록하라」면 서비스 한 자리(완화 · 마이그 0) · 「`workerIds` 를 required 로」면 계약 요청 스키마 · 참여·이탈 화면이 정해지면 `manual-permissions.ts:201` **두 줄**을 그 화면 코드로 바꾼다 |

## 무엇이 문제인가

ⓐ 세션을 여는 **유일한 화면 `P-02-01`** 이 **사번 하나만** 받고 `workerIds[]` 를 채울 입력이 **0건**이다. `workerIds[]` 는 required 도 아니다 ⇒ **오늘 열리는 세션은 전건이 참여자 0명**이다.
ⓑ `POST /work-sessions` 의 `X-Worker-No` 는 **required** 인데 `work_session` 에 사번·작업자 칸이 **0**이고, `work_session_event.performed_by` 는 **`app_user` FK** 라 사번이 갈 곳이 없다 ⇒ **「누가 시작했는가」가 `workerIds[]` 를 보내야만 남는다.**
ⓒ 그런데 `P-02-01` §5-A 는 `work_session_worker` 를 ⌜작업자 — **사번 귀속** — REQ-PR-0023⌝ 으로 자기 표에 실었다 — 요구사항은 있는데 그것을 채울 입력·칸이 화면에도 계약에도 없다.
ⓓ 참여·이탈을 **부르는 화면이 0건**이다(`plan-uiux.md` 835 ⌜`{workSessionId}` 상세와 `/workers` **목록**이 `P-02-01` 을 들고 있다. 목록의 짝인 «참여·이탈»이 **화면을 안 들고 있을 뿐**이다⌝). 그런데 계약이 403 을 선언해 **미등록이면 500** 이라 서버가 `P-02-01` 로 잠정 등록했다.
ⓔ 서버가 헤더의 사번을 참여자로 자동 등록하면 **조용한 도출**이라 하지 않았다 — 계약이 그 자리를 `workerIds[]` 로 따로 열어 두었기 때문이다.

## 지금 서버는

- 세션 셋(`POST /work-sessions`·`/events`·`:end`)은 `X-Worker-No` 가 없으면 400 `REQUIRED`, `mdm.worker.worker_no` 에 없으면 400 `INVALID` 를 내고 **값은 버린다**(담을 칸이 0). `plan.md` §5 규칙 9 의 POP 예외가 여기서 4·5·6번째로 는다.
- `workerIds` 를 안 보낸 세션은 **참여자 0명으로 정상으로 선다** — e2e `workerIds 없이 연 세션은 workers 가 0건이다` 가 그 사실을 못 박는다.
- `manual-permissions.ts:201` 에 참여·이탈 두 줄 + ⌜참여·이탈을 «부르는» 화면은 0건이다 — 화면이 정해지면 그때 옮긴다⌝ 주석. `POST /production/precheck-decisions` 만 예외로 사번을 **저장한다**(`precheck_decision.worker_no` — FK 가 아니라 문자열).
