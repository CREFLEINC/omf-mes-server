# 189. 결재함 목록(`GET /app/approval-requests`)의 **호출 셸 둘이 권한 도출 원천에 없다** — 통보 181 의 형제

**구분: 통보**(회신을 기다리지 않는다 — `coverage-100/README.md` §2 1-1단계 「본질 아님 × 비용 낮음」)

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /app/approval-requests`(**구현 완료** · I-1) |
| 구현 상태 | **수동표 2행 추가로 막았다**(`src/common/permissions/manual-permissions.ts` · 단독 커밋) |
| 판정 | §2 **0단계 선례** — 수동표 자신이 절차를 적어 두었다(「도출되지 않는 자리는 근거와 함께 적는다」). 그리고 **통보 181 이 같은 원인으로 같은 처방을 이미 썼다** |
| 되돌릴 때 | 요구서 §3 이 갱신돼 도출표가 두 화면을 담으면 **그 2행을 지운다**(겹침 검사가 그때 알려 준다 — `operation-permissions.spec.ts:27`) |
| 발견 경위 | 레인 A2 의 I-34 작업 중 조율 보고로 넘어왔다 |

## 무엇이 문제인가

`derived-permissions.ts` 는 **요구서 §3(화면 → 엔드포인트)** 에서 기계로 만든다. 실측(main `da940cd`):

```
'GET /app/approval-requests': ['W-01-13', 'W-03-09', 'W-CO-09']
```

그런데 **계약이 이름 적은 호출자 둘이 그 목록에 없다.**

| 화면 | 계약 원문 | 도출표 |
|---|---|:-:|
| **`M-01-13`** | 오퍼레이션 description — 「⭐ **부르는 셸이 «둘»이다** — 관리웹 결재함(`W-CO-09`)과 **모바일 상신 화면(`M-01-13` 의 「내가 올린 요청」 구획)**」. `requestedByMe` 근거도 「… `M-01-13` §4 · omf-mes#335」 | ❌ **없다** |
| **`W-01-02`** | `assignedToMe` description — 「승인 화면은 관리웹뿐이라(`W-CO-09`·**`W-01-02`**·`W-03-09`) 지금은 계정 토큰에서만 풀린다」 | ❌ **없다** |

⭐ `assignedToMe` 가 이름 적은 **셋 중 둘(`W-CO-09`·`W-03-09`)은 도출표에 있고 `W-01-02` 만 빠졌다.** 계약이 한 문장에 나란히 적은 셋인데 도출은 둘만 집었다.

**결과** — 그 두 화면 담당자는 **결재함 목록에서 403 을 받는다.** 특히 `M-01-13` 은 계약이 「**부르는 셸이 둘**」이라 못 박은 자리라, **모바일 상신 화면의 「내가 올린 요청」 구획이 오늘 열리지 않는다.**

## ⇒ 우리가 한 것

`manual-permissions.ts` 에 **2행**을 근거와 함께 더했다(단독 커밋).

```ts
'GET /app/approval-requests': ['M-01-13', 'W-01-02'],
```

두 표는 **합집합**이라 도출된 셋은 그대로 살아 있다(`operation-permissions.spec.ts:38-47` 이 그것을 지킨다).

## ⛔ 넣지 «않은» 것 — `M-CO-01`

조율 보고는 `M-CO-01` 도 함께 들었으나 **넣지 않았다.** 계약이 그 이름을 적은 유일한 자리는 `requestedByMe` description 의

> 「… 현장 단말·모바일은 `X-Worker-No` 헤더의 «사번»이다(**모바일 셸에는 계정 로그인이 없다 · `M-CO-01` §2**)」

인데, 이것은 **「나」가 셸마다 어떻게 풀리는지의 «인증 모델» 근거**이지 **「`M-CO-01` 화면이 이 목록을 부른다」가 아니다.**
수동표 머리가 「**그 화면이 그 자원의 마스터를 소유한다」가 근거일 때만 적는다 — 지어내면 그것이 사실상의 인가 정책이 된다**」라 못 박아 두었으므로, 근거가 caller 가 아닌 것은 넣지 않았다.

⇒ **`M-CO-01` 이 이 목록을 부르는 것이 맞다면 알려 주십시오.** 그때 한 줄을 더한다.

## ⚠ 알려 드릴 것 — 이것이 **둘째 사례**입니다

**통보 181**(`W-03-10` 이 권한 도출 원천에 없어 처분 판정 저장이 403)과 **원인이 같습니다** — 요구서 §3 이 화면보다 낡아 도출이 그 화면을 못 집습니다. 181 은 화면이 **신설**(DR-008 · 2026-08-13)돼서였고, 189 는 계약 description 이 **호출 셸을 명시했는데 §3 이 안 담아서**입니다.

⇒ 한 자리의 사고가 아니라 **원천의 성질**로 보입니다. 요구서 §3 을 **전수로 한 번 대조**해 주시길 요청합니다 — 서버가 수동표로 메울 수는 있으나, 그것이 늘수록 **인가 정책이 요구서가 아니라 서버 코드에 쌓입니다.**
