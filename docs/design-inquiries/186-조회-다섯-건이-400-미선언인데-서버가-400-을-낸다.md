# 186. 조회 **다섯 건이 400 을 선언하지 않았는데** 서버가 400 을 낸다 — 문의 074 와 같은 패턴

**구분: 통보**(회신을 기다리지 않는다) · ⭐ **I-20 문의 074 와 «묶어» 보십시오** — 대상만 다르고 패턴이 같습니다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /quality/nonconformances` · `GET /quality/disposition-candidates` · `GET /quality/nonconformances/{ncId}/disposition-decisions` · `GET /quality/disposition-decisions` · `GET /quality/concessions` — **다섯 다 200 하나만 선언**(python 실측) |
| 구현 상태 | **구현 예정(I-21 PR ①a·②a″·③·⑤)** — 계획서 `docs/coverage-100/slices/I-21.md` §1-2 |
| 판정 | §2 **2단계 기준 2**(거부하는 쪽 — 거부→허용이 호환 완화) · **0단계 선례 = I-20 §1-2 갈래 C**(같은 판정을 문의 074 로 남겼다) |
| 되돌릴 때 | 「기간이 없으면 전건을 낸다」로 완화 — `WHERE` 한 줄과 e2e 두 건 |

## 어디서 400 이 나나

| 자리 | 서버가 내는 것 | 계약이 선언한 응답 |
|---|---|---|
| `GET /quality/nonconformances` — `openedFrom`/`To` 부재 | **400 `REQUIRED`** | 200 **하나** |
| 〃 — 한쪽만 | 400 `REQUIRED` | 200 하나 |
| `GET /quality/disposition-decisions` — `decidedFrom`/`To` **한쪽만** | **400 `PAIR`** | 200 하나 |

**근거는 계약 «설명»입니다** — `openedFrom` 「**기간 필수** — 공유계약 L-3」 · `decidedFrom` 「기간 — **이력 모드에서 필수**(L-3)」.
⇒ **설명은 「필수」인데 `required` 도 `400` 도 선언되지 않았습니다.**

⚠ 세 번째 기간 갈래는 반대입니다 — `disposition-candidates` 의 `receivedFrom`/`To` 는 계약이 **「⚠ 기간을 «필수»로 두지 않는다 — 이 목록은 「지금 판정을 기다리는 것」이라 재고성이고, 기간을 강제하면 오래된 미처리 건이 화면에서 사라진다」**라 «명시»했습니다. 그래서 그 자리는 **통과**시킵니다. **한 슬라이스 안에서 기간 규칙이 세 갈래**입니다.

## ⇒ 우리가 정한 것

- 「기간 필수」라 **설명한** 자리는 **400 으로 요구합니다**(§2 2단계 기준 2 — 나중에 완화하는 것이 싸다).
- ⛔ 「이력 모드」의 판정 축이 계약에 없어 `decidedFrom`/`To` 는 **한 쌍으로만** 봅니다(한쪽만 오면 400 `PAIR`, 둘 다 없으면 통과).
- ⛔ **조회 필터의 코드값은 검증하지 않습니다** — `severityCode` 가 시드 3값 밖이어도 **200 + 빈 목록**입니다. 계약이 「⭐ **고객이 늘릴 수 있다** — 닫힌 목록이 아니다」라 적었고, 저장소의 `assertCodeValues` 전 사용처 20자리가 **전부 쓰기 경로**입니다(조회에서 부르는 자리 0건). ⇒ **쓰기에서만** 검증합니다.

## 📨 알려 드리는 것

**계약에 `required: true` 와 `400` 응답을 함께 적어 주십시오.**
지금은 **계약에서 만든 클라이언트에 400 분기가 없어**, 화면이 목록 대신 「알 수 없는 오류」를 봅니다.
⭐ **문의 074(I-20 · `GET /quality/defect-records` 의 같은 자리)와 묶어 보시면** 「계약이 기간을 필수라 «설명»하고 `required`·400 을 안 적는」 패턴이 **두 도메인에서 반복**된다는 것이 보입니다. 한 번에 고치실 수 있습니다.
