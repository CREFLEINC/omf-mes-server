# 165. 구성 치환이 **단위를 바꿀 수 있는데** 재포장 이력 라인에 단위 칸이 **0** 이라, 그 변경이 이력에 「변화 없음」으로 남는다

> ⚠ **「오늘 서버가 정하고 구현할 것」이다.** 회신을 기다리지 않는다.
> ⭐ 이 문의는 **레인 C 대역(120~149)의 통보 `140`·`143`·`144` 를 «가리키기만» 한다** — 그 본문은 한 글자도 고치지 않았다.
> ⭐⭐ **이 자리는 3관점 재수립이 초안의 결정을 «뒤집은» 유일한 곳이다**(`I-16-a2.md` §0-재수립 **R-2**).

| 칸 | 내용 |
|---|---|
| **구분** | ⭐ **통보** — **계약 응답은 한 칸도 안 바뀐다**(서버 전용 칸이다). 되돌리는 비용은 「칸 둘을 안 쓰고 두는 것」뿐이다. 정하고 알린다 |
| 걸리는 오퍼레이션 | `PUT /inventory/handling-units/{handlingUnitId}/contents` · `GET /inventory/handling-units/{handlingUnitId}/repack-events` |
| 구현 상태 | **구현 예정(I-16 PR ② 마이그 + PR ④ 채우는 코드 · 계획만 병합됨 · 오늘 코드 0줄)** — 계획서 `docs/coverage-100/slices/I-16-a2.md` §2-3 · §2-4 · §5-3 · §10-1 #15 |
| 판정 | `coverage-100/README.md` §2 **1단계**(계약이 한쪽 문은 열고 다른 쪽은 안 열었다) → **2단계 기준 2**(되돌릴 수 없는 쪽을 피한다 — 마이그가 **forward-only** 다) · **기준 3 은 여기서 지지 않는다**(칸을 늘리지만, 그 표 자체가 이 슬라이스가 «지금» 만드는 신설 표다 — 나중에 더하면 그 사이 이력이 못 산다) |
| 되돌릴 때 | ⓐ 「그 칸이 필요 없다」가 오면 **두 칸을 안 쓰고 둔다** — 응답에 안 실려 있으므로 화면·계약 영향 **0**, 삭제는 두 릴리스 규칙대로 별건이다. ⓑ 반대로 계약 `HandlingUnitRepackEventLine` 에 `uomId`(또는 before/after)가 **서면 그때 응답에 싣는다 — 마이그 0**. 뷰 두 줄이다 |

## 무엇이 문제인가

### ⓐ 요청은 `uomId` 를 **required 로 받는데**, 이력 라인에는 그 축이 없다

- 계약 `HandlingUnitContentUpsert` 의 **`required` 4칸 = `itemId`·`lotId`·`qty`·`uomId`**(직접 파싱). **클라이언트가 단위를 실어 보낸다.**
- 계약 `HandlingUnitRepackEventLine` 의 **`required` 6칸 = `handlingUnitId`·`roleCode`·`itemId`·`lotId`·`qtyBefore`·`qtyAfter`** — ⛔ **`uomId` 가 없다.** 단위 축이 **응답에도 프로퍼티로도 0**이다.
- 물리 `inventory.handling_unit_content.uom_id` 는 **NOT NULL FK** 로 실재한다(psql). 단위는 저장되지만 **그 변경의 이력은 저장할 곳이 없다.**

### ⓑ ⭐ 그리고 그 변경은 **실제로 들어온다** — UNIQUE 키에 `uom_id` 가 없기 때문이다

- `uq_handling_unit_content UNIQUE (handling_unit_id, item_id, lot_id)` — ⭐ **`uom_id` 가 그 키에 없다**(psql 원문).
- ⇒ 같은 포장의 같은 `(item, lot)` 행에 대해 **`10 EA` → `10 BOX`** 같은 치환이 **완전히 성립한다.** 계약 `PUT …/contents` 는 「구성 **전체 치환**」이고 요청이 단위를 실으므로, 화면이 단위를 바꿔 보내는 것을 막는 것이 **계약에도 물리에도 0**이다.
- ⇒ 이력 라인이 `qty_before`·`qty_after` 만 담으면 그 사건은 **`100 === 100` 「변화 없음」으로만** 남는다. **무엇이 바뀌었는지 적는 것이 그 표의 존재 이유인데, 바뀐 것을 못 적으면 그 표는 거짓말을 한다.**

### ⓒ ⛔ 마이그레이션이 **forward-only** 라, 이 자리만은 **지금** 정해야 한다

- `CLAUDE.md` · `lanes.md` §1-2 — 마이그는 **추가·완화만**, 삭제 0, 백필 0.
- 나중에 `uom_id_before`·`uom_id_after` 를 «더하는 것»은 언제든 된다. ⛔ **그러나 그 사이에 기록된 이력 행의 단위는 어디에도 없어 영구히 복구 불가다.**
- ⇒ 「나중에 계약이 서면 그때」로 미룰 수 있는 자리가 **아니다.** 이 슬라이스가 **바로 그 표를 신설하는 PR** 을 낸다.

### ⓓ 그래서 서버가 **서버 전용 칸 둘**로 닫았다 — 계약 위반이 0인 이유

- 신설 `inventory.handling_unit_repack_event_line` 에 **`uom_id_before bigint NULL REFERENCES mdm.uom(uom_id)`** · **`uom_id_after` 같은 모양** 두 칸을 만든다.
- **nullable 인 이유**: 새로 생긴 줄의 `uom_id_before` 와 빠진 줄의 `uom_id_after` 가 **없는 값**이다(`qty_before`/`qty_after` 가 0 인 자리와 짝이다 — 다만 0 은 수량이고 단위는 「없음」이라 NULL 이 맞다).
- ⛔ **응답에 안 싣는다** — 계약 라인 스키마에 그 칸이 없다. **서버가 채우고 서버만 읽는다** ⇒ **계약 위반 0 · 화면 영향 0.**
- ⛔ **`uom_id`(단일 칸)를 만들지 않는다** — 기존 `handling_unit_reconfiguration_line.uom_id`(NOT NULL) 는 「이동한 수량의 단위」 하나를 담는 모양이라 **전/후 두 값을 못 담는다.** 그 표를 재사용하지 않는 이유와 같다(통보 140).
- 비용: **마이그 2칸 + 채우는 코드 2줄.** 초안이 재사용을 기각한 사유(「영구 NULL 칸」)와 **다르다** — 이 두 칸은 서버가 언제나 채운다(양쪽이 다 있는 줄에서는 둘 다 값이 있다).

## 지금 서버는

- **PR ② 의 선행 커밋(마이그)** 이 신설 `handling_unit_repack_event_line` 에 `uom_id_before`·`uom_id_after` 를 함께 만든다 — **CREATE 만 · 완화 0 · 삭제 0 · 백필 0**(그 표에 행이 0이므로 백필할 것이 없다).
- **PR ④**(`PUT …/contents`)의 diff 계산이 치환 «전» 맵을 `(item_id, lot_id) → {qty, uom_id}` 로 읽고 세 갈래를 이렇게 채운다:
  유지 = `RESULT` · 전 uom → 후 uom · 신규 = `RESULT` · **NULL** → 후 uom · 제거 = `SOURCE` · 전 uom → **NULL**.
- ⛔ **응답 뷰에는 두 칸이 없다** — e2e 16 이 「라인 응답에 `uomId`·`uomIdBefore`·`uomIdAfter` 가 **없다**」를 **값 단언**으로 잡는다(ajv 는 여분 칸을 못 잡는다).
- ⭐ **단위 시험 12 가 이 자리를 지킨다** — `(item, lot)` 이 같고 **단위만** 바뀐 줄이 `qty_before === qty_after` 이면서 `uom_id_before !== uom_id_after` 로 기록되는 것을 단언한다. 변이 두 개(**두 칸을 NULL 로 둠** · **`uom_id_after` 를 `uom_id_before` 로 채움**)가 그 시험을 빨갛게 만든다 — 안 그러면 이 결정은 반증 불가다.
- ⛔ `contracts/*.json` 은 **한 글자도 안 고쳤다** — 계약 변경 요청이 아니라 **서버가 자기 저장 축을 넓힌 것**이다.

⇒ **알리는 것**: 계약이 **요청에는 `uomId` 를 required 로 두고 이력 라인에는 안 뒀는데**, `uq_handling_unit_content` 에 `uom_id` 가 없어 **단위만 바뀌는 치환이 실제로 성립한다.** 그대로 두면 그 사건이 이력에 **「변화 없음」으로만** 남고, 마이그가 forward-only 라 **나중에 칸을 더해도 그 사이 이력은 영구 복구 불가**다. ⇒ 서버가 **신설 표에 `uom_id_before`·`uom_id_after` 두 칸을 지금 만들고, 계약이 안 읽으므로 응답에는 싣지 않는다.** 계약 `HandlingUnitRepackEventLine` 에 단위 축이 서면 **그때 응답에 싣는다 — 마이그는 0이다.**
