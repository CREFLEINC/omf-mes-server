# 47. 자재 출고요청·부족 응답에 표시 라벨 칸이 0 이다 — `MaterialIssueShortageLine` 에 `itemCode`·`itemName` 없음 · `MaterialIssueRequest` 에 `workOrderNo`·도착 위치 코드/명 없음 · 같은 계약의 `PickingLine` 은 파생 9칸을 준다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /logistics/material-issue-requests` · `GET …/{materialIssueRequestId}` · `GET …/shortage` |
| 구현 상태 | **구현함(I-8 · 계약 required 그대로 · 라벨 칸을 지어 넣지 않았다)** |
| 판정 | `coverage-100/README.md` §2 0단계 **선례**(I-7 R-n · 응답 칸은 계약 required 대로 · 지어 넣으면 계약 검증이 아니라 관행이 정본이 된다) → 2단계 **기준 3**(계약 사본을 안 고치는 쪽) |
| 되돌릴 때 | 계약이 `MaterialIssueShortageLine`·`MaterialIssueRequest(Line)` 에 파생 칸을 더하면 뷰 매퍼 각 ~5줄 + `shortage` 조인 1(`item`) — 마이그 0 |

## 무엇이 문제인가

`contracts/logistics-01자재창고.json` 실측:

| 스키마 | required | 화면이 그리는 첫 열 | 없는 칸 |
|---|---|---|---|
| `MaterialIssueShortageLine` | `itemId`·`requiredQty`·`issuedQty`·`shortageQty`·`uomId` + `bomComponentId` | `W-02-10.md:48-51` 「품목」 | `itemCode`·`itemName` |
| `MaterialIssueRequest` | 5 | 「작업지시」·「도착 위치」 | `workOrderNo` · 도착 위치 코드/명 |
| `MaterialIssueRequestLine` | 7 | 「품목」 | `itemCode` |

같은 계약의 `PickingLine` 은 파생 9칸(`itemCode`·`itemName`·`lotNo`·`locationCode`·`expiryDate`·`manufacturedAt`·`held`·`holdReasonCode`·`pickSequenceRank` — required 밖 10칸 중 물리 칸 `inventoryReservationId` 를 뺀 실측)을 준다 — **비대칭은 설계가 아니라 누락**으로 읽힌다. `plan-uiux.md:1022`(L-2) ⌜BOM 조회를 화면이 따로 하지 않는다⌝ 와 정면으로 충돌한다 — `shortage` 가 `itemId` 만 주면 화면은 품목마다 `GET /mdm/items/{id}` 를 부르거나 BOM 을 따로 열어야 한다.

## 지금 서버는

- 세 응답 다 계약 required 그대로. `itemCode` 등을 지어 넣지 않았다(계약 검증 가드가 `additionalProperties` 를 막지는 않지만, 관행이 정본이 되면 계약 사본 고정(a6a87e1) 의 뜻이 사라진다).
- `W-02-10` 표의 「요청수량·비고」 열이 `MaterialIssueShortageLine` 에 없는 것은 **입력 칸**이라 결손이 아니다(「알려둘 것」 ⓗ → 이 문의로 승격하며 그 부분은 뺐다).
