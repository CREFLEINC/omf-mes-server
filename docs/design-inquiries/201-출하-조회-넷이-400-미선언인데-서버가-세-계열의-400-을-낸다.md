# 201. 출하 조회 넷이 **400 을 선언하지 않았는데** 서버가 **세 계열**의 400 을 낸다 — 문의 074·186 과 같은 패턴

**구분: 통보**(회신을 기다리지 않는다) · ⭐ **문의 074(I-20)·186(I-21)과 묶어 보십시오 — 세 번째 반복입니다**

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /logistics/sales-orders` · `GET /logistics/shipment-requests` · `GET /logistics/shipment-requests/summary` · `GET /logistics/shipment-lot-allocations` — **넷 다 `200` 하나만 선언**(python 실측) |
| 구현 상태 | **구현 예정(I-22 PR ②·③·④·⑦a)** |
| 판정 | §2 **2단계 기준 2**(거부하는 쪽) · **0단계 선례 = 문의 074·186**(같은 판정을 두 번 남겼다) |
| 되돌릴 때 | 「기간이 없으면 전건」으로 완화 — `WHERE` 한 줄과 e2e 두 건 |

## 세 계열입니다

| 계열 | 어디 | 코드 | 근거 |
|:-:|---|---|---|
| **① 기간 필수** | `GET /logistics/shipment-requests` · ⭐ **`…/summary`** | 400 `REQUIRED` | 계약 `shipDateFrom` description 「**필수 — 공유계약 L-3**」 · 요약 쪽은 「필수 — 공유계약 L-3. **목록과 같은 기준을 쓴다**」 · `W-04-05` §5 「기간을 비운 요청은 서버가 400 이다 · **비울 수 없다**」 |
| **② 정렬 화이트리스트** | `GET /logistics/shipment-requests` `sort` | 400 `INVALID` | 계약 「출하일·고객·작업지시번호 **셋만**(L-4)」 · `W-04-02` §5-5 |
| **③ 계약 가드 자신** | 네 목록 전부 | 400 | `shipmentProgressCode` enum 밖 값 · 타입 강제 실패 등을 **공용 검증 가드가** 낸다 |

⇒ **셋 다 「계약이 설명으로는 요구하고 응답으로는 안 적은」 자리**입니다.

## ⇒ 우리가 정한 것

- **①** `shipDateFrom` 이 없으면 **목록도 요약도** 400 `REQUIRED` 입니다(요약을 빠뜨리면 「목록은 막히는데 합계는 전건을 훑는」 비대칭이 생깁니다).
- **②** 허용 3키(`requestedShipDate`·`customerId`·`shipmentRequestNo`) 밖의 `sort` 는 400 `INVALID` 입니다. 기본 정렬은 계약이 침묵해 **`requested_ship_date` 오름차순 + PK** 로 정했습니다(출하 예정 목록이라 임박한 것이 위).
- **③** 은 우리가 만드는 것이 아니라 공용 가드의 동작입니다 — 계약에 400 이 없으면 **문서와 실제가 갈립니다.**
- ⛔ `GET /logistics/sales-orders` 는 **기간 필수가 아닙니다**(L-3 목록에 없습니다) — ③ 만 걸립니다.

## 📨 알려 드리는 것

**네 오퍼레이션에 `400` 응답을 적어 주시고, `shipDateFrom` 에 `required: true` 를 달아 주십시오.**
지금은 계약에서 만든 클라이언트에 400 분기가 없어 화면이 목록 대신 「알 수 없는 오류」를 봅니다.
⭐ **문의 074·186 과 묶어 보시면** 「기간을 필수라 «설명»하고 `required`·400 을 안 적는」 패턴이 **세 도메인에서 반복**된다는 것이 보입니다 — 한 번에 고치실 수 있습니다.

## 🔎 이 통보가 «흡수»한 것 (3관점 재검토 · 2026-09-09)

| 어디서 왔나 | 무엇 |
|---|---|
| **API 관점**(Major A-8 ⓐ) | ⭐ **`GET …/shipment-requests/summary` 의 `shipDateFrom` 필수를 계획안이 아예 안 적었다** — 계약이 「필수 — 공유계약 L-3. **목록과 같은 기준을 쓴다**」라 못박았는데 e2e 가 **0건**이었다 ⇒ 요약 400 한 줄과 시험 한 건을 더했다 |
| **API 관점**(Major A-8 ⓑ) | ⭐ **400 이 «세 계열»이다** — ① 필수 기간 ② 정렬 화이트리스트 밖 ③ **계약 가드 자신**(enum 밖 값·타입 강제 실패). 초판 문안은 셋 중 하나만 말했다 |
| **UI/UX 관점**(§3-7) | `W-04-05` §5 「기간을 비운 요청은 서버가 400 이다 · **비울 수 없다**」로 화면 근거를 보강했다 |
