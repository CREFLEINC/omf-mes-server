# 51. 자재 반출이 재고를 옮기는데 원장을 지날 수단이 계약에 하나도 없다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /production/material-returns` · `GET /production/material-returns` |
| 구현 상태 | **구현함(I-10 · 전기하지 않는다 — `material_return_line.inventory_transaction_line_id` 영원히 NULL · `requested_at` 은 서버 수신 시각 · `received_at` 영원히 NULL)** |
| 판정 | `coverage-100/README.md` §2 1단계 **본길**(모든 반출의 결과가 갈린다) → **계약 문자 그대로**(날짜·목적 위치·원장 칸·도착 오퍼레이션이 전부 0) → 2단계 기준 1(원장을 안 쓰는 쪽)·기준 2(안 전기하다 전기하는 것이 완화)·기준 4(값을 조용히 도출하지 않는 쪽) **셋이 같은 답**. `requested_at` 은 1단계 본길(담을 칸이 있는데 받을 칸이 0) → 기준 5 |
| 되돌릴 때 | 「전기하라」면 계약이 먼저 넷을 줘야 한다 — `MaterialReturnCreate` 에 `businessDate`·`occurredAt` · 목적 **«위치»** · `InventoryTransaction.sourceDocumentTypeCode` 에 `MATERIAL_RETURN`(+ `app.entity_type_registry` 1행). 서버는 그 뒤 `post()` 배선 한 자리다. 「`requestedAt` 을 클라이언트가 보낸다」면 요청 스키마 한 칸 + 서비스 한 줄(마이그 0) |

## 무엇이 문제인가

ⓐ `MaterialReturnCreate` 에 **`businessDate`·`occurredAt`·`requestedAt` 이 전부 없다**(`StockTransferCreate`·`ShopfloorReceiptCreate`·`GoodsIssueCreate` 는 다 갖는다). `PostingInput.businessDate` 는 필수이고 **C-8 이 서버의 시각 재계산을 금한다**(CLAUDE.md).
ⓑ 목적지가 **창고 하나뿐**이고 목적 «위치» 칸이 없는데 `inventory_balance.location_id` 는 NOT NULL 이고 `mdm.location` 에 기본 위치 플래그가 없다(17칸 전건 실측) ⇒ 도착 잔액 행을 만들 수 없다.
ⓒ `InventoryTransaction.sourceDocumentTypeCode` enum **4값**(값 = «대상 테이블 이름»)에 `MATERIAL_RETURN` 이 없고 `app.entity_type_registry` 25행에도 없다 — `STOCK_TRANSFER` 를 쓰면 `sourceDocumentId` 가 `logistics.stock_transfer` 를 가리키는 **거짓**이 된다.
ⓓ 계약이 ⌜**구간 형 리소스**라 진행은 `requestedAt ↔ receivedAt` 의 유무로 판정한다⌝ 라 적었는데 **`receivedAt` 을 채우는 오퍼레이션이 0건**이다. 형제 `stock_transfer_line` 은 원장 FK 를 **둘** 갖는데 `material_return_line` 은 **하나**라 2단을 담을 칸이 아예 없다.
ⓔ 원장 행은 **불변**이다(baseline `[TRG-05]` — Line 은 수정·삭제 금지) ⇒ 잘못 전기하면 되돌릴 수 없다.
ⓕ ⭐ 덤이 아니라 물증이다 — 같은 오퍼레이션 description 이 ⌜**오프라인 대상** — 셸의 outbox 가 들고 있다가 연결되면 그때 보낸다⌝ 라 적어 `requested_at = now()` 는 **재전송 시각**이고 자정을 넘기면 하루가 밀린다(`MR-` 채번 기간 키도 함께 밀린다 — C-8 이 막으려던 바로 그 형상). 투입은 `occurredAt` 이 있어 C-1(발생/기록 분리)을 받았고 **반출만 못 받았다**. 회신 대기 15(`businessDate` 축)의 **11번째이자 «반대 방향» 첫 사례**다.

## 지금 서버는

- 원장 **0** — `InventoryPostingService` 를 **생성자에서도 받지 않는다**(단위 테스트가 생성자 인자 수로 못 박는다) · `InventoryPostingModule` import 0 · `FOR UPDATE`·잔량 대조 0. e2e 가 `inventory_transaction`·`_line` 0건과 `inventory_balance` 무변화를 DB 직접 SELECT 로 단언한다.
- `requested_at = new Date()`(수신 시각) · `received_at` 은 NULL 로 태어나 NULL 로 남고 뷰가 키를 생략한다.
- `status_code` 는 상수 `'REQUESTED'`(문의 053) · 채번 `MR-{YYYYMMDD}-{SEQ4}` 의 기간 키는 **UTC 날짜**라 하노이 새벽이 전날 번호를 받는다.
