# 설계 요청 전달용 정산 — Lane B (2026-09-09)

> 상태: **전달 문안 정리 완료 · 설계팀 전달 전**
>
> 추적 이슈: GitHub #342
>
> 범위: Lane B(설비·보전·발행·알림)와 Lane B가 인수해 완료한 I-35·I-15

이 문서는 개별 요청서의 분석 이력을 지우지 않고, 2026-09-09 현재 설계팀에 전달할 항목만 다시 묶은 정산 정본이다.
판정 기준은 `coverage-100/README.md` §2 1-1단계다. **MES 본질에 가깝고 변경 비용도 높은 경우만 질의**하며,
그 밖은 서버팀이 일관된 결정을 구현한 뒤 설계팀에 통보한다.

## 2. 회신이 필요한 질의

### 276 — 음수 재고의 실사 장부수량

대상은 `POST /inventory/counts`와 `GET /inventory/counts/{id}/lines`다.

확인된 사실은 다음과 같다.

1. `item.negative_stock_allowed=true`인 품목의 `inventory_balance.on_hand_qty`는 음수일 수 있다.
2. `inventory_count_line.system_qty`는 비음수 공용 도메인 `app.qty_t`를 사용한다.
3. 계약의 `InventoryCountLine.systemQty.minimum`도 0이다.
4. 따라서 실제 음수를 보존하려면 물리 컬럼 도메인과 계약을 함께 바꿔야 한다.

설계팀에는 다음 셋 중 정본을 요청한다.

1. **권고안 — 실제 음수 보존:** `system_qty`를 signed decimal로 바꾸고 계약 minimum을 제거한다.
2. **음수 묶음 제외:** 음수인 `(location,item,lot,uom)`을 실사 대상에서 뺀다.
3. **개시 거부:** 음수를 먼저 조정한 뒤 실사를 시작한다.

회신 전에는 사실을 누락하거나 0으로 자르지 않는다. 음수 묶음이 하나라도 있는 창고의 개시 요청 전체를 400으로 거부하고,
실사 라인과 멱등 기록을 남기지 않는다. 비음수 창고의 I-15 6개 오퍼레이션은 모두 구현 완료 상태다.

원문: [276-음수-재고의-실사-장부수량을-실제값으로-보존한다.md](276-음수-재고의-실사-장부수량을-실제값으로-보존한다.md)

## 3. 회신 반영 완료

### 105 — LOT 배분 수량과 제품 개체 수

2026-09-09 정보 회신으로 아래 사실을 확인했다.

- 제품 개체 1개는 수량 1이며, `SerialNumber`에는 수량·단위 속성이 없다.
- 발번은 생산 실적·`goodQty`·LOT 배분을 선행조건이나 상한으로 사용하지 않는다.
- 품목 기준단위는 `Item.baseUomId`이고 LOT 배분 행에는 단위가 없다.
- 이 경로에는 단위 환산·혼합 단위·소수 개체 처리가 없다.

서버는 회신을 반영해 I-26 POST를 PR #544로 구현했다. 회신 자체는 설계 변경이 아니며,
설계팀이 위 설명을 계약 설명문에 명문화하면 그 변경을 설계 변동 공지에 싣기로 했다.

원문: [105-LOT-배분-단위와-개체-수의-대응.md](105-LOT-배분-단위와-개체-수의-대응.md)
