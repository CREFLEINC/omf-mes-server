# 184. **「차단이 풀리는 자리」가 둘이다** — 처분 「정상」(I-21)이 재고 재등록(I-23)을 선점한다

**구분: 통보**(회신을 기다리지 않는다) · ⚠ **두 레인이 함께 정할 자리**라 판정을 미뤄 둔 항목이 하나 있습니다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /quality/nonconformances/{nonconformanceId}/disposition-decisions`(I-21 · 레인 A) · **`POST /logistics/stock-reinstatements`**(I-23 · 레인 C) |
| 구현 상태 | **둘 다 구현 예정** — I-21 은 계획 완료(PR ④·⑦) · I-23 은 미착수(표도 아직 물리에 없다) |
| 판정 | §2 **1단계 본길** — 계약 문자가 **두 자리 모두** 전이를 요구한다. 어느 한쪽을 임의로 끄지 않는다 ⇒ **두 레인 공동 판정으로 남긴다** |
| 되돌릴 때 | `transitions.ts` **한 줄**(`stock-reinstate` 의 `from` 에 `'NORMAL'` 추가) 또는 I-21 이 `disposition-normal` 을 안 거는 것 |

## 무엇이 겹치나

**I-21 이 더하는 전이**(통보 089 §1):

```
'disposition-normal': { from: ['NORMAL','INSPECTION_PENDING','DEFECTIVE'], to: 'NORMAL',
  transitionCode: 'C19', sourceOperation: 'POST /quality/nonconformances/{…}/disposition-decisions' }
```

**I-23 이 쓰기로 예약된 전이**(`src/core/document-state/transitions.ts:215-219` · 이미 등록돼 있다):

```
'stock-reinstate': { from: ['DEFECTIVE'], to: 'NORMAL',
  sourceOperation: 'POST /logistics/stock-reinstatements' }        // transitionCode 미정 — 통보 089 §7
```

**본길 순서**는 `W-04-11` §5-2 가 정했습니다 — 재등록 대상은 「처분이 **정상** 또는 **재작업 완료**」입니다.
⇒ 재등록 확정이 오는 시점에 그 LOT 은 **처분 판정 저장이 이미 `NORMAL` 로 옮긴 뒤**입니다.
⇒ `stock-reinstate` 의 `from:['DEFECTIVE']` 가 **0건을 옮기고**, 코어의 규약대로 **400 `STATE_LOCKED`** 가 납니다.

## ⚠ 화면 문구가 거짓이 됩니다

`W-04-11` §5-3 이 J-7(「이 버튼이 무엇을 푸는가」)을 화면에 상시 적습니다 — 「① Lot Status Hold → Release — **차단이 풀린다**」 · 「⚠ 재등록하면 이 LOT 이 **출하 가능해집니다**」.
그런데 **차단은 한 화면 앞에서(`W-03-10` 판정 저장) 이미 풀립니다.** 재등록 화면이 「지금 풀린다」고 말하는 것이 사실과 다릅니다.

## ⇒ 우리(레인 A)가 한 것 · 남긴 것

- **한 것** — `disposition-normal` 을 계약 문자대로 «겁니다». 계약 `quality-03품질.json:2460` 이 「판정 저장과 Lot Status 전이는 **한 트랜잭션**(B-8) — 처분만 남고 LOT 이 안 바뀌면 **다음 화면이 잘못된 대상을 집는다**」라 이유까지 적었습니다. ⛔ 우리 쪽을 끄면 그 문장을 어깁니다.
- **남긴 것** — `stock-reinstate` 의 `from` 은 **레인 C 의 판정**입니다. 우리가 남의 레인 행을 고치지 않습니다(`lanes.md` §1-4).

## 📨 정해 주셔야 하는 것

**둘 중 하나입니다.**

| 안 | 무엇 | 대가 |
|:-:|---|---|
| **가** | `stock-reinstate` 의 `from` 에 **`'NORMAL'` 을 더한다**(`['DEFECTIVE','NORMAL']`) | 재등록이 「이미 정상인 LOT」도 받게 된다 — 전이는 무변화(NORMAL→NORMAL)지만 `lot_status_event` 한 행이 남는다. **화면 문구는 여전히 거짓**이라 `W-04-11` §5-3 을 고쳐야 한다 |
| **나** | 재등록이 **LOT 상태를 안 옮기고** 재고만 되돌린다 | 그러면 `stock-reinstate` 전이 자체가 필요 없어지고 **통보 089 §7 의 전이 코드 물음도 함께 닫힌다**. 대신 「불량창고에 남아 있던 정상 LOT」을 나타낼 축이 필요하다 |

⭐ **「나」가 더 단순합니다** — 차단을 푸는 자리가 하나(처분 판정)로 모이고, 재등록은 «재고 이동»이 됩니다. 그러나 **레인 C 의 소관**이라 우리가 고르지 않습니다.
