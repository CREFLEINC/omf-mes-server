# 071. **C9(클레임·리콜 재Hold)로 걸린 보류를 풀 길이 0 이다** — 그리고 해제가 LOT 을 «안 옮기는» 구멍이 셋 더 있다

**구분: 통보**(회신을 기다리지 않는다 — `coverage-100/README.md` §2 1-1단계 「본질 아님 × 비용 낮음」)
⚠ **080·088 과 같은 뿌리**(「불량은 발신 전이가 0」)라 **셋을 묶어 봐 달라.**

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/quality/lot-holds/{lotHoldId}:release` (I-20 PR ⑤) |
| 구현 상태 | 구현함 — 해제 뒤 그 LOT 의 열린 보류가 **0 일 때만** 전이하고, `moveWithin()` 이 0건을 옮기면 **400 `STATE_LOCKED`** 로 트랜잭션 전체를 되돌린다 |
| 판정 | §2 **0단계 선례** — I-19 `:confirm` 이 같은 자리에 이미 400 `STATE_LOCKED` 를 적었다(문의 088) · 2단계 **기준 1**(아무 상태도 안 쓴다)·**기준 2**(거부하는 쪽) |
| 되돌릴 때 | ⓐ 는 `transitions.ts` 의 `'lot-hold-release-accepted'`·`'lot-hold-release-rejected'` 의 `from` 에 `'DEFECTIVE'` 를 더하면 풀린다(서비스 코드 변경 0) · ⓑⓒⓓ 는 「무엇을 보이나」의 문제라 화면 정본이 답을 준다 |

## ⓐ 사실 — C9 로 걸린 보류는 «영영» 열린 채 남는다

`src/core/document-state/transitions.ts:206-211`

```ts
'lot-hold-release-accepted': { from: ['INSPECTION_PENDING'], to: 'NORMAL',    transitionCode: 'C7' },
'lot-hold-release-rejected': { from: ['INSPECTION_PENDING'], to: 'DEFECTIVE', transitionCode: 'C8' },
'lot-hold-claim':            { from: ['NORMAL'],             to: 'DEFECTIVE', transitionCode: 'C9' },
```

C9 는 LOT 을 **`DEFECTIVE`** 로 보낸다. 그런데 그 보류를 푸는 C7·C8 의 출발은 **`INSPECTION_PENDING`
하나**다. ⇒ C9 로 걸린 보류에 `:release` 하면 전이가 0건이고 **400 `STATE_LOCKED`** 다.
**어떤 도착 상태를 보내도 마찬가지다** — `NORMAL`(C7)도 `DEFECTIVE`(C8)도 출발이 안 맞는다.

⚠ 이 좁은 `from` 은 우리가 지어낸 것이 아니다 — 계약이 **C7·C8 의 출발 상태를 적은 자리가 없고**,
근거는 화면 정본 `W-03-02` §5-5 도식(「Hold 수신 C6·C8·C9 / **발신 (없음)**」)과 계약 `:4472`
(「불량(Hold)은 발신 전이가 0」)다.

### 현장에서 이것이 무엇을 막나

「고객 클레임으로 불량 재Hold 한 LOT 을, 조사 결과 문제 없어 **정상으로 되돌린다**」가 안 된다.
`W-03-02` 의 해제 사유 4값 중 **`INVESTIGATION_CLEARED`(조사 종결)**·**`MANAGER_OVERRIDE`(관리자
승인)** 가 정확히 그 흐름인데, 그 두 사유를 쓸 LOT 이 서버에서 언제나 400 이다.

⚠ 우회로는 **`POST /logistics/stock-reinstatements`**(`stock-reinstate` · `DEFECTIVE`→`NORMAL`)
하나뿐인데 — ⓓ 를 보라 — 그쪽은 **LOT 만 빼내고 보류 행을 안 닫는다.**

## ⓑ 다른 열린 보류가 남으면 C9 보류도 **200 으로 해제된다**

전이는 「해제 뒤 그 LOT 의 열린 보류가 **0 일 때만**」 일어난다(계약 `:4410` · `W-03-02` §5-9).
그래서 같은 LOT 에 열린 보류가 둘이면, C9 보류를 푸는 요청이 **전이를 아예 안 태우고 200** 이다.
⇒ **ⓐ 의 400 은 「마지막 한 건일 때만」 난다.** 화면에서 보면 같은 버튼이 남은 보류 수에 따라
200 도 되고 400 도 된다. 우리가 보기에 이것은 규칙의 필연이지 결함이 아니지만, `W-03-02` 가
「해제하면 LOT 이 어디로 가는지」를 확정 전에 보이므로 **그 미리보기가 두 갈래를 가려야 한다.**

## ⓒ 부분 해제(`releaseQty`)는 **언제나 200** 이고 LOT 을 «절대» 안 옮긴다

부분 해제는 원 행을 닫고 **남은 수량으로 새 보류 행을 만든다**(계약 `x-internal-note` · 공유계약
B-3). 그 잔량 행이 곧 「열린 보류」라 **열린 보류 수가 언제나 ≥ 1** 이다 ⇒ 전이는 영영 안 일어난다.
거부하지 않았다 — 부분 해제는 「보류를 **줄인** 것」이지 「푼 것」이 아니고, 계약이 `releaseQty` 를
정면으로 설계했으므로 400 을 내면 그 칸이 죽는다.

⭐ 그 필연의 딸림으로 **`release_target_lot_status_code` 를 «비운다»** — 요청은 `NORMAL` 을 실어
왔지만 LOT 은 안 갔다. 채우면 `W-03-01` 이력의 「전이」 열에 **「보류 → 정상」이 거짓으로 그려진다.**
같은 이유로 **응답 ETag(= `trace.lot.version_no`)도 안 오른다** — 방금 쓴 If-Match 를 그대로 다시
쓸 수 있다. 계약이 ETag 를 「LOT 의 판 번호」로 못 박았으므로(`:1950`·`:2058`) 이것이 정합이다.

## ⓓ `stock-reinstate` 는 **정상 LOT 에 열린 전량 보류(가용 0)** 를 남긴다

`transitions.ts:216-219` 의 `'stock-reinstate'`(`DEFECTIVE`→`NORMAL` · `POST
/logistics/stock-reinstatements`)는 **LOT 의 상태만** 옮기고 `lot_hold` 를 안 닫는다.
⇒ ⓐ 를 우회해 LOT 을 정상으로 되돌리면 **열린 전량 보류가 그대로 남아** LOT 카드는 「정상인데
가용 0」이 된다. 그리고 그 보류는 이제 `NORMAL` 이라 C7·C8 의 `from` 밖이어서 **여전히 못 푼다.**

## ⓔ 딸림 — 「구멍」은 아니다: `remarks` 가 **한 칸**이라 해제가 등록 비고를 덮는다

`:release` 의 `remarks` 는 **치환**이다(생략하면 무변경 — 널로 지우지 않는다). 그런데 `lot_hold.remarks`
는 칸이 하나뿐이라 해제 비고를 쓰면 **원 행의 등록 비고가 사라진다**(부분 해제의 잔량 행만 «등록» 비고를
물려받는다). 이것은 **`target_lot_status_code` 를 두 칸으로 가른 것과 정확히 같은 축**인데(통보 070 —
「한 칸에 넣고 해제 때 덮으면 등록 도착값이 사라진다」) 계약에 둘째 칸(`releaseRemarks`)이 **없다.**
⛔ 스키마로 풀지 않았다 — 계약·마이그 무변경. 지금 동작을 e2e 로 못 박아 두었다(「관련」 참조).

## ⚠ 함께 남기는 것 — 이 오퍼레이션의 400 ↔ 409 경계

계약 `:4589` 가 스스로 미결로 적었다: 「03 은 업무 사유 거부를 409 로 말한다 … 어느 쪽이
정본인지는 **횡단 단일안 소관**」. I-19 R-9(문의 088)와 **같은 자리**다. 우리는 **400 으로 갔다**:

- **400 `STATE_LOCKED`** — 「이미 해제된 보류」·「전이가 0건」. 공유계약 G-1 「재로드해도 안 풀린다」.
- **409** — `VERSION_CONFLICT`·`DUPLICATE_HOLD`·`HOLD_QTY_EXCEEDED` **셋뿐**. 계약이 이 셋을
  **409 봉투 enum(`QualityConflictResponse.code`)에 직접 넣어** 답을 줬다.

⇒ 「계약이 409 라고 이름을 적은 것만 409」가 우리 규칙이다. 단일안이 반대로 정해지면 갈래는 **함수 하나**
(`releaseStateLocked()` — 호출부가 정확히 둘이고 둘 다 이 함수를 지난다)지만 「두 줄」은 아니다:
**봉투**(`ContractException` → `ConflictException`)·**코드**(`STATE_LOCKED` → **`INVALID_STATE`** — 계약
409 enum 6값에 `STATE_LOCKED` 가 **없다**)·**반환 타입**이 함께 바뀐다.

## 요청 — 넷 중 하나로 확정해 달라

1. ⭐ **C7·C8 의 `from` 에 `'DEFECTIVE'` 를 더한다.** 「불량은 발신 전이가 0」을 이 한 경로에서만
   여는 것이고, 이미 그 예외가 하나 있다(`stock-reinstate` · B-13). 우리가 보기에 가장 자연스럽다 —
   그러면 ⓓ 도 함께 풀린다(재등록 대신 `:release` 로 정본 경로가 생긴다).
2. **그대로 막는 것이 맞다** — C9 로 잡은 LOT 은 폐기(`SCRAPPED`)나 재고 재등록으로만 나간다면
   그 흐름을 `W-03-02`·`W-03-03` 에 그려 달라. 그때 ⓓ 의 「정상 + 열린 보류」를 누가 닫는지도 함께.
3. **ⓑⓒ 의 미리보기를 화면이 가른다** — 「해제하면 LOT 이 어디로 가나」를 「남은 열린 보류 수」와
   「부분/전량」으로 갈라 보여야 한다면 그 문언을 정해 달라.
4. **400/409 단일안** — 위 ⚠ 의 경계가 반대라면 알려 달라(088 과 한 답이면 좋겠다).
