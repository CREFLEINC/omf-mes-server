# 081. 보류 등록의 `lots[]` 에 **같은 `lotId` 가 두 번** 오면 — 400 `INVALID` 로 막는다

**구분: 통보**(회신을 기다리지 않는다 — `coverage-100/README.md` §2 1-1단계 「본질 아님 × 비용 낮음」)

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/quality/lot-holds` (I-20 PR ④) |
| 구현 상태 | 구현함 — 트랜잭션 «밖» 본문 검증에서 **400 `INVALID`**(`field: 'lots'`) |
| 판정 | §2 1단계 **가장자리**(중복을 담은 요청에서만 갈린다) → 2단계 **기준 1**(재고·원장·상태를 안 쓴다) · **기준 2**(거부하는 쪽) |
| 되돌릴 때 | `lot-hold-rules.ts` `assertDistinctLots()` 한 함수와 e2e 한 건. 다만 허용하려면 **아래 셋을 함께 고쳐야 한다**(그게 이 문서의 요지다) |

## 계약이 침묵한다

`LotHoldCreate.lots` 는 `LotVersionRef` 배열이고 `uniqueItems` 도, 「중복 금지」 문장도 **없다**.
물리도 안 막는다 — `trace.lot_hold` 에 **UNIQUE 제약이 0개**다(`W-03-03` §5-5 「서버가 진다」).

## 허용하면 셋이 «조용히» 깨진다

**ⓐ 404 판정이 뒤집힌다.** 잠금은 `SELECT … FROM trace.lot WHERE lot_id IN (…) FOR UPDATE` 한
문장이고 `IN (7, 7)` 은 **한 행**이다. 「잠근 행수 ≠ 요청 LOT 수 ⇒ 404」로 없는 LOT 을 가리는데,
중복이 통과하면 **멀쩡한 LOT 하나를 두 번 보낸 요청이 404** 가 된다.

**ⓑ 이력이 «둘째 보류를 잃는다».** `lot_status_event.source_document_id` 는 LOT 마다 자기
`lot_hold_id` 를 가리켜야 하고(I-20 R-12) 그 지도의 키가 **`lot_id`** 다. 같은 LOT 의 보류 둘이
한 항목으로 접혀 **두 번째 `lot_hold_id` 가 이력 어디에도 안 남는다** — R-12 가 막으려던 사고가
다른 문으로 들어온다.

**ⓒ 코어 규약이 깨진다.** `moveWithin()` 은 「`moved + skipped` = 입력 집합」을 약속하는데
입력에 중복이 있으면 그 등식이 성립하지 않아 호출자의 「하나라도 안 옮겨졌으면 전체 거부」
판정이 헛돈다.

## 왜 `INVALID` 인가(`RANGE` 가 아니라)

I-20 §1-6 의 400 갈래는 넷이다. `RANGE` 는 **개수·크기**가 범위를 벗어난 자리(빈 `lots` ·
`holdQty <= 0`)이고, 중복은 개수가 아니라 **같은 것을 두 번 담은 형식 위반**이다 ⇒ 계약이
이름 붙이지 않은 형식 위반을 모으는 `INVALID`. ⛔ 새 `ERROR_CODE` 를 만들지 않았다.
⛔ `UNIQUE_VIOLATION` 도 아니다 — 그것은 **저장된 행**의 유일성 충돌이지 본문 모양이 아니다.

## 왜 「접어서 한 건으로 처리」를 안 골랐나

조용히 중복을 걷어 한 건으로 만들면 **요청 `lots` 는 2건인데 응답 배열은 1건**이 된다.
계약 201 본문이 배열이고 화면은 보낸 LOT 과 받은 보류를 나란히 읽으므로(우리는 **반환 순서를
입력 순서로** 보장한다), 길이가 달라지면 그 짝이 어긋난다. §2 2단계 **기준 4**(값을 조용히
도출하지 않는 쪽)와도 어긋난다.

## 요청 — 둘 중 하나로 확정해 달라

1. **그대로 좋다** — 중복은 400 이다. 계약 `LotHoldCreate.lots` 에 「같은 LOT 을 두 번 담지
   않는다」 한 줄(또는 `uniqueItems: true`)을 적어 주면 화면·서버가 같은 곳을 본다.
2. **허용해야 한다** — 한 LOT 에 사유가 다른 보류 둘을 «한 요청»으로 걸어야 한다면 그렇게
   적어 달라. 그때는 위 ⓐⓑⓒ 를 함께 고쳐야 한다(404 판정을 `DISTINCT` 축으로, R-12 지도의
   키를 `lot_hold_id` 축으로, 코어 규약을 다중집합으로).
   ⚠ 다만 오늘 `lots[]` 는 **LOT 참조뿐**이라 사유·수량이 요청 전체에 하나씩만 있다 —
   같은 요청 안의 두 보류는 **글자 그대로 같은 행**이 된다. 그래서 우리는 1 을 권한다.
