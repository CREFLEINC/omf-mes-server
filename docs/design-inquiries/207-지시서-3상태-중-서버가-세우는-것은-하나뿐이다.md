# 207. 출하지시서 목록의 **「미편성 / 부분편성 / 편성완료」 3상태 중 서버가 세우는 축은 하나뿐**이다

**구분: 통보**(회신을 기다리지 않는다)

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /logistics/sales-orders`(`unassignedOnly`) · `GET /logistics/shipment-requests`(질의 14축) |
| 구현 상태 | **구현 예정(I-22 PR ②)** — 두 상태만 가른다 |
| 판정 | §2 **1단계 가장자리** → 2단계 기준 3(스키마를 안 늘린다) · 기준 4(값을 조용히 도출하지 않는다) |
| 되돌릴 때 | 질의 축이 생기면 조회 한 줄 |

## 화면이 그리는 것

`W-04-01` §3 ① 지시서 목록 행 — 「08-06 · 3라인 · **미편성**」. 배지는 **셋**입니다: 미편성 / 부분편성 / 편성완료.

## ⛔ 서버가 가진 축은 boolean 하나입니다

| 축 | 실측 |
|---|---|
| `GET /logistics/sales-orders?unassignedOnly=` | **boolean** — 「아직 편성되지 않은 것만」 |
| `SalesOrder` 응답 | 편성 상태를 담는 칸 **0개**(`statusCode` 는 「칸 불필요」로 닫혔고 수신본이라 MES 가 못 올립니다) |
| `GET /logistics/shipment-requests` 질의 **14축** | ⛔ **`salesOrderId` 가 없다** — 「이 지시서로 만든 작업지시들」을 되짚을 길도 없습니다 |

그리고 우리가 세우는 물리 칸은 **`shipment_request.sales_order_id`(nullable FK) 하나**입니다(마이그 A13).
⇒ `NOT EXISTS(shipment_request WHERE sales_order_id = …)` 로 **미편성 ↔ 편성됨** 둘만 갈립니다.
「부분편성」(라인 일부만 편성)은 라인 축 비교가 필요한데, 그 비교를 실을 응답 칸도 질의 축도 없습니다.

## ⇒ 우리가 정한 것

- `unassignedOnly=true` → `NOT EXISTS` 로 **미편성만** 냅니다(⛔ `NOT IN` 은 쓰지 않습니다 — nullable 칸이라 널이 하나라도 있으면 결과가 통째로 빕니다).
- `unassignedOnly=false` 는 **필터를 안 겁니다**(계약이 한 방향만 적었습니다).
- **「부분편성」 배지는 그리지 않습니다** — 도출 규칙을 지어내지 않습니다.

## 📨 알려 드리는 것

1. **「부분편성」을 서버가 판정해야 한다면 `SalesOrder` 에 파생 칸**(예: `assignmentStatusCode` 3값 또는 `assignedQtyTotal`)**을 열어 주십시오.**
2. ⭐ **`GET /logistics/shipment-requests` 에 `salesOrderId` 질의 축을 열어 주십시오.** 지금은 지시서에서 작업지시로 내려가는 길이 없습니다 — `W-04-01` 에서 지시서를 고른 뒤 「이 지시서로 뭘 만들었나」를 볼 수 없습니다.
