# 21. 승인 «유형»·«대상 유형»의 사람이 읽는 이름을 서버가 어디서 얻나 — `displayName`(required)·끄기 경고·`?q`

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `GET /app/approval-requests`(+상세·`:approve`·`:reject` 응답의 `ApprovalTarget.displayName`) · `POST /app/approval-routes/{id}:deactivate`(막히는 화면 목록) · `GET /app/approval-routes?q` |
| 구현 상태 | 구현 예정(I-1) — `displayName = "{targetTypeCode} #{targetId}"`(예 `GOODS_ISSUE #4412`) · `?q` 는 `approval_type_code ILIKE` · 막히는 화면 목록은 내리지 않음 |
| 판정 | §2 0단계 선례 없음 → 1단계 **본길**(9 유형 전건·모든 결재함 응답) → 2-4 조용한 도출 금지(서버가 한국어 라벨을 지어내지 않는다) · 2-3 표·칸 안 늘림 → 3단계 흔적: 매퍼 주석 `// 설계 미정 — 문의 021` |
| 되돌릴 때 | 매퍼 한 곳. 원천이 코드 그룹이면 `code_value` 조인, 화면 상수면 계약 enum `x-display` 를 읽는 표 한 장. 저장 데이터 없음 |

## 무엇이 문제인가

계약 `ApprovalTarget.displayName` 은 **required** · 「사람이 읽는 대상 이름. **서버가 만든다**」 · example `"기타 출고 · 문서 #4412"`. 그런데 이름의 원천이 없다 —

- `app.entity_type_registry` 에 표시명 칸이 없다(`entity_type_code`·`schema_name`·`table_name`·`id_column_name`·`is_active` + 감사 — 실측).
- 공통코드 `APPROVAL_TYPE`·`APPROVER_TYPE` 그룹은 「enum 으로 승격돼 그룹이 필요 없어진 것」으로 **폐기**돼 `code_value` 행이 없다(`seed.ts`). `CD-APPROVAL-TARGET-TYPE` 도 계약 enum 이라 코드 그룹이 없다.
- 하노이는 한/베 두 언어라 서버에 한국어 표를 박는 것도 답이 아니다(`localized_text` 는 «행» 축이지 «유형» 축이 아니다).

같은 뿌리의 물음 둘 —
1. W-06-15 §5-6 끄기 확인 다이얼로그는 「`W-01-06` 폐기 품의·기타 출고 화면에서 상신이 막힙니다」를 요구하고 「⚠ 막히는 화면 목록을 화면이 지어내지 않는다 — 계약이 내려 준다(§9-2)」로 못박았다.
   계약 `:deactivate` 는 「화면이 무엇이 막히는지 먼저 보인다」만 적고 대응을 주지 않는다. `ApprovalRoute` 에 칸이 없고 1:1 도 아니다(자재 폐기 `W-01-06` 와 제품 폐기 `W-04-10` 가 같은 `GOODS_ISSUE_DISPOSAL`).
2. `GET /app/approval-routes?q`(「승인 유형 검색」)는 검색할 «이름»이 없어 코드 문자열 부분일치만 된다.

## 지금 서버는

`displayName` 을 `"{targetTypeCode} #{targetId}"` 로 낸다 — W-CO-09 §5-3 이 「목록에 보일 업무 값이 사유 하나뿐」이라 적은 화면에서 대상 식별 정보까지 코드 문자열이 된다.
막히는 화면 목록은 내리지 않는다(다이얼로그는 진행 중 건수만 보인다). `?q` 는 코드 부분일치.

## 요청

승인 유형 9값·대상 유형 8값의 **표시명 원천**을 정해 달라 — ① 계약 enum 에 표시명(한/베)을 싣는다(화면 상수, 서버는 코드만) ② 공통코드 그룹을 되살려 `code_value` 로 관리한다 ③ 서버가 고정 표를 갖는다.
함께 — 유형 → 「막히는 화면」 목록(`:deactivate` 다이얼로그)의 원천도 같은 답으로 정해 달라.

우리 권고안(회신이 없으면 이대로 갈 값): **①** — 화면이 언어를 안다. 서버는 `displayName` 을 `"{type} #{id}"` 로 유지하고 화면이 코드를 이름으로 바꾼다. 이유: 두 언어 라벨은 화면 자원이고, 서버에 표를 두면 라벨 수정마다 배포가 필요하다.
