# 113. 보전 결과코드와 지시 마감의 의미

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/maintenance/results` · PUT `/maintenance/results/{maintenanceResultId}`의 closed=true |
| 구현 상태 | 계획 확정·구현 전. 미마감 본길은 진행, closed=true만422 INVALID/field closed |
| 판정 | 0단계 고정 계약·고객 코드 원천→1단계 특정 closed 입력→2단계 최초① 업무상태 쓰기0,② 명시거부 |
| 되돌릴 때 | 결과 의미·누적 규칙 회신 뒤 R/전이 core·도메인 쓰기·경합 테스트로 거부 완화 |

고정 equipment-05설비툴.json의 MaintenanceResultLine.resultCode는 고객 확장 MAINTENANCE_RESULT_LINE_RESULT 문자열이다. 같은 계약은 closed=true를 지시 항목 전부 완료/해당없음인 경우로 제한하지만 **어떤 결과값이 완료/해당없음을 뜻하는지** 연결 원천이 없다. EQUIPMENT와 MOLD의 의미도 다르다. mdm.code_value는 등재값·활성 여부를 제공할 뿐 완료 분류 메타데이터가 없다. 개발 DB에 값이0개라는 사실 자체가 미정 판정의 근거는 아니다.

**확인 요청:** 대상별 허용 결과와 완료/해당없음 의미를 어떤 정본에서 읽는가? 같은 지시 항목을 여러 실적에서 기록했을 때 어느 실적·순서·누적 규칙으로 지시 항목 상태와 전체 마감을 판단하는가? 미입력 항목·빈 lines·지시없는 실적의 closed 요청은 어떻게 처리하는가?

서버는 결과 이름/번역·DONE/NA 문자열 비교·빈 배열 every()로 마감을 도출하지 않는다. MAINTENANCE_CLOSE_POLICY='REJECT_UNMAPPED_RESULT_CODE'·UNRESOLVED_MAINTENANCE_CLOSE를 로컬 이름으로 두며 새 ERROR_CODE/분류표/시드를 만들지 않는다. closed=true 요청은 실적·라인·예비품·부모상태·누계·멱등완료 기록을 모두 남기지 않는다.

closed=false/생략은 정상 입력이며 유효 코드가 주어진 미마감 실적을 저장·편집할 수 있다. lines 생략/[]도 계약 범위대로 유지한다. 이 정상 성공으로 지시완료 화면까지 인수했다고 보고하지 않는다. 완료 보전의 집계 엔티티·시각·범위는 **기존111**에서 별도로 확인하며, result.finishedAt를 곧 order 완료시각으로 대입하지 않는다.

흔적: I-31 R1·§8-1, E-R18/19·빈 lines 마감0·확장 label 도출0·전건 rollback. 해소 후 별도 R·필요 A 소유 전이 코어·도메인 쓰기/경합 테스트로 거부를 완화한다. 계약 사본은 a6a87e1 고정이다.
