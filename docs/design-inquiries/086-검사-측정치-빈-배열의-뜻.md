# 086. 검사 결과 수정의 `measurements: []` — 「전부 지운다」인가 「손대지 않는다」인가

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | PUT `/quality/inspection-results/{inspectionResultId}` (I-19 PR ③c) · POST `/quality/inspection-results`(같은 배열을 받는다) |
| 구현 상태 | 구현함 — **빈 배열 = 그 결과의 측정치 전건 삭제** · **생략 = 손대지 않음** |
| 판정 | README §2 1단계 가장자리(`measurements: []` 를 실제로 보낸 요청에서만 갈린다) → 2단계 **기준 4**(값을 조용히 도출하지 않는 쪽 — 「보낸 배열이 곧 전부」). ⚠ **기준 1**(재고·원장·상태를 쓰지 않는 쪽)은 반대를 가리킨다 — 아래 「우리가 걸리는 곳」 |
| 되돌릴 때 | 「빈 배열도 무변경」이면 `inspection-result-write.service.ts` 의 `update()` 에서 `body.measurements.length === 0` 을 생략과 같게 처리하고 e2e 단언 한 줄(전건 삭제)을 뒤집는다. 서비스 3줄 · 물리 변경 0 |

## 사실 — 계약이 **완전히 침묵한다**

- `InspectionResultUpdate.measurements` 에 **`description` 도 `x-` 노트도 없다**(python 실측 — `contracts/quality-03품질.json`). `InspectionResultCreate.measurements` 에는 설명이 있으나(「검사 기준이 없는 의뢰에는 이 배열을 **생략하거나 빈 배열로** 보낸다」) 그것은 «새로 만들 때» 이야기라 **수정에서 빈 배열이 무엇을 뜻하는지**는 답하지 않는다.
- 물리에는 `uq_inspection_measurement (inspection_result_id, inspection_item_spec_id, sample_no)` 가 있어 **부분 갱신의 키가 있다** — 즉 「보낸 항목만 갱신」도 표현 가능한 형상이다. 계약이 「부분」을 적지 않았을 뿐이다.
- 화면 정본(`P-02-13` §5-2·§5-9)은 「항목별 규격 표를 채우고 임시 저장은 항상」까지만 적고, **표에서 행을 지우는 조작**을 그리지 않았다.

## 우리가 고른 것과, 그 선택이 걸리는 곳

I-19 정본(§1-3)이 **치환**으로 정했고 구현도 그렇다 — 「보낸 배열이 곧 전부」(§2 기준 4: 계약이 안 적은 「부분 병합」을 서버가 조용히 도출하지 않는다). 생략과 빈 배열을 가른 것도 같은 이유다.

그런데 §2 2단계는 **기준 1**(재고·원장·상태를 쓰지 않는 쪽)이 **기준 4보다 위**다. 그 기준으로 보면:

- 「빈 배열 = 전건 삭제」는 **행을 지운다** — 되돌릴 오퍼레이션이 없고 이력 표도 없다(`inspection_measurement` 는 감사 칸이 `created_at`·`created_by` 뿐이다).
- 화면이 「측정치는 안 건드리고 비고만 고친다」를 하면서 상태 객체를 통째로 `PUT` 하면(흔한 프런트 패턴) `measurements` 가 **빈 배열로 실려 나갈 수 있다.** 그러면 **조용한 데이터 소실**이다 — 응답은 200 이고 화면은 아무 경고를 못 받는다.
- 반대로 「빈 배열도 무변경」을 골랐다면, 「측정치를 전부 지우고 싶다」는 요구는 오늘 표현할 길이 없어진다(그 요구가 실재하는지도 계약·화면이 안 적었다).

즉 두 기준이 **정면으로 갈리고**, 어느 쪽이든 되돌리는 비용은 서비스 3줄로 같다. 그래서 고르되 물어 둔다.

## 요청

`PUT /quality/inspection-results/{inspectionResultId}` 의 `measurements` 를 셋 중 하나로 확정해 달라.

1. **치환**(지금 구현) — 생략 = 무변경 · 빈 배열 = 전건 삭제. 화면은 「안 건드릴 때 이 칸을 생략」할 책임을 진다.
2. **무변경 우선** — 생략도 빈 배열도 무변경. 전건 삭제는 **표현하지 않는다**(필요해지면 별도 오퍼레이션).
3. **부분 갱신** — 보낸 항목만 `uq_inspection_measurement` 키로 갱신·추가하고 안 보낸 항목은 남긴다. 이때 「지우기」를 어떻게 표현할지(예: 항목별 삭제 플래그)를 함께 정해 달라.

⭐ 1을 유지한다면 계약 `InspectionResultUpdate.measurements` 에 **한 문장**만 적어 달라 — 「생략하면 유지, 빈 배열이면 전건 삭제」. 그 한 줄이 없으면 클라이언트마다 다르게 읽는다.
