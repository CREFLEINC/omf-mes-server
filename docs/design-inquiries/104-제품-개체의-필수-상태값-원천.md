# 104. 제품 개체를 처음 만들 때 필수 상태값을 무엇으로 채우는가

> **서버팀 결정·통보 예정(2026-09-09):** 초기값은 `REGISTERED`로 한다. 현재 계약이 상태를 표시용 문자열로만 두고 코드 그룹·전이 규칙을 정의하지 않으므로, 새 코드 그룹·상태 전이·DB 기본값을 만들지 않고 생성 서비스가 상수를 기록한다. 이 결정은 질의 대기가 아니라 설계 정산 때 통보할 사항이다.

| 칸 | 내용 |
|---|---|
| 대상 | POST `/trace/serial-numbers` — I-26 |
| 상태 | 서버팀 결정 완료·I-26 POST 반영 중 |
| 판정 | 비핵심·저비용 결정. `REGISTERED`를 생성 서비스 상수로 기록하고 설계팀에 통보 |
| 최소 해소 | 해소 완료. 설계 정산 시 위 결정 전달 |

## 확인한 근거

- 고정 계약 a6a87e1, `production-02생산실행.json`의 SerialNumber.statusCode는 required 문자열이다(:5987·:5999). 코드 그룹을 만들지 말고 표시만 하도록 하지만 초기값은 정하지 않는다.
- Create는 lotId·quantity·선택 producedAt만 받으며 상태 입력이 없다(:6007). 물리 serial_number.status_code는 기본값 없는 NOT NULL이다.
- POST 설명과 P-02-05 §8-2가 서버에 위임한 것은 **번호**다. 번호 위임을 상태 선택 위임으로 넓힐 수 없다.
- 기존 문의053은 계약의 ‘서버가 정한다/기록한다’ 문언을 근거로 한 예외다. required·표시 전용·전이 없음만으로 그 예외를 적용하지 않는다.

## 요청과 현재 제한

**개체 최초 상태의 값/원천과 뜻을 정해 달라. 서버가 잠정 문자열을 선택하는 범위라면 그 위임을 명시해 달라.** 코드 그룹 신설을 요청하는 것은 아니다.

NORMAL·ACTIVE·LOT 품질/생애 상태를 복사하거나 상태를 nullable로 완화하지 않는다. 조회는 이미 저장된 원문 상태를 그대로 반환하며, 빈 목록은 저장 개체0이라는 뜻이다.

P-02-05 및 이를 재사용하는 P-02-12의 새 인식표 발번은 아직 완결되지 않는다. 상태가 정해진 뒤에도 문의105의 수량 단위 대응과 I-26 R4~R6의 조건부 채번·헤더 계획을 먼저 확인한다. 설계 저장소에는 직접 글을 올리지 않았다.
