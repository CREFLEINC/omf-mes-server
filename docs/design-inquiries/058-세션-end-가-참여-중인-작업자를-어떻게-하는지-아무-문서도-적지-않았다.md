# 58. 세션 `:end` 가 참여 중인 작업자를 어떻게 하는지 아무 문서도 적지 않았다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /production/work-sessions/{workSessionId}:end` · `GET /production/work-sessions/{workSessionId}/workers` |
| 구현 상태 | **구현함(I-11 · `left_at` 을 자동으로 안 찍는다 · 종료된 세션에서도 `:leave` 를 허용한다 · 종료된 세션에 «참여»는 400 `STATE_LOCKED`)** |
| 판정 | `coverage-100/README.md` §2 1단계 **본길**(`:end` 마다 갈린다) → 계약 문자 그대로 = **아무 말도 없으니 쓰지 않는다** · 2단계 기준 4(값을 조용히 도출하지 않는다). 이탈 허용은 기준 2 의 단서 — I-4 §5-3 ⌜거부가 업무를 없애면 안 된다⌝ |
| 되돌릴 때 | 「종료 시각으로 자동 마감하라」면 `work-session-end.service.ts` 에 `work_session_worker.updateMany` **한 줄**(완화 · 마이그 0). 그때 종료 세션의 `:leave` 는 400 이 되므로 §6-3 4 도 함께 뒤집는다 |

## 무엇이 문제인가

ⓐ 계약 `:end` 설명이 `ended_at`·`status_code` 만 말하고 `work_session_worker` 를 **한 번도 언급하지 않는다**.
ⓑ 같은 계약이 ⌜행을 지우지 않는다 — **누가 언제까지 있었는지가 기록이다**⌝ 로 `left_at` 을 **이력**으로 세워 두고, 세션 종료 시각으로 그 이력을 마감할지는 비웠다.
ⓒ 그대로 두면 `GET …/workers?active=true` 가 **끝난 세션에서 사람을 영원히 들고 있다** — 「지금 이 세션에 누가 있나」가 종료 뒤에도 답을 낸다.
ⓓ 세션 종료 **화면 자체가 인벤토리에 없다**(`P-02-10` §8 미결 5 는 `:end` **오퍼레이션**으로 닫혔을 뿐 화면은 서지 않았다) ⇒ 사람이 손으로 이탈을 찍어 줄 자리도 없다.
ⓔ ⭐ 그래서 종료된 세션의 «참여»와 «이탈»이 **비대칭**이 됐다 — 참여는 400 `STATE_LOCKED` 로 막고 이탈은 **허용**한다. 자동 마감을 안 하는 이상 이탈까지 닫으면 「영원히 참여 중」이 **확정**되기 때문이다. 회신이 「자동으로 찍는다」면 이 비대칭이 사라진다.

## 지금 서버는

- `:end` 는 `ended_at`·`status_code='ENDED'`·`version_no+1` 과 `work_session_event` **END** 한 행만 만든다. `work_session_worker` 에 **접근하지 않는다**(단위 테스트가 접근 자체를 단언한다).
- `:leave` 는 세션 상태를 보지 않는다 — 이미 `left_at` 이 있으면 400 `STATE_LOCKED`(두 번 안 찍는다) · `leftAt < joined_at` 이면 400 `RANGE` · `version_no` 는 올리지 않는다.
- `POST …/workers`(참여)는 세션이 `ENDED` 면 400 `STATE_LOCKED` 다(전이표를 타지 않는 서비스 손검사).
- 덤: `:end` 는 `work_order` 도 건드리지 않는다(W/O 는 `:close` 가 닫는다) · 본문 `stopReasonCode` 는 받되 저장하지 않는다(계약이 프로퍼티를 열어 두어 400 을 낼 수 없다).
