# 274. 위치별 실사 라인 전량 치환의 세부 규칙을 정했다

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 회신을 기다리지 않는다 |
| 걸리는 오퍼레이션 | `PUT /inventory/counts/{inventoryCountId}/lines` |
| 구현 상태 | I-15에서 구현 예정 |
| 판정 | 계약이 위치별 전량 치환과 누락 라인의 미실사 복귀를 이미 정했다. 남은 저장 세부는 작은 서비스 변경으로 되돌릴 수 있어 개발팀이 정한다 |
| 되돌릴 때 | 치환 매핑·행위자 선택·시각 저장 규칙과 테스트만 바꾼다 |

## 결정

1. 본문에서 빠진 해당 위치의 기존 라인은 삭제하지 않고 `counted=false`, 수량 0, 사유·행위자 null로 되돌린다. 다른 위치는 건드리지 않는다.
2. 기존 라인의 `system_qty`와 `line_no`는 개시 스냅샷이므로 보존한다.
3. id 없는 현장 신규 라인의 `system_qty`는 PUT 시점 현재 잔액의 같은 `(location,item,lot,uom)` 합계, 없으면 0이다.
4. 같은 네 축 중복은 400, 차이가 있으면 활성 `VARIANCE_REASON`이 필수다.
5. 각 라인의 `countedAt`이 계수 시각의 정본이다. 최상위 `businessDate`·`occurredAt`은 형식만 검증하고 저장하지 않는다.
6. `X-Worker-No`가 있으면 그 작업자의 연결 `app_user_id`, 없으면 세션 사용자를 `counted_by`로 쓴다. 작업자에 계정 연결이 없으면 null을 허용한다.
7. `PLANNED` 과거 행의 첫 정상 치환은 `IN_PROGRESS`로 옮긴다. `COMPLETED`는 400 `STATE_LOCKED`다.
