# 213. 재생재 원장에 붙일 **판별자가 없다** — 빌리면 남의 전표에 유령 라인이 붙는다

**구분: 질의**(회신이 필요합니다) — §2 **1-1단계 두 축에 둘 다** 걸립니다: **MES 본질**(원장 한 줄의 출처 식별은 추적성의 근간) × **바꾸는 비용**(`block_ledger_header_mutation` 때문에 **이미 쌓인 원장 행은 소급 정정이 불가능**합니다 — 잘못 빌리면 영구입니다).

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /logistics/recycle-entries`(I-17 · 이슈 #407) |
| 구현 상태 | ⛔ **막혔습니다** — 이 답이 없으면 원장을 쓸 수 없습니다 |
| 판정 | ⛔ **서버가 정하지 않았습니다.** 네 후보가 전부 막혀 계약이 답할 자리입니다 |

## 계약이 요구하는 것

`POST /logistics/recycle-entries` description 과 `RecycleEntryCreate` description **둘 다** 같은 문장을 적었습니다:

> 「새 자재 LOT 을 만들고 **그 수량만큼 재고를 늘린다 — 한 트랜잭션이다**」

⇒ **원장을 안 쓰는 선택지가 없습니다.**

## 그런데 붙일 판별자가 없습니다

`InventoryTransaction.sourceDocumentTypeCode` 는 **enum 4값**입니다 — `GOODS_RECEIPT` · `GOODS_ISSUE` · `INVENTORY_ADJUSTMENT` · `STOCK_TRANSFER`. **재생재가 없습니다.**

같은 description 이 이렇게 못 박았습니다:

> 「**A-10 다형 참조 판별자**이고 값은 «대상 테이블 이름»이다 — `sourceDocumentId` 는 **그 표의 식별자**다.
> ⛔ 공통코드 그룹으로 받지 않는다 — 가리킬 표가 늘면 **계약을 고친다**.」

### 후보 넷을 전수로 재고 전부 막혔습니다

| 후보 | 막히는 이유 | 실측 |
|---|---|---|
| **`GOODS_RECEIPT`** | `document-type-registry.ts` 가 `cancelable: true` 로 등록했고, `document-cancel-execute.service.ts:149-151` 이 「한 문서에 원장이 2행이면 **`throw`**」다. `recycle_entry_id` 와 `goods_receipt_id` 가 겹치는 순간 **애먼 입고 취소가 500 으로 죽습니다** | ✅ 코드 두 자리 확인 |
| **`INVENTORY_ADJUSTMENT`** | ⭐ **I-14 가 이미 병합돼 소비처가 생겼습니다** — `test/inventory-adjustment.e2e-spec.ts:688-691` 이 `findMany({INVENTORY_ADJUSTMENT, id})` → `toHaveLength(1)`, `:914` 가 같은 짝으로 정렬 없는 `findFirstOrThrow`. 그리고 계약 description 이 「`W-01-12` §5-2 가 `source_document_id = inventory_adjustment_id` 로 잇는다」를 직접 적었습니다 | ✅ 시험 두 자리 · 계약 원문 |
| **`STOCK_TRANSFER`** | **이미 두 세입자가 있습니다** — 재고이동과 적치(통보 059 · `transaction_no LIKE 'PT-%'`). 셋째를 들이면 같은 문제가 커집니다 | ✅ `putaway-posting.ts:7-18` |
| **`GOODS_ISSUE`** | 재생재는 **들어오는 것**이라 뜻이 정반대입니다 | — |

### ⛔ 그리고 `transactionTypeCode` 로 양성 판별하는 길도 계약이 막았습니다

`sourceDocumentTypeCode.description` 끝문장:
> 「방향은 라인의 `from*`/`to*` 가 이미 말하므로 **`transactionTypeCode` 를 따로 두지 않는다**(L-2-1 · **2026-09-02 판정**).」

`transactionTypeCode.x-no-code-key`:
> 「⛔ 원장 한 줄이 «무엇인가»를 말하는 축이 이미 셋이다 … **한 칸 더 두면 어긋났을 때 어느 쪽이 맞는지 판정할 수 없다**(L-2-1). ⚠ 「거래유형·수불유형」을 읽는 화면은 **전건 0건**이다(A-21).」

⇒ 그 칸을 정본 판별자로 세우는 것은 **계약이 이름을 대며 금지한 것**입니다. 「읽는 화면 0건」도 안전의 근거가 아니라 **그 판별이 아무 데도 도달하지 않는다**는 뜻입니다.

## ⭐ 선례가 있는데 왜 그대로 못 쓰나 — **소비처가 생겼습니다**

통보 **059**(2026-09-08)가 적치에 대해 「`STOCK_TRANSFER` 를 빌리고 `transaction_no LIKE 'PT-%'` 로 가른다」로 정했습니다. 서버는 그 접두어로 언제나 가를 수 있습니다.

⛔ **그런데 «화면»은 못 가릅니다.** `GET /inventory/transactions` 의 질의 파라미터 **10개를 전수 파싱**했는데 **`sourceDocumentId` 가 없습니다**(`businessDateFrom`·`To`·`itemId`·`lotId`·`warehouseId`·`locationId`·`transactionTypeCode`·`sourceDocumentTypeCode`·`page`·`size`).

⇒ 화면은 **유형으로만 서버 필터를 걸고 id 는 클라이언트에서 맞춥니다.** 두 표의 id 가 겹치면
**조정 #7 상세에 재생재 #7 의 원장 라인이 «유령»으로 붙습니다.** 서버가 접두어를 붙여도 이건 못 막습니다.

⚠ 그리고 두 시퀀스가 실제로 겹칩니다 — 둘 다 `START 1`. 다만 **레인 DB 현재값이 1675 대 1** 이라
**지금 e2e 를 돌리면 초록**입니다. 운영에서 재생재가 1675건 쌓이는 날 터집니다.

## 여쭙는 것 — 셋 중 무엇입니까

| | 안 | 대가 |
|:-:|---|---|
| **ⓐ** ⭐ | **enum 에 `RECYCLE_ENTRY` 를 더한다** | 계약 변경 1줄. description 이 스스로 「**가리킬 표가 늘면 계약을 고친다**」라 적어 둔 그 경우입니다. ⭐ **저희가 가장 정직하다고 봅니다** |
| **ⓑ** | 빌리고 `transaction_no LIKE 'RC-%'` 로 가른다(059-형) | 서버는 가르지만 **화면은 못 가릅니다** — 위 유령 라인. 그리고 원장은 소급 정정이 안 됩니다 |
| **ⓒ** | `GET /inventory/transactions` 에 `sourceDocumentId` 질의 축을 연다 | ⓑ 의 화면 문제만 닫습니다. 취소 경로(`GOODS_RECEIPT`)와 시험 단언 문제는 남습니다 |

⛔ **저희가 고르지 않았습니다** — 셋 다 계약을 건드리고, 원장은 잘못 쌓으면 되돌릴 수 없습니다.

⚠ **이 답이 없으면 I-17 은 원장을 못 씁니다.** 계약이 「재고를 늘린다」를 요구하는데 그것을 기록할 판별자를 안 주는 상태라, README §3 「**계약끼리 모순**」으로 보고 슬라이스를 멈춰 두었습니다.
