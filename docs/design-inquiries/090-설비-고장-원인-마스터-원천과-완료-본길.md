# 090. 설비 고장 원인 마스터 원천과 완료 본길

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/maintenance/breakdowns/{breakdownId}:complete` · PUT `/maintenance/breakdowns/{breakdownId}` |
| 구현 상태 | I-30 R-1: 완료1건 보류, PUT 메모/생략/null 진행 예정·비null 원인만400 INVALID |
| 판정 | 0단계 고정 계약/화면/물리 대조→완료는1단계 본길, 원천 정의 침묵으로 보류. PUT 비null은 가장자리→2단계② 명시 거부 |
| 되돌릴 때 | 원천 확정→필요 물리/FK→A 전이 코어PR→완료 도메인PR. PUT 거부를 해당 원천 검증으로 완화 |

계약 `equipment-05설비툴.json:3315,3507,3525`의 causeCode는 **mdm.cause_code 행 식별자**, 공통코드 금지다. 실제 선택 API `mdm-기준정보.json:6735,18645`와 Prisma는 quality.cause_code를 가리키며 W-05-04 §5-3·§8-2는 품질 원인 사용을 금지한다. 화면의 공통코드 구상도 고정 계약을 대체하지 못한다.

**요청: 설비 원인 원천의 소유 도메인, 행 식별 키/타입, 선택 목록 경로, 신규 쓰기 검증 규칙을 확정해 달라.** 원천명이나 HYD_LEAK 예시 하나만으로는 부족하다. 품질/공통코드로 바꾸려면 계약과 화면 금지를 함께 해소해야 한다. 마스터가 있으나 값0개인 경우와 원천 자체 미정은 다르다.

현재 새 마스터·코드그룹·임의값·가짜성공·전건거부 complete 핸들러는 만들지 않는다. PUT의 causeCode 생략은 유지, null은 해제, handlingNote만 저장 가능하다. 비null은 품질에 실제 등재되거나 기존값과 같아도 INVALID이며 원래값을 보존한다. root_cause는 건드리지 않는다.

`UNRESOLVED_BREAKDOWN_CAUSE_MESSAGE`와 E-B19/E-B26·향후 E-C04에 문의090을 연결한다. 본길1건 보류를 레인전체 중단이나 메모저장 불가로 확대하지 않는다. 계약 사본 a6a87e1은 변경하지 않았다.
