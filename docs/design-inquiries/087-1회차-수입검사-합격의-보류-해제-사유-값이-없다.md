# 087. 검사 확정이 보류를 푸는데 「1회차 수입검사 합격」의 해제 사유 값이 목록에 없다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/quality/inspection-results/{inspectionResultId}:confirm` (I-19 PR ④) · 뒤이어 POST `/quality/lot-holds/{lotHoldId}:release` (I-20) |
| 구현 상태 | 구현함(§2 절차 1단계 본길 → 값 목록 부재 → README §0 「값 정의는 권고안대로」) — **`release_reason_code = 'INCOMING_INSPECTION_PASSED'`** 를 넣는다. 어느 목록에도 없는 값이다 |
| 판정 | 물음 A(푸느냐) = **1단계 본길 · 계약 문자 그대로 = 푼다**(I-19 §0-재수립 R-4 ⓐ). 물음 B(사유 값) = **0단계 — 선례가 답을 준다.** ⭐ **이 이름은 우리가 지어낸 것이 아니라 문의 11 이 문자 그대로 권고한 값**이다(아래 §「문의 11 이 이미 권고했다」). 소거법(§2 2단계 기준 4)은 그 위에 겹치는 둘째 근거다 |
| 되돌릴 때 | 값이 정해지면 ⓐ `inspection-confirm.service.ts` 의 `HOLD_RELEASE_REASON` 한 줄 ⓑ `UPDATE trace.lot_hold SET release_reason_code = '<새 값>' WHERE release_reason_code = 'INCOMING_INSPECTION_PASSED'` **한 문장**. 이 값이 다른 어디에도 없어 **대상 행이 정확히 우리 것뿐**이다 ⓒ e2e 단언 한 줄 |

## ⭐ 문의 11 이 이미 이 이름을 권고했다 — 087 은 그 «되묻기»다

`~/omf-design-requests/설계-문의-2026-09-05-C.md` **문의 11**(「수입검사 합격」에 해당하는 보류 해제 사유 코드가 없다)이 같은 4값 표를 놓고 이렇게 적었다:

> 수입검사 «최초» 합격도, 샘플링 미대상도, 한도승인도 여기 없다. 셋 다 `MANAGER_OVERRIDE` 로 밀어 넣으면 이력이 「관리자가 직권으로 풀었다」로 남는다 — **사실과 다르다.**
> **서버 대응(1차)**: 값이 정해지기 전까지 `MANAGER_OVERRIDE` 를 쓰지 않고 … **새 코드가 오면 그것으로 바꾸겠다는 전제로 임시값 하나를 쓴다.**
> **요청**: 값을 늘려 달라. … 세 값(**`INCOMING_INSPECTION_PASSED`** · `SAMPLING_NOT_REQUIRED` · `URGENT_IQC_WAIVED` 같은 꼴)이 자연스럽다.

⇒ 구현이 넣은 `INCOMING_INSPECTION_PASSED` 는 **문의 11 이 이름까지 적어 권고한 그 값**이고, 「임시값을 쓰고 새 코드가 오면 바꾼다」도 11 이 이미 선언한 대응이다. 이 문서는 새 물음이 아니라 **그 권고를 그대로 실행에 옮겼다는 통지 + 되묻기**다.

⚠ **왜 다시 묻나** — `docs/coverage-100/README.md` §0 의 대기 목록이 문의 11 을 「보류 해제 사유(**철회 예정**)」로 적어 두었다. 철회 사유는 `docs/계약-되돌림-mdm.md` §Z-8 — 설계팀 회신(2026-09-05)이 「LOT 재고 상태」와 「의심자재 보류 기록」을 **다른 축**으로 갈랐고, **입고 확정의 다섯 단계에 보류 해제가 없어** 11 의 전제가 사라졌다(같은 취지가 `src/logistics/goods-receipt/receipt-posting.ts:15-18` 에도 있다 — 「⛔ LOT 보류를 풀지 않는다 … 뒤의 것은 `W-03-02` 소관이다」). ⇒ 물음이 **틀렸던 것이 아니라 잘못된 문 앞에서 물었던 것**이다. 같은 §Z-8 이 `trace.lot_hold` 를 옮기는 주체를 **`W-03-02` Lot Status 판정·전이 처리**로 명시했고, **`:confirm` 이 바로 그 오퍼레이션**이다 ⇒ 물음은 사라진 것이 아니라 **소관 오퍼레이션으로 옮겨왔다.** §Z-8 이 남긴 열린 물음(「확정 시점에 아직 열린 의심자재 보류가 있으면」)은 이 슬라이스가 **R-11 로 이미 답을 냈다** — 그 보류가 남으면 `NORMAL` 로 올리지 않는다.

## 사실

- 계약이 **확정이 보류를 푼다**고 두 자리에 적었다(`quality-03품질.json:3621`·`:3749`). 화면 정본도 같다 — `W-01-01` §5-2 「판정 확정 = `confirmed_at` 기록 + **Lot Status 전이** + **`lot_hold.released_at`·`released_by` 기록**」.
- 물리가 **사유를 강제한다** — `ck_lot_hold_release_reason`(`20260901030000:92`): `released_at IS NULL OR release_reason_code IS NOT NULL`. 즉 「풀되 사유는 비운다」가 불가능하다.
- 시드 `LOT_HOLD_RELEASE_REASON` 은 **4값뿐**이고(`prisma/seed.ts:438-446`) 전부 다른 사실을 가리킨다 — `RETEST_PASS`(재검사 합격) · `RETEST_FAIL`(재검사 불합격) · `INVESTIGATION_CLEARED`(조사 종결) · `MANAGER_OVERRIDE`(관리자 직권 해제). **「1회차 수입검사가 그냥 합격했다」에 맞는 값이 0개다.**
- ⛔ `RETEST_PASS`/`RETEST_FAIL` 로 대신할 수 없다 — `W-03-02` §5-4 가 그 둘을 **C7·C8 전용**(`:release`, I-20)으로 못박고 「**재판정으로 풀린 건이 몇 건인가**」를 이 값으로 센다. 1회차 합격(C4)을 거기 섞으면 그 집계가 조용히 부풀고, **나중에 우리 행만 골라낼 수 없다**(`lot_hold` 에 원천 전표 칸이 없다).
- 계약이 이 축의 값 목록을 **스스로 열어 두었다** — 「⭐ 고객이 늘린다 — 값은 초기 시드다(공유계약 G-31)」(`quality-03품질.json:4183`).

## 왜 「해제를 I-20 으로 미룬다」를 못 골랐나

§2 2단계 **기준 1**(재고·원장·상태를 쓰지 않는 쪽)은 미루는 쪽을 가리킨다. 그런데 그 안은 **두 자리에서 스스로 깨진다**.

1. **R-11 과 모순된다.** 확정은 「LOT 에 «다른» 열린 보류가 남아 있으면 `NORMAL` 로 올리지 않는다」(중복 보류 허용 · `W-03-02` §4-B). 수입검사 보류를 안 닫으면 열린 보류가 **언제나 1 이상**이라 **어떤 합격도 LOT 을 풀 수 없다** — 데드락이다.
2. **본길 화면이 안 비워진다.** `W-01-01` 좌측이 「검사 대기 큐(**Hold LOT 목록**)」다. 합격한 LOT 이 큐에 영원히 남는다.

⇒ 후보에서 탈락. 남은 것은 「어떤 값을 넣는가」뿐이고, 기존 4값을 재사용하는 안은 **기준 4**(값을 조용히 도출하지 않는 쪽)에 먼저 걸린다.

## 요청 — 셋 중 하나로 확정해 달라

1. ⭐ **값을 하나 늘린다**(권고 · 지금 구현) — `LOT_HOLD_RELEASE_REASON` 에 「수입검사 합격」(`INCOMING_INSPECTION_PASSED` 등 이름은 설계팀이 정한다)을 더한다. 등록 사유 `INCOMING_INSPECTION_WAIT`(수입검사 대기)와 **대칭**이라 §5-4 가 말한 「등록·해제 대칭」이 완성된다.
2. **기존 값 중 하나로 대신한다** — 어느 값인지 지정해 달라. 그 값의 기존 뜻과 이 사실이 섞이는 것을 감수한다는 뜻이 된다.
3. **확정은 보류를 안 푼다** — 그러면 R-11 의 데드락과 `W-01-01` 큐를 어떻게 푸는지 함께 적어 달라(`:release` 를 사람이 한 번 더 눌러야 하는 흐름인지).

⚠ **언제 눈에 띄나** — 오늘은 아무도 못 본다: `release_reason_code` 는 `app.code_t` 라 FK 가 없고 이 경로가 `assertCodeValues` 로 그 칸을 대조하지 않는다. 그런데 **I-20 의 `GET /quality/lot-hold-events` 가 열리는 순간** 이 값이 화면에 실리고, 표시명을 `LOT_HOLD_RELEASE_REASON` 에서 찾으므로 **라벨이 비거나 코드 문자열이 그대로 노출된다.** ⇒ I-20 착수 «전»에 답이 오면 가장 싸다.

⚠ 덧 — `lot_hold.status_code` 는 이번에도 **안 건드렸다.** `LOT_HOLD_STATUS` 코드 그룹이 시드에 0건이라(문의 13) 「해제됨」을 가리킬 값이 없다. 087 과 13 을 **묶어 답해 달라** — 둘 다 같은 표의 같은 순간이다.
