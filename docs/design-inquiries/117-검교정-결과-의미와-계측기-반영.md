# 117. 검교정 결과 의미와 계측기 반영

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/maintenance/calibrations`의 CALIBRATION 확장 결과와 관련 조회·해소 화면 |
| 구현 상태 | I-33 R3/R11 계획 확정·구현 전. 기본3결과와 nonCAL 정상 진행, 미분류 CAL 결과만422 STATE_LOCKED/field resultCode |
| 판정 | 기본 PASS/ADJUSTED/FAIL은0단계 고정 시드 의미+계약 효과. 확장 CAL은 특정 입력 가장자리→최초① 이력/master/멱등완료 쓰기0→② 명시거부 |
| 되돌릴 때 | 결과의 유형별 부분집합·합격효과 분류 정본을 받으면 로컬 분기·검증·소비자 인수를 보완하고 거부 완화 |

고정 `equipment-05설비툴.json` POST 설명은 CALIBRATION 합격계열이면 같은 트랜잭션에서 설비의 최근검교정일·다음기한을 반영하도록 한다. 현재 `prisma/seed.ts:304`의 CALIBRATION_RESULT는 PASS=적합, ADJUSTED=조정후적합, FAIL=부적합이다. 이 고정 의미를 연결해 `CALIBRATION_MASTER_PASS_RESULTS={PASS,ADJUSTED}`, `CALIBRATION_MASTER_FAIL_RESULTS={FAIL}`로 계획했다. 번역명·정렬·코드명 접두어를 런타임 분류기로 쓰지 않는다.

**확인 요청:** 고객 확장 결과의 합격계열/부적합 효과와 이력 유형별 허용 부분집합을 어느 정본에서 읽는가? 코드 등록부의 그룹/활성만으로는 이 의미를 알 수 없다. 표시명을 바꿔도 반영 효과가 바뀌지 않는 식별축·관리 주체가 필요하다.

CALIBRATION의 PASS/ADJUSTED는 이력과 master 두 날짜/version을 같은 tx에서 반영한다. FAIL은 이력만, nonCAL의 활성 확장 결과도 이력 정상 등록이다. 미분류 CAL만 이력과 master 모두 남기지 않는다. 그룹 값이0개인 개발 DB를 미정 근거로 삼거나 기본3값 정상 경로까지 보류하지 않는다. performedOn/nextDueOn은 제출값 그대로이며 선택기한 생략/null은 null로 치환한다. 과거일이어도 임의 MAX·cycle 계산·브라우저 날짜 보정0이다. 선택기한을 생략하면 기존 master 기한도 null로 바뀌는 계약 문자상의 효과가 의도와 맞는지도 확인해 달라.

소비자 인수도 남아 있다. 현재 client의 `gauge-calibration/code-options.ts:36`은 PASS/FAIL과 유형을 고정하고 외부기관 선택이 비어 있으며 `lookups.ts:58`은 검교정대상만 가져온다. registry의 ADJUSTED/EXTERNAL 선택, 비대상기기 CHECK의 경고후등록, 합격계열 master 반영 미리보기를 연결해야 한다. 다음기한 없음은 이력 없음과 다르다. 공장 today/UTC 표시 경계는094와 연계한다. 이력의 blocksUse/clearedAt 보존과 실제 해소 UI도 별도 인수가 필요하다. 이 소스 관측은 브라우저 실행 PASS가 아니다.

흔적: I-33 R3/R4/R11·§4·§7-1, E-C04~09·기본코드 label 변경 불변·미분류 CAL 전건 rollback·nonCAL 확장201·다른 차단/만료 유지. 계약 사본 a6a87e1은 변경하지 않는다.
