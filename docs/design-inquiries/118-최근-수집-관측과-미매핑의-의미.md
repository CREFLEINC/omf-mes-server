# 118. 최근 수집 관측과 미매핑의 의미

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | GET `/maintenance/collection-channels/observations` 및 수집 채널 가져오기 후보 |
| 구현 상태 | I-33 R6 계획 확정·테이블/API 미구현. 저장된 실제 최신 관측 조회는 진행, 수집자·현장 import 운영 인수는 미완 |
| 판정 | 기존 통합계획의 T 신설 권고 채택. 계약의 관측값/시각을 같은 저장행에서 읽으며 등록 존재와 활성 연결 존재를 분리 |
| 되돌릴 때 | writer의 시각·역순/동률 정책과 필터 의미 회신을 받아 수집 통합·해당 조회 단언을 보완. 원문 관측 손실이나 가짜 현재시각 보정0 |

고정 O6와 Observation 스키마(`equipment-05설비툴.json:2630`, `:4963`), W-05-07 §5-2~5-4는 아직 등록되지 않은 수신 신호를 보고 채널로 등록하게 한다. 기존 `maintenance.collection_observation`은 channel FK가 필수여서 미등록 key를 담을 수 없다. `integration_message.payload`에는 채널/값 해석 규약이 없다.

정본 통합계획의 명시 신설 권고를 구체화해 `maintenance.collection_channel_observation`을 설비+channelKey별 최신 관측1행 저장소로 계획했다. lastValue와 observedAt은 같은 행의 실제값이며 NULL값도 보존한다. GET은 관측 시각을 선택하거나 수집기를 만들지 않는다. 수신시각/NOW로 치환·JSON 임의 파싱·구표 자동복사·영구 빈 handler는 만들지 않는다. 페이지·보관기간·신선도 cutoff·임의 상한을 추가하지 않고 필터한 전건 items/totalCount를 내린다.

**확인 요청:** 이 최신 projection을 쓰는 수집 주체와 이벤트 식별자는 무엇인가? observedAt은 실제 발생/관측/수신 중 어느 원천인가? 역순 메시지 및 같은 시각 서로 다른 값에서 어느 행을 유지하는가? 설비+key 식별·보관/신선도 정책과 운영 활성화 책임을 정해 달라. 저장자료가 존재할 때의 DB 조회와 수집자가 없어 현장에서 빈 상태인 경우를 구별한다.

두 표시의 계획상 의미는 아래와 같다. 등록은 같은 설비/key의 어떤 채널 행이라도 존재하는지, 활성연결은 그중 isActive=true이면서 inspectionItemId가 nonnull인 행이 존재하는지다. 특정 생산품목/공정의 적용가능성은 query에 축이 없어 도출하지 않는다.

| 저장된 채널 상태 | alreadyMapped | unmappedOnly=true 목록 |
|---|---|---|
| 등록행 없음 | false | 포함 |
| 등록행이 있지만 항목 연결 없음 | true | 포함 |
| 비활성 연결만 존재 | true | 포함 |
| 활성 연결 존재 | true | 제외 |
| 활성 조건A 연결 + 조건B 미연결 | true | 제외(ANY 활성연결 존재) |

**의미 확인:** 위 혼합 조건 사례도 ‘미매핑’에서 제외하는 것이 맞는가? alreadyMapped는 중복 가져오기 선택 제어이고 ‘현재 생산조건에 적용 가능’이 아니다. 조건A 때문에 importer가 막혀도 조건B/전체행은 수동 등록할 수 있다는 경계를 인수해야 한다. 같은 key라도 다른 설비는 독립이다.

흔적: `OBSERVATION_STORE_KIND='LATEST_PER_EQUIPMENT_KEY'`, `OBSERVATION_REGISTERED_EXISTS`, `OBSERVATION_UNMAPPED_FILTER`, I-33 R6/§6/E-O01~07. 실제 NULL값·µs·동명 다중설비·혼합조건·전체count를 DB fixture로 검증할 계획이며 아직 PASS0이다. schema/DB API/수집자/UI 네 완료 상태를 따로 보고한다. 단위해제와 import 실패집계는 별도 단건이며 이 질문에 합치지 않는다.
