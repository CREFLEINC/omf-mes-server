# 134. 조정의 ERP 송신 토글이 갈 곳이 없다 — 건별 토글도, 그 토글과 논리곱할 「전역 설정」도 담을 자리가 0 이다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /inventory/adjustments` · `GET /inventory/adjustments` · `GET /inventory/adjustments/{id}` |
| 구현 상태 | **미구현**(등록) · **구현함**(조회 — `erpMessageQueued` 를 늘 `false` 로 내린다 · `main` 병합분) |
| 판정 | `coverage-100/README.md` §2 **0단계** — 형제 출고가 같은 두 칸을 이미 같은 방식으로 판정했다(`src/logistics/goods-issue/goods-issue-view.ts:66-67`). 새 판정을 만들지 않는다 |
| 되돌릴 때 | 「아웃박스에 넣는다」면 조정 전기 뒤 `integration_message` INSERT 한 자리 + 뷰의 `erpMessageQueued` 를 그 행 존재 여부로 바꾼다. 「토글을 저장한다」면 헤더에 칸 하나 |

## 무엇이 문제인가

**ⓐ 계약이 건별 토글을 받는데 담을 칸이 없고, 그 값의 정본은 「전역 설정」이라 적혀 있다.**
`InventoryAdjustmentCreate.sendToErp`(default `true`)의 설명 원문 — ⌜ERP 송신 여부. 화면의 송신 토글이 이 값이다. ⭐ **전역 송신 설정과 논리곱이다** — 전역이 꺼져 있으면 이 값이 참이어도 보내지 않고, 전역이 켜져 있을 때 이 값으로 이 건만 끈다. **켜고 끄기의 정본은 전역 설정이다.**⌝(`contracts/logistics-01자재창고.json:9838-9843`).
물리 `inventory_adjustment` 12칸에 **그 토글을 담을 칸이 0** 이고(`prisma/schema.prisma:464-482`), **그 「전역 설정」을 담을 자리도 서버에 0** 이다.

**ⓑ 응답 칸을 채울 원천도 0 이다.**
`InventoryAdjustment.erpMessageQueued` — ⌜ERP 송신 대기열에 적재됐는지⌝(`:9803-9807`). 「대기열」은 아웃박스 행의 **존재 여부**인데, 조정에는 아웃박스에 넣는 오퍼레이션이 **0건**이다(I-6·I-23 이 갖는 `…:send` 형상이 조정에 없다). ⇒ 오늘은 언제나 `false` 다.

**ⓒ 화면은 그 토글을 실제 스위치로 그린다.**
`W-01-12-재고조정.md:56-57` ⌜《④ ERP 조정 전표》 / [✓] 조정 전표 송신 ⚠ 연계 방식 상세 미확정 (회신 E-10)⌝ · §7 DS 매핑 `:243` ⌜ERP 토글 | `Switch` | a⌝ · §5-6 `:214` ⌜ERP 송신 토글 | 항상⌝. 즉 **값이 늘 거짓인 스위치를 사용자가 켜고 끈다**.
같은 화면 §8 #5 `:255` 는 ⌜**ERP 조정 전표 연계 방식**(회신 E-10) · ~~설정 테이블 부재(#66)~~ ✅ **전역 설정 계약이 섰다**(2026-08-18 · `W-06-12`) … 건별 토글은 전역과 논리곱이다⌝ 라 적었다 — **전역 설정의 «계약»은 섰는데 이 서버에 그 값을 읽을 자리가 없다**.

## 지금 서버는

- 조회 3건은 병합됐고 `erpMessageQueued` 를 **파생값 `false` 로 고정**해 내린다(아웃박스 행이 0건이라 오늘은 늘 거짓이다 — 「담을 칸이 없어서」가 아니라 「행이 없어서」다).
- 등록은 미구현이다. 계획된 동작은 `sendToErp` 를 **받아서 버리는 것**이다 — 저장할 칸이 없다.
- 아웃박스(`integration_message`)에 조정을 넣는 코드는 0 이다.

⇒ **묻는 것**: 조정에 **아웃박스 경로를 열 것인가**(열면 전역 송신 설정을 서버가 어디서 읽는가), 아니면 화면이 **값이 늘 거짓인 스위치를 그대로 그릴 것인가**.

「알려둘 것」으로 함께 보내는 것(문의 아님): 화면 `W-01-12` §8 #3(`:253`)이 ⌜프론트가 **`ADJUST_REASON`** 으로 고정해 두었고 실제 그룹은 `INVENTORY_ADJUSTMENT_REASON` … ⛔ 변경 통지 대상⌝ 이라 적었다. 서버 값 목록은 `INVENTORY_ADJUSTMENT_REASON` 시드로 서 있으므로, 클라이언트가 그 이름을 고치지 않으면 사용자는 **사유 드롭다운이 빈 채**로 만난다 — 서버는 오류를 내지 않는다.
