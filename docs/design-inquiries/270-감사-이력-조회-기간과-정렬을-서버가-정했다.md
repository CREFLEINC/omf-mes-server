# 270. 감사 이력 조회의 기간 경계와 정렬을 서버가 정했다

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 회신을 기다리지 않는다 |
| 걸리는 오퍼레이션 | `GET /audit/events` |
| 구현 상태 | I-35에서 구현 예정 |
| 판정 | `coverage-100/README.md` §2 — MES 본질의 기록 내용을 새로 정하는 일이 아니라 이미 저장된 감사 행의 조회 규칙이다. 변경 비용도 낮아 서버가 정하고 통보한다 |
| 되돌릴 때 | 기간 비교 두 연산자와 정렬 상수, 관련 테스트만 바꾸면 된다. 스키마·기존 행 정정은 없다 |

## 결정

1. 기간은 저장소의 `date-time From/To` 공통 선례대로 **반개구간**으로 조회한다. `occurredFrom`은 포함(`gte`), `occurredTo`는 제외(`lt`)한다.
2. 기본 정렬은 **`occurredAt` 내림차순, 동률이면 `auditEventId` 내림차순**이다. 계약에 정렬 파라미터가 없으므로 페이지 경계가 흔들리지 않게 서버가 고정한다.
3. `targetTypeCode`·`targetId`·`eventTypeCode`·`performedBy`·`correlationId`는 각각 독립 선택 필터다. 계약이 짝 강제나 별도 400을 선언하지 않았으므로 서버가 추가 제약을 만들지 않는다.
4. `beforeValue`·`afterValue`는 저장된 JSON을 해석하거나 키를 버리지 않고 그대로 돌려준다. 계약의 B-5 규약에 따라 모르는 키도 조회에서 보존한다.
5. `page`·`size`는 공용 페이지 규칙(기본 1/50, 서버 안전 상한 200)을 쓴다.
