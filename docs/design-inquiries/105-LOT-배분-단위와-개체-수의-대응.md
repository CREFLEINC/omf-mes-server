# 105. LOT의 배분 수량을 몇 개의 제품 개체로 볼 수 있는가

| 칸 | 내용 |
|---|---|
| 대상 | I-26 발번 quantity 상한, I-7 생산 실적 LOT 배분의 하류 소비 |
| 상태 | POST 재개 조건. 조회 구현은 영향 없음, I-7·기존 LOT 코드 수정0 |
| 판정 | LOT 배분합이라는 집계 축은 0단계 해소. **수량 단위→개체 개수의 대응은 원천 미확인** |
| 최소 해소 | 개체 1개의 수량 단위·허용 배분 단위·필요시 환산 원천/평가시점과 혼합 단위 처리 |

## 확인한 근거

- quantity는 1~1000의 정수 **개체 수**다. LOT 양품의 기존 정본은 production_result_lot_allocation.allocated_qty이지 W/O 실적 헤더 good_qty가 아니다.
- 각 배분은 uom_id를 따로 저장한다. I-7 `production-result.service.ts:106`은 요청 uomId를 그대로 저장하며 :181은 존재만 확인한다. 같은 LOT의 단위 일치를 검사하지 않는다.
- 따라서 10 EA와 2 BOX의 숫자를 더해 12개로 세거나, 12 KG를 정수라는 이유로 12개체로 볼 근거가 없다. Decimal은 소수 오차만 해결한다.
- item_uom_conversion 표가 있다는 사실만으로 개체 목표단위·환산율·유효일이 정해지지 않는다. EA 문자열·품목 base_uom과 일치한다는 사실도 개체 단위의 위임이 아니다.

## 요청과 조건부 경계

**한 개체에 대응하는 수량 단위와 허용 조합, 혼합 단위를 환산한다면 그 정본과 적용 시점을 알려 달라.** 전 품목 원칙을 새 품목분류 게이트로 바꾸지 않는다.

재개 후에는 LOT 잠금 뒤 단위별 배분을 다시 읽고, 대응이 입증된 집합만 개체의 모든 상태 COUNT와 비교한다. 혼합/환산 불명 집합은 400 INVALID(field=lotId), 개체·멱등 기록 증가0의 가장자리 거부안이다. 정상 허용 집합의 원천이 전혀 없으면 POST 본길 유보를 유지한다.

개체 단위가 해소된 뒤 2.5−기발번1이면 quantity1만 허용하고 0.5를 올리지 않는다. 동일 LOT 병렬 발번은 잠금 후 새 집계로 상한을 보호한다. 실적 정정의 배분 미갱신은 기존 문의044이며, 배분 감소/삭제를 새로 만들 때 기발번 하한과 같은 LOT 잠금이 필요하다는 점을 A에 인계한다.
