고정계약 equipment-05설비툴.json:2002·:4476은 실제 세션 조업시간·캘린더 계획비가동·실적비가동과 보전3건수를 함께 낸다. optional 필드를 항상 생략하거나 원천 미정을0으로 채워 완료 처리하지 않는다.

## 1. 날짜×설비 정상계획 구간과 계획비가동 산식

W-05-09 §5-4는 정상 조업시간의 재료가 shift라고 하고 PARTIAL은 그날의 예외라고 한다. shift/calendar/application/day는 실재한다. 그러나 특정 날짜·설비에 어떤 교대 구간을 적용하고 WORKING/HOLIDAY/PARTIAL 및 날짜행 부재를 계획정지 분으로 어떻게 환산하는지는 정해져야 한다. 교대의 존재만으로 설비마다1교대/전교대/24시간 중 하나를 고를 수 없다.

**날짜×설비의 정상계획구간 선택·적용 규칙과 그 구간에 대한 계획비가동 산식을 명시해 달라.** 기존 캘린더 계층/effective 해석을 존중하고, 근거 없이 HOLIDAY=1440·WORKING=0으로 만들지 않는다.

과거 캘린더 수정으로 집계가 바뀌는 것은 W-05-09 §6이 허용한다. 따라서 불변 적용 이력·과거 스냅샷을 새 필수조건으로 요구하지 않는다. PARTIAL의 교대별 배분도 같은 화면이 불필요하다고 하므로 새 요구0이다.

## 2. 완료보전의 엔티티·완료일·대상 범위

**완료 보전1건이 DONE 지시1개인지 완료 실적1행인지, 완료기간의 시각과 설비/툴/지시없는 실적의 범위를 명시해 달라.** maintenance_order/result/completed_at이 실재해도 집계단위가 자동으로 정해지지 않는다. I-31 API 미구현이나 로컬DB0행은 유보 근거가 아니다. I-31에서 같은 정의를 발견하면 근거를 통합해 이 문의를 해소한다.

사후/예방은 고장 포함 트리거 여부의 CORRECTIVE/PREVENTIVE 축이다. 비가동 사유 PREVENTIVE_MAINTENANCE 행수로 대체하지 않는다. 지시없는 완료고장은 DONE·completed_at 기준이며 직접breakdown FK와BREAKDOWN 다형trigger 양쪽 부재를 읽는 I-30 선례를 따른다. 취소지시도 발행 흔적이다.

## 유보를 확대하지 않는 경계

기간 안의 닫힌 정수분 정상 사례는 이미 계산 가능하다: session09~17=480분, 같은설비 비가동10~11 및10:15~10:45는raw90/union60·가동률87.5%. I-30 동일고장 연결합은90이다.

교차기간·소수분·열린세션·무장비필터·WEEK·복수minor정책은 **특정 자료 가장자리**이며 이것만으로 operation 본길을 유보하지 않는다(112). 위 두 정상 정의를 해소하면 남은 조건마다 처리 또는 명시거부로 정상경로를 열 수 있는지 재판정한다. 고장완료·W/O/세션 재개·원장·알림 쓰기는 이 요약의 역할이 아니다.
