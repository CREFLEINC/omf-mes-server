# 098. EQI·MLF 채번 날짜와 트랜잭션 경계

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/maintenance/inspections` · POST `/maintenance/breakdowns` |
| 구현 상태 | 번호2유형 등록·R-14 tx 밖 선채번 계획 확정. 구현0 |
| 판정 | 0단계 plan.md §0-3 공용 패턴·계약 EQI/MLF 예시·기존 채번 코어. 결번·날짜 축·멱등 경계는 R-14로 확정 |
| 되돌릴 때 | 기간 날짜·로컬 호출 순서·등록표와 테스트를 수정한다. 이미 발급된 번호를 재번호화하지 않는다 |

물리 inspection_no/breakdown_no는 NOT NULL UNIQUE이고 요청에 번호가 없다. DEFAULT_PREFIX에 EQUIPMENT_INSPECTION:EQI와 BREAKDOWN:MLF를 등록하며 기본 패턴은 `{PREFIX}-{YYYYMMDD}-{SEQ4}`다. 실제 설비 plant_id의 지정 규칙이 전역 규칙보다 우선하고, 미등록이면 기존 코어가 전역 기본 규칙을 쓴다. 연·월 리셋 규칙은 만들지 않는다.

날짜는 수신한 오늘이 아니라 단말 inspectedAt/reportedAt에서 얻는다. 계획은 UTC 날짜라는 기존 채번 선례를 유지하고 공장 로컬 조회 날짜(094)와의 차이를 명시한다. 이 값을 businessDate로 저장하거나 원래 timestamp를 바꾸지 않는다.

**형식·날짜 확인 요청: 기존 문의14 채번표에 위 두 번호와 기간 축을 포함해 검토해 달라.** 하노이 새벽 번호의 날짜가 전날 UTC일 수 있는 한계가 남는다. 공장별 규칙은 물리 전역 UNIQUE를 깨지 않는 패턴으로 설정해야 하며, 충돌을 성공으로 위장하지 않는다.

서버 통합 판정 R-14: NumberingService:64~70의 경고대로 tx 밖에서 채번을 끝낸다. 계약 equipment-05설비툴.json:2982는 중복 기록을 금지하지만 재생 시 채번 카운터 불변이나 번호 연속을 요구하지 않는다. 기존 멱등 행을 사전 조회하여 있으면 새 채번·설비 검증 없이 기존 run에서 재생/충돌을 판단한다. 없으면 번호 준비를 끝낸 뒤 run의 tx에서 최종 업무·응답·멱등 기록을 원자 커밋한다. 최종 판정은 기존 코어가 하며 private 재생 로직을 복제하지 않는다.

사전 조회한 행이 삭제돼 callback이 실행되면 번호 미준비 제어 신호로 롤백하고 밖에서 번호를 준비한다. callback 안에서는 next를 호출하지 않는다. 정상 완료 재생은 규칙이 비활성화돼도 최초 응답을 유지한다. 경합·업무 실패·재시도로 먼저 준비한 번호의 결번은 허용한다. 준비한 공장 축이 최종 검증과 다르면409·업무0으로 새 요청을 요구한다. 실제 풀 장애를 재현했다고 주장하지 않는다. 연결풀1 검증과 호출 순서·경합·규칙 비활성·사전 행 삭제 테스트를 구현 PR에 붙인다.

번호 P2002만 실패한 tx 전체를 최초 시도 후 최대3회 재시도하고 그 외 오류는 전파한다. 실패 뒤 번호 결번은 허용하지만 번호를 숨겨 재사용하지 않는다. 단위·실제 E2E·연결풀 경계 검증의 구체 명령은 구현 PR에 남긴다.
