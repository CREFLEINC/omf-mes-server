# 240. 피킹 수량이 배정 수량을 **넘는 것**(과피킹)을 막는 제약이 저장소에 없다

**구분: 통보**(회신을 기다리지 않는다 — 우리는 이미 그 상태를 판정식에 넣었다)

| 칸 | 내용 |
|---|---|
| 걸리는 자리 | `logistics.shipment_request_line.allocated_qty` ↔ `inventory.inventory_reservation` 롤업(`Σ(reserved_qty − released_qty)`) |
| 드러난 곳 | I-22 PR ③a(`shipment-progress.ts`) 변이 점검 — 「`A == R && P < A` → `A == R`」 변이가 **초록**이었고, 원인이 「격자에 `P > A` 가 없다」였다 |
| 우리 처리 | ⭐ **`P > A` 를 «닿는 값»으로 보고 격자에 넣었다.** 판정식은 §5-1 정본 그대로 두었다 |

## 무엇이 문제인가

출하 진행(`shipmentProgressCode`)은 라인 4수량으로 판정한다 — `R = Σrequested · A = Σallocated · **P = Σ(reserved − released)** · S = Σshipped`.

`R`·`A`·`S` 셋은 **한 표(`shipment_request_line`)의 칸**이라 CHECK 하나가 순서를 잡는다. 그런데 **`P` 만 다른 표(`inventory.inventory_reservation`)의 롤업**이고, **두 표를 잇는 제약이 하나도 없다.**

**실측**(`omf_mes` · `pg_constraint`·`pg_trigger`):

| 무엇 | 실물 |
|---|---|
| `ck_shipment_request_qty` | `shipped_qty <= allocated_qty AND allocated_qty <= requested_qty` — ⛔ **예약을 전혀 안 본다** |
| `ck_reservation_qty` | `released_qty + consumed_qty <= reserved_qty` — ⛔ **배정을 전혀 안 본다** |
| `inventory_reservation_reserved_qty_check` | `reserved_qty > 0` |
| 두 표를 잇는 트리거 | ⛔ **0건**(세 표의 비내부 트리거는 `trg_*_set_updated_at` 셋과 `trg_inventory_balance_qty` 뿐) |

⇒ **`P > A`(배정보다 많이 집은 상태)를 막는 것이 DB 에 없다.**

⚠ 응용에는 그물이 있다 — 04 계약의 `:pick` 은 「집을 수량이 남은 배정을 넘으면 409」를 선언했고 I-22 PR ⑥ 이 그걸 구현한다. 다만 **그물이 한 겹뿐**이고, 예약 행은 `:pick` 말고도 만들어질 수 있는 자리(01 자재창고·조정·직접 INSERT)가 있다.

## ⇒ 우리가 한 것

`shipmentProgressCode` 판정식(§5-1)을 **글자 그대로** 두고, 단위 spec 격자에 **`P > A` 줄을 넣었다**. 그 줄이 없으면 「`A == R` **그리고** `P < A` 일 때 `PICKING`」의 뒤 절이 반증되지 않는다(실측: 뒤 절을 지워도 전건 초록이었다).

`P > A` 인 건은 오늘 판정식에서 `PICKING` 이 **아니고** 아래로 흘러 `PARTIALLY_ALLOCATED` 가 된다(`A = R` 이면). 이것이 의도한 값인지는 계약이 말하지 않는다.

## 📨 알려 드리는 것

**⓵ 과피킹을 「일어날 수 없는 상태」로 보고 계신다면 그 근거를 알려 주십시오.** 저장소에는 그것을 보장하는 것이 없습니다. 보장이 필요하면 자리는 둘입니다 — ⓐ 응용 그물(`:pick` 409)만으로 충분하다고 정하거나 ⓑ 예약 롤업을 `allocated_qty` 에 묶는 제약·트리거를 새로 세우거나.

**⓶ 과피킹이 «일어날 수 있는» 상태라면 그때의 `shipmentProgressCode` 를 정해 주십시오.** 계약의 6값 정의는 `P > A` 를 다루지 않습니다. 오늘 우리 구현은 `PARTIALLY_ALLOCATED`(또는 `A < R` 이면 그대로)로 떨어지는데, 화면(`W-04-02` 상태 열·`W-04-04` 「피킹중 ⛔」 배지)이 그 값을 어떻게 읽어야 하는지가 정해져 있지 않습니다.
