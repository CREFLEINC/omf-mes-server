# 096. 설비 멱등 재전송의 주체와 업무 트랜잭션

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | I-30 점검 POST·고장 POST/PUT/start·조건부 complete |
| 구현 상태 | R-5·R-14 확정·구현 전. 채번은 tx 밖에서 사전 준비(098) |
| 판정 | 0단계 run의 tx 계약·WorkerNo 필수/귀속. 다른 주체는 가장자리 명시409. 공용 code-reference 타입 우회0 |
| 되돌릴 때 | 공용 runner가 같은 보장을 제공하면 로컬 context/tx 검증을 통합한다. 오류 정책 변경 시 계약·테스트를 함께 맞춘다 |

공용 master-write는 tx를 전달하지 않고 지문에서 actor와 헤더를 제외한다. I-30은 기존 IdempotencyService.run이 전달한 tx로 업무·응답·멱등 완료 기록을 함께 커밋한다. 로컬 지문은 method/path + body + actorUserId + O3/O6의 원문 workerNo로 만들고 If-Match는 제외한다. 다른 계정/사번은 409 user이며 앞사람의 응답을 보여주지 않는다.

사번 필수·공백·max50은 run 전에 검사해 재생도 우회하지 못하게 한다. 사번 존재는 신규 업무 tx 안에서 확인한다. 귀속·키·본문이 같은 요청은 If-Match가 낡아도 최초 응답을 재생한다. I-30 쓰기 query는 없으므로 I-28의 eventCode query 보강과 구분한다.

code-reference.ts:24의 assertCodeValues는 PrismaService만 받으므로 TransactionClient를 타입 단언으로 통과시키지 않는다. 로컬 tx.code_value 검증으로 그룹과 활성 여부를 확인한다. 다른 레인과 공용 runner 코드는 바꾸지 않는다.

**검토 요청: 생성 POST에 빠진 공통 멱등409와 주체 변경 시 재생 거부를 공통 정책으로 명시해 달라.** 새 오류 코드나 인증 수단은 만들지 않는다. 사번은 귀속이며 로그인을 대체하는 비밀번호가 아니다. 세션이 없으면 현재401이다(054).

흔적: I-30 R-5·R-14, E-I19/20·E-B17/24. 다른 주체409, 재생 요청의 사번400, 완료 기록 실패의 전체 롤백, 전달받은 tx에서 최종 검증하는 테스트에 문의096을 남긴다. 번호 준비를 위한 사전 조회·선채번은 098과 I-30 §5-1의 명시적 예외다.
