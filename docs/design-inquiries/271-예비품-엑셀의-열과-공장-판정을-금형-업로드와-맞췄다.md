# 271. 예비품 엑셀의 열과 공장 판정을 금형 업로드와 맞췄다

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 회신을 기다리지 않는다 |
| 걸리는 오퍼레이션 | `POST /mdm/spare-parts:import` |
| 구현 상태 | I-35에서 구현 완료(PR #550) |
| 판정 | `coverage-100/README.md` §2 — 예비품 대장 입력 형식은 MES 핵심 추적·실행 규칙이 아니며, 열 별명표만 바꾸면 되어 변경 비용이 낮다. 구현된 형제 `POST /mdm/molds:import` 선례를 그대로 적용한다 |
| 되돌릴 때 | 머리글 별명표와 행 매핑만 바꾸면 된다. 스키마 변경·기존 행 정정은 없다 |

## 결정

1. 확실한 열만 받는다: **공장 코드(선택), 예비품 코드(필수), 예비품명(필수)**. 그 밖의 엑셀 열은 이번 경로에서 저장하지 않는다.
2. 머리글은 위치가 아니라 이름으로 찾고 한국어·영문 별명을 허용한다. 첫 번째 워크시트를 읽으며 완전히 빈 자료 행은 건너뛴다.
3. 공장 코드 열이 있으면 `plant.plant_code`로 찾는다. 공장 코드가 없으면 등록된 공장이 정확히 하나일 때만 그 공장을 사용한다. 공장이 여러 개이거나 코드가 없으면 해당 행만 실패시킨다.
4. 읽을 수 없는 파일이나 코드·명칭 머리글이 없는 파일은 전체 요청을 400으로 거부한다. 자료 행의 공장·필수값·길이·중복 오류는 `BatchResult.failed[]`에 모으고 성공 행은 유지한다.
5. `failed[].index`는 계약대로 머리글을 제외한 자료 행의 0부터 시작하는 순번이며, `key`에는 예비품 코드를 싣는다.
6. 멱등 지문에는 업로드 파일의 SHA-256을 포함한다. 같은 키·같은 파일은 응답을 재생하고, 같은 키·다른 파일은 409로 거부한다.
