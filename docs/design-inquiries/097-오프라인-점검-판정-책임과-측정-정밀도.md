# 097. 오프라인 점검 판정 책임과 측정 정밀도

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/maintenance/inspections` · POST `/maintenance/breakdowns` |
| 구현 상태 | R-8대로 구현 예정 |
| 판정 | 0단계 오프라인의 옛 기준 허용·전달 판정 보존. 빈 라인/FAIL 비고/무손실 저장 불가 수치는 가장자리→② 명시 거부. 정지 시각 임의 도출0 |
| 되돌릴 때 | 당시 기준 버전/필수 집합의 원천이 생기면 서버 검증을 확장한다. 수치 확장이 결정되면 명시적 마이그·계약·테스트를 수정한다 |

M-05-01은 측정 자동 판정·필수 항목 전건과 오프라인 중 부여·기준 변경 허용을 함께 요구한다. 요청에는 당시 기준 버전과 필수 집합이 없다. 서버가 현재 기준으로 다시 검사하면 정상적인 옛 기준 입력을 거부할 수 있다. 서버는 받은 라인의 PASS/FAIL을 보존해 종합하고 현재 마스터 표시값을 조인한다.

단말이 캐시된 effective 항목의 필수 검사와 측정 자동 판정을 책임진다. 서버의 빈 lines422 LINE_REQUIRED와 FAIL 헤더 remarks422 REQUIRED는 필수 집합 완결성 검사가 아니다. 일부 필수 라인을 뺀 비어 있지 않은 PASS와 정상 옛 기준을 구별하지 못한다. 라인 비고만 있는 FAIL은 헤더 REQUIRED이며, PASS의 비고 생략은 성공이다. 현재 유형 코드의 활성 검사는 유지하므로 모든 마스터 변경을 허용한다고 말하지 않는다.

계약 measuredValue는 한도 없는 double, DB numeric_value는 Decimal(20,6)이다. Decimal 값 기준으로 무손실 표현 가능한 값 또는 null만 저장한다. 0.0000001·1e14는400 RANGE(field lines[i].measuredValue)이고 헤더·라인·멱등 기록은 남기지 않는다. 문자열 자릿수 검사나 DB 반올림으로 측정 근거를 바꾸지 않는다.

**검토 요청: 단말 책임·서버 미검증 한계와 측정 저장 범위에 대한 요구를 확인해 달라.** 서버가 당시 필수 집합까지 보장해야 한다면 그 원천을 정의해야 한다. 현재 itemName/judgeMethod는 당시 기준의 스냅샷이 아니다.

고장 stoppedAt은 선택 원문이며 ABNORMAL일 때도 명시한 값을 버리지 않는다. reportedAt과의 선후 관계·장치 시각을 계약 근거 없이 보정하거나 거부하지 않는다. I-30 §6·E-I14/15/17·E-B13과 수치 왕복/거부 단언에 문의097을 남긴다.
