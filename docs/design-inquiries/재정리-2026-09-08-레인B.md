# 설계 요청 재정리 — 레인 B (2026-09-08)

`coverage-100/README.md` **§2 1-1단계**의 판정 기준을 사용자와 다시 확인한 뒤, 레인 B 소관을 재분류했다.

> **질의는 `MES 본질`과 `바꾸는 비용 높음`이 동시에 참일 때만 한다.**
> 여기서 MES 본질은 LOT 추적·생산 계획·생산 실행처럼 MES를 사용하는 직접 이유에 해당하는 기능이다.
> 둘 중 하나라도 아니면 서버팀이 결정해 구현하고 설계팀에는 통보한다.

⛔ 레인 A·C 소관은 이 문서에서 판정하지 않는다.

## 0. 결론

1. 번호가 있는 레인 B 요청 **090~119 30건**은 **질의 2건·통보 28건**으로 분류한다.
2. 질의는 **105**(LOT 배분 단위와 제품 개체 수)와 **109**(비가동 종료 발생시각)뿐이다.
3. 두 질의가 막는 자리는 각각 **I-26 `POST /trace/serial-numbers` 1건**, **I-32 `POST /maintenance/downtimes/{downtimeId}:close` 1건**으로 한정한다.
4. I-27·I-33의 번호 없는 후보는 모두 통보다. 새 번호를 만들거나 기존 번호 대역을 재사용하지 않는다.
5. 규칙 변경 전 작성된 090~119 개별 파일은 소급 수정하지 않는다. 이 문서를 재분류 정본으로 삼고 루틴 종료 전달물에서 질의·통보를 구분한다.

## 2. 번호 없는 후보

### I-27 발행·프린터 후보

배송/포장 매핑, 개별 불량 라벨 대상 여부, 프린터 매핑·상태·기본값 원천, 발행 귀속·이력, CSV·요약 가장자리, 권한, 재발행 사유는 모두 **통보**로 분류한다.

- 라벨 발행은 LOT 추적의 소비자일 수 있으나, 위 후보들은 추적 관계를 만드는 규칙이 아니라 출력·프린터·표시·권한 정책이다.
- 발행 원문과 귀속을 보존하고 서버팀이 기존 발행 규칙과 일관되게 결정한다.
- material rendition은 커버리지 100의 기술적 제외 범위를 유지하며 이 재분류로 복원하지 않는다.

### I-33 수집 채널 후보

채널 단위 해제와 import 실패 건수 표시는 모두 **통보**로 분류한다.

- 채널 단위 해제는 수집 매핑의 수정 규칙이다.
- import 실패 건수는 서버 동작을 새로 결정하는 항목이 아니라 운영·소비자 인계다.

레인 B 배정 52개 오퍼레이션을 현재 상태로 다시 계산하면 다음과 같다.

|---|--:|--:|--:|--:|--:|--:|--:|--:|
| 이미 구현 | 1 | 0 | 5 | 4 | 0 | 4 | 0 | **14** |

작업 경계:

- **I-26:** 조회 1건은 구현 완료. 생성 1건만 105 회신 전까지 대기한다. 104·106·107은 서버팀이 결정·통보한다.
- **I-27:** rendition 1건을 제외한 6건은 진행한다. 프린터 관련 후보도 더 이상 설계 회신을 기다리지 않는다.
- **I-28:** 남은 이벤트·구독 3건을 진행한다. 099의 eventCode 목록은 서버팀이 정해 통보한다.
- **I-30:** 구현된 4건 뒤 남은 5건을 진행한다. 090의 완료 본길도 서버팀이 정해 진행한다.
- **I-31:** 8건 전부 진행한다.
- **I-32:** 목록·상세·등록은 #357/#359, 수정은 #360에서 구현했다. 요약 1건은 서버팀이 결정·통보해 이어서 진행하고, 종료 1건만 109 회신 전까지 대기한다.
- **I-33:** 12건 전부 진행한다.

## 4. 설계팀에 보낼 정확한 질의 경계

### 105 — LOT 배분 단위와 제품 개체 수

`POST /trace/serial-numbers`에서 LOT의 생산 실적 배분 수량을 몇 개의 제품 개체로 바꿀지 결정하는 원천이 필요하다.

- 제품 개체 1개가 나타내는 수량 단위
- 허용되는 LOT 배분 단위
- 환산이 필요할 때 사용할 원천과 평가 시점
- 혼합 단위 처리

이 답이 오기 전에는 생성 1건만 미룬다. 조회·발행 이력 등 다른 작업은 진행한다.

### 109 — 오프라인 비가동 종료 발생시각

`POST /maintenance/downtimes/{downtimeId}:close`가 오프라인 재전송을 지원하면서 본문에 종료 발생시각을 받지 않는다. 실제 종료시각을 어떤 경로로 전달·보존할지 결정이 필요하다.

이 답이 오기 전에는 종료 1건만 미룬다. 명시 시각을 받는 등록·수정과 조회·요약은 진행한다.

## 5. 범위 밖 자료

최초 설계 요청 1~15의 원문은 `docs/design-inquiries/README.md`가 가리키는 `~/omf-design-requests`에 있다고 되어 있으나, 현재 작업 환경에는 해당 경로가 없다. 따라서 이 문서에서는 원문 없이 소관이나 내용을 추정하지 않는다.
