## 4. 설계팀 전달 경계

### 105 — LOT 배분 단위와 제품 개체 수 · 정보 회신 완료

2026-09-09 회신으로 `POST /trace/serial-numbers`의 제품 개체 1개는 수량 1이며, 생산 실적·양품·LOT 배분이 발번의 선행조건이나 상한이 아님을 확인했다.

- 제품 개체 1개가 나타내는 수량 단위
- 허용되는 LOT 배분 단위
- 환산이 필요할 때 사용할 원천과 평가 시점
- 혼합 단위 처리

서버는 이 회신을 반영해 I-26 생성 1건을 PR #544로 구현했다. 설계팀은 위 설명을 계약 설명문에 명문화할 때 설계 변동 공지에 싣기로 했다.

### 통보 109 — 비가동 종료의 서버 최초 처리시각

`POST /maintenance/downtimes/{downtimeId}:close`는 종료 발생시각 입력 없이 오프라인 재전송을 지원한다. 사용자 결정에 따라 이 operation만 서버 최초 처리시각을 종료시각으로 사용하고, 전송 지연을 허용하며, 같은 멱등 키 재전송은 최초 시각을 유지한다.

새 body/header를 만들지 않는다. 설계팀에는 ‘지금’의 의미·C-12 예외·오프라인 지연·멱등 재생 규칙을 문서에 반영하도록 통보하며 회신을 기다리지 않는다.

## 6. 통보 090 — 설비 고장 원인 원천의 서버 결정

I-30의 `causeCode`는 **활성 `mdm.code_value` 중 활성 그룹 `EQUIPMENT_BREAKDOWN_CAUSE`에 속한 자연키 `code`**로 결정한다. 선택 목록은 기존 `GET /mdm/code-values?codeGroupCode=EQUIPMENT_BREAKDOWN_CAUSE`를 사용한다. 그룹과 값은 고객이 기준정보 API로 관리하며 시스템 고정 enum이나 품질 원인 행으로 만들지 않는다.

이 결정은 다음 저장소 사실을 함께 만족하는 최소 경로다.

- `quality.cause_code`는 불량 원인 마스터이고 W-05-04가 설비 고장 원인으로의 재사용을 금지한다.
- 고정 계약이 적은 `mdm.cause_code` 테이블·생성 API·선택 API는 실제 저장소에 없다. 테이블만 추가하면 선택·운영 경로가 없는 두 번째 마스터가 된다.
- `mdm.code_group/code_value`와 범용 조회·관리 API는 이미 있고, 고장 요청·저장칸·응답이 모두 문자열 자연키라 별도 ID 변환이나 스키마 변경이 필요 없다.
- 추후 전용 마스터가 확정돼도 같은 자연키 문자열을 보존한 채 검증 원천만 교체할 수 있다. 기존 고장 행은 조회 때 현재 마스터 존재 여부를 다시 검사하지 않는다.

적용 규칙은 다음과 같다.

1. PUT은 `causeCode` 생략 시 기존 값 유지, `null`이면 해제, 문자열이면 위 활성 원천에 존재할 때만 저장한다.
2. complete는 공백이 아닌 `causeCode`·`handlingNote`를 모두 요구하고 같은 원천을 검증한다.
3. 그룹/값 부재·비활성·품질 원인은 400 `INVALID(field=causeCode)`다. 그룹에 값이 없으면 화면은 완료를 활성화하지 않는다.
4. complete는 `RECEIVED|HANDLING → DONE`만 허용하며 작업지시·작업세션·비가동·설비 상태·알림·재고를 바꾸지 않는다.
5. 계약 사본은 동결 상태로 수정하지 않는다. 설계팀에는 `x-no-code-key`의 `mdm.cause_code` 설명과 선택 경로를 이 서버 결정에 맞춰 정리하도록 **통보**하며, 회신을 배포 선행조건으로 삼지 않는다.

## 7. I-27 P1 번호 없는 통보 — 발행 이력 조회 가장자리

목록·상세 구현 PR #448에서는 원시 발행 행을 바꾸지 않는 조회 가장자리를 다음과 같이 확정했다.

1. 기간은 PostgreSQL 마이크로초 격자에서 `issued_at >= issuedFrom AND issued_at < issuedTo`가 유지되도록 6자리보다 긴 소수 경계를 올림 처리한다. 입력 offset은 보존하며 `Date`로 먼저 밀리초 절단하지 않는다.
2. 정렬은 `issued_at DESC, document_issue_log_id DESC`, 목록 행·전체 건수·대상 표시명은 한 `RepeatableRead` snapshot에서 읽는다.
3. 대상 표시명은 정본 원천을 유형별 최대 7회 배치 조회한다. 출고 라인은 `goods_issue_no #line_no`, 삭제된 대상은 `TYPE #id`로 표시하고 이동 화면은 생략한다.
4. `lotId` 필터는 저장된 `document_issue_log.lot_id`만 사용한다. 현재 HU 내용물을 역추적해 과거 이력에 LOT를 소급 귀속하지 않는다.
5. 재발행 사유명은 과거 이력 표시이므로 현재 비활성 값도 읽는다. 반대로 계약 필수 enum·길이·안전 정수 결손은 숨기거나 임의 보정하지 않고 환경 활성화 검사 대상으로 드러낸다.

모두 발행 원문을 보존하는 조회·표시 정책으로 변경 비용이 낮고 MES 추적 관계를 새로 만들지 않는다. 따라서 `README.md` §2 1-1에 따라 서버팀이 결정·구현하고 설계팀에 통보하며 회신을 배포 선행조건으로 삼지 않는다.

## 8. I-27 번호 없는 통보 — 발행·프린터 최종 결정

I-27 구현 PR #460·#462~#476·#479에서 다음을 서버 결정으로 확정했다.

1. 발행은 대상 부모를 실제 writer와 같은 순서로 잠근 뒤 경로·상태를 다시 읽고, 회차와 로그를 한 트랜잭션에서 배치 저장한다. 출고 라인·검사 확정·금형 코드 변경 writer는 실제 API 양방향 경합으로 검증했다.
2. TOOL_LABEL은 금형 코드 변경을 `mold 잠금 → 참조·발행 이력 검사 → CAS` 한 트랜잭션으로 직렬화한 뒤 활성화했다. PENDING·FAILED 발행 이력도 코드 변경을 막는다.
3. 프린터는 같은 공장·활성값·첫 행에서 추론하지 않고 `terminal_printer`의 명시 매핑·기본값·지원 문서 종류만 사용한다. 기본 프린터는 단말당 최대 1개다.
4. 프린터 상태는 저장된 `READY|BUSY|OFFLINE|ERROR`만 반환한다. 관측 producer가 없어 NULL인 기존 행은 OFFLINE으로 표시하되 READY로 추정하지 않으며, 상태 메시지는 저장 원문을 보존한다.
5. 요청의 terminalId가 있으면 그것을, 없으면 검증된 단말 토큰의 ID를 사용하고 둘 다 없으면 빈 목록을 반환한다. 서버는 URI 접속·장치 poll·driver·spool 동작을 하지 않는다.
6. 계약 사본은 수정하지 않았다. rendition은 바이너리 생성 원천이 없어 기술적 제외로 유지하며, 6개 API 구현 완료를 문서 9종의 물리 출력 완료로 표현하지 않는다.

이 결정들은 출력 장치·표시·동시성 정책이고 발행 원문·LOT 관계를 보존하므로 변경 비용이 낮다. 설계팀에는 위 저장 원천과 추론 금지 경계를 반영하도록 **통보**하며 회신을 배포 선행조건으로 삼지 않는다.

## 9. 통보 099~103 — I-28 알림 최종 결정

알림은 MES 본질 기능이 아니며 설정·표시·동시성 정책은 원시 사건을 바꾸지 않는다. 서버팀은 #482·#483·#484·#486에서 다음을 확정했다.

| eventCode | 화면명 |
|---|---|
| `EQUIPMENT_BREAKDOWN_OCCURRED` | 설비 고장 발생 |
| `MOLD_RECOMMENDED_SHOTS_EXCEEDED` | 적정타수 초과 |
| `CALIBRATION_EXPIRY_APPROACHING` | 검교정 만료 임박 |
| `PURCHASE_ORDER_CHANGE_RECEIVED` | P/O 변경 수신 |
| `INTEGRATION_FAILED` | 연계 실패 |
| `APPROVAL_ACTION_REQUIRED` | 승인 요청·결재 도착 |

1. **099:** 위 6개가 계약·W-CO-03·W-CO-11이 함께 쓰는 읽기 전용 정본이다. 공통코드나 발생 이력에서 만들지 않는다. 검교정 임박은 설정 행에는 포함하지만 임박 일수와 배치가 미확정이므로 발생기는 만들지 않는다.
2. **100:** 설정 없는 이벤트는 수신자0·Zalo false·ETag1로 읽되 GET에서 행을 만들지 않는다. 최초 PUT은 헤더1을 잠근 뒤 version2로 저장한다. 전체 GET에는 ETag가 없고 단일 이벤트 GET에만 있다. Zalo 생략은 기존값 유지다.
3. **101:** preview는 비활성 사용자를 `isActive:false`로 표시하고 `totalCount`에서는 제외한다. 비활성 조직·역할을 별도 사용자 활성값으로 합성하지 않는다.
4. **102:** 화면·위치 원천이 없는 대상은 `openable:false`와 optional 키 생략으로 반환한다. 계약 enum 밖 과거 대상도 임의 매핑하지 않는다.
5. **103:** PUT 멱등 지문은 actor·eventCode(query)·body를 포함하고 If-Match는 제외한다. 헤더·자식 전부 치환·Zalo·version·완료기록은 한 트랜잭션이며 응답 유실 재전송은 최초 응답을 재생한다.

기존 사용자·채널 구독 행은 변경·백필·삭제하지 않는다. 알림 발생기, 검교정 시간 트리거, Zalo 수신처와 외부 전송은 이번 완료 범위가 아니며 설계 회신을 기다리는 것처럼 표시하지 않는다.
