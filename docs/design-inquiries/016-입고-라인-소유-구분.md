# 16. 입고 라인에 「소유 구분」을 받는 칸이 없다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /logistics/goods-receipts` (앞으로 `POST /logistics/inbound-receipts`·`shopfloor-receipts`·`stock-reinstatements` 도 같다) |
| 구현 상태 | 구현함 — `ownershipTypeCode = 'OWNED'` 고정 (PR #180) |
| 판정 | §2 1단계 **가장자리**(고객지급품·위탁재고 입고만 갈린다) → 2-4 「값을 조용히 도출하지 않는다」— 입고 유형에서 도출하지 않고 고정값 + 기록 |
| 되돌릴 때 | 계약이 `GoodsReceiptLineCreate.ownershipTypeCode`(+ `ownerPartnerId`)를 열면 화면 값으로 전기. 서버 변경 10줄 이내, 기존 데이터는 전부 `OWNED` 라 이관 없음 |

## 무엇이 문제인가

잔량 유일키 `uq_inventory_balance_dim` 은 `ownership_type_code` 를 차원으로 갖는다 — 같은 LOT 이
같은 위치에 있어도 자사소유(`OWNED`)와 고객지급품(`CUSTOMER_SUPPLIED`)·위탁(`CONSIGNMENT`)은
**다른 재고 행**이다. 그런데 `GoodsReceiptLineCreate` 에는 품질 상태·재고 상태는 있고 소유 구분만
없다. 원장 라인은 NOT NULL 이라 서버가 무엇이든 넣어야 한다.

## 지금 서버는

`OWNED` 로 전기한다. 고객지급품·위탁재고를 입고하면 **자사 재고로 잡힌다** — 재고 평가와 반환
의무가 어긋난다.

## 요청

`GoodsReceiptLineCreate`(및 입하·생산창고 입고·재고 재등록 라인)에 `ownershipTypeCode`
(`OWNERSHIP_TYPE` 코드 그룹, 기본 `OWNED`)와 위탁·고객지급품일 때의 `ownerPartnerId` 를 열어 달라.
입고 유형(`RECEIPT_TYPE`)에서 도출하는 규칙이 있다면 그것도 답이 된다 — 서버는 그 규칙을 지어내지 않았다.
