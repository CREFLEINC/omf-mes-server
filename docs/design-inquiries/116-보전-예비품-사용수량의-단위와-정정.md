# 116. 보전 예비품 사용수량의 단위와 확인·정정

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | POST `/maintenance/results` · PUT `/maintenance/results/{maintenanceResultId}`의 parts 및 결과 조회 |
| 구현 상태 | 계획 확정·구현 전. 예비품·기존 출고 참조만, posting/자동출고/할당량/환산0 |
| 판정 | 0단계 readOnly uom·출고참조 계약. 다중UOM/미연결은 가장자리③nullable·④조용한단위도출0 |
| 되돌릴 때 | 회신된 단위 의미에 따라 part 입력/조회 및 수량 확인·GI 재선택·PUT 소비자 인수 수정; 계약 갱신은 별도 사용자 지시 뒤 |

part는 sparePartId·usedQty 필수이고 goodsIssueId는 선택 nullable다. uomCode/출고번호/시각은 readOnly다. API에는 수량 단위를 별도 입력하는 칸이 없으며 출고없이도 정상 입력이 가능하다.

서버 조회는 같은 GI+spare의 실재 단위가 하나면 그 UOM, 여러 개면NULL을 낸다. GI가 없으면 spare.base_uom 또는NULL이다. EA/BOX를 임의로 고르거나 둘의 수량을 더해 단위를 정하지 않는다. 이 NULL은 ‘단위 확인 불가’이지0수량/EA/환산완료가 아니다. usedQty는numeric20,6의무손실범위만저장한다.

**확인 요청:** 출고없는 사용량 및 하나의 출고에 단위가 여러 개인 예비품 사용량은 어떤 단위를 의미하는가? GI를 다른 단위의 출고로 재선택할 때 입력 수량의 확인·정정 절차를 정해 달라. 계약 변경이 필요하다면 확정 후 별도로 반영하며 먼저 단위입력을 신설하지 않는다.

현재 maintenance-result 화면은 수량/GI를 입력하지만 단위를 표시하지 않고 저장 후 parts 건수만 보인다. API-client 타입에7칸이 있다는 것만으로 예비품명·수량·단위·GI번호·출고일을 확인할 수 있는 것은 아니다. GETdetail/PUT 사용처도 없어 정정 흐름이 미완이다. 서버를계약대로구현하되화면인수완료로보고하지않는다.

필요 소비자 인수: part7전필드표시·unknown단위명시·GI재선택단위확인·상세GET→실적ETag→PUT→상세GET. 서버 단언은 omitted배열보존/[]교체·정확수량·다중UOM NULL·실패시자식/버전 rollback·과거reset편집무재실행. 출고 issuedAt도109/I32 R14의µs 원문시각을보존하며물류mapper의Date절삭을복제하지않는다.
