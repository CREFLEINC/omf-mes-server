# 216. 재생재 품목 행을 **누가 만드나** — 품목 생성 오퍼레이션이 **0건**이다

**구분: 통보**(2026-09-10 닫혔다 — 맨 끝 「결정」 절) · 원래는 §2 1-1단계 두 축에 둘 다 걸린다고 보아 질의로 올렸다: **MES 본질**(품목 마스터는 모든 재고·원장의 출발점) × **바꾸는 비용**(ERP 와의 소유권 경계).

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /logistics/recycle-entries`(I-17) · `POST /logistics/inbound-receipts`(I-3 · 병합됨) |
| 구현 상태 | **등록된 품목만 받는다** — 서버가 품목을 만들지 않는다 |

| 이미 등재된 자리 | ⭐ `plan.md` **231행** 「재생재/입하 오류의 «미등록 품목» 생성 경로 없음 \| I-17 · I-3 \| UI/UX **B·C**」 |

## 무엇이 났나

`RecycleEntryCreate.itemId` 는 **required** 고, 서버는 그 품목이 **이미 있어야** 받는다(없으면 400).
그런데 **품목을 만드는 오퍼레이션이 계약에 0건**이다 — `/mdm/items` 는 **GET 뿐**이다.

화면 쪽도 같은 자리를 열어 뒀다:
- `plan-uiux.md:1193` — 「**M-01-12** 재생재 등록 \| 재생재 «신규 품목» 행을 만드는 경로 \| `/mdm/items` 는 **GET 뿐**이다(`W-06-05` 가 「품목 추가는 없다 — **ERP 정본 수신본**」) \| 화면 §8 이 **2026-09-02 재확인에도 열려 있다**고 적음」

⇒ 현장이 **ERP 에 없는 분쇄재 품목**을 만났을 때 **갈 곳이 없다.** 등록 자체를 못 한다.

## 여쭙는 것

**⓵ 재생재 품목은 ERP 에 «먼저» 등록되는 것이 전제입니까?**
그렇다면 이 자리는 닫힙니다 — 화면이 「ERP 에 먼저 등록하십시오」를 안내하면 됩니다. **저희는 이쪽으로 봅니다**
(`W-06-05` 의 「ERP 정본 수신본」과 일관되고, MES 가 품목 정본을 만들기 시작하면 두 정본이 생깁니다).

**⓶ 아니면 MES 가 만들어야 합니까?** 그렇다면 **`POST /mdm/items` 가 계약에 필요합니다** — 지금은 경로가 없어
서버가 할 수 있는 일이 0입니다. 그리고 품목 코드 체계·ERP 역전송 규약이 함께 정해져야 합니다.

⚠ **이 질의는 I-17 구현을 막지 않습니다.** 「등록된 품목만 받는다」로 구현하고, 답에 따라 화면 안내문만 바뀝니다.

## ⛔ 이 질의에서 «뺀» 것 둘 — 질의가 아니라고 판정했습니다

3관점 리뷰가 초안의 묶음을 갈랐습니다. 기록으로 남깁니다.

| 뺀 것 | 왜 |
|---|---|
| 「`(item_code, mes_category_code)` **복합 유일**이 물리에 없다」 | 계약 `x-internal-note` 가 **이미 답을 적어 둔 물리 미완**이라 README §5(되돌림 항목)이고 질의가 아니다. ⚠ 다만 `item_item_code_key` 가 **`item_code` 단독 UNIQUE** 인 것은 사실이라, 계약이 말한 복합 유일을 원하면 **마이그가 필요하다** — 그건 mdm 소유다 |
| 「기간계로 보내지 않는다」 | ⛔ **초안이 방향을 뒤집어 읽었다.** 계약 문장은 **나가는 방향**(MES → 기간계)인데 들어오는 방향으로 읽었다. 이대로 나가면 **거짓 전제**가 설계팀에 간다 |

⭐ 그리고 `item.mes_category_code` 는 **실재한다**(varchar · nullable · 2026-09-03 마이그 · psql 실측).
⛔ **계약 `x-internal-note`·`plan.md:134`·`plan-integration.md:357`·이슈 #64 본문 넷이 「없다」로 낡아 있다** — 고쳐야 한다.

## ✅ 2026-09-10 — 닫혔다. **ERP 가 먼저다** (사용자 결정)

> **재생재 품목도 ERP 에 «먼저» 등록되고, MES 는 받아쓴다.** ⓵ 안이다.

### 근거

- 화면 정본이 이미 그렇게 적었다 — `W-06-05` 「**품목 추가는 없다 — ERP 정본 수신본**」.
- `/mdm/items` 는 **GET 뿐**이다(실측). 계약이 처음부터 그 경계를 그어 두었다.
- MES 가 품목 정본을 만들기 시작하면 **정본이 두 곳에 생긴다** — 되돌리는 비용이 가장 큰 종류다.

### 무엇이 바뀌나 — **서버 코드 0줄**

구현은 이미 「등록된 품목만 받는다」다. 바뀌는 것은 **화면 안내 문구 하나**다:

> 현장이 ERP 에 없는 분쇄재를 만나면 → **「ERP 에 먼저 등록해 주십시오」**를 안내한다.

⚠ **화면 `M-01-12`(재생재 등록) §8 의 「열려 있음」 표시를 닫아 주십시오** — 이 결정으로 닫혔습니다.

### 📨 설계팀께

**MES 가 품목을 만들어야 하는 현장 사정이 있으면 알려 주십시오.** 그때는
**`POST /mdm/items` 가 계약에 필요합니다**(오늘은 경로가 없어 서버가 할 수 있는 일이 0입니다).
품목 코드 체계와 ERP 역전송 규약도 함께 정해져야 합니다.
