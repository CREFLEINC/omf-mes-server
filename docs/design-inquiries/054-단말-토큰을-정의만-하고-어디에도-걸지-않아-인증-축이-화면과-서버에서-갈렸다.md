# 54. ⭐ 단말 토큰을 정의만 하고 어느 오퍼레이션에도 걸지 않아, 인증 축이 화면과 서버에서 갈렸다 — 단말 인증을 언제 세우나

> I-7 이 「알려둘 것」으로 이미 한 번 적은 자리다(`design-inquiries/README.md` (I-7) 줄 ⌜`terminal_id` 영원히 NULL(단말 토큰 없음 · 게이팅 2플래그 미검사)⌝). **재보고가 아니다** — I-10 에서 **마이그레이션 한 건**을 낳고 I-11 에서 **403 갈래 하나**를 낳아 번호로 승격한다.

## 무엇이 문제인가

ⓐ 계약이 `app-공통.json` 에 `terminalToken`(`type: http` · `scheme: bearer` · ⌜단말 등록 때 발급한 값을 **기기가 저장해 보낸다**⌝)을 **정의만 하고 `security` 를 어느 오퍼레이션에도 걸지 않았다** — 487 오퍼레이션 0건 · top-level 도 7벌 전부 없음(실측). ⇒ **어디에 걸 것인가**가 물음이다. `authentication.guard.ts:24-28` 이 그 사실을 이미 주석으로 적었다.
ⓑ 서버는 그 토큰을 **발급은 한다** — `mdm/terminal/terminal.service.ts:200-223` `issueToken()` 이 `{sub, typ:'terminal', tv}` 를 **세션 쿠키와 같은 비밀키**로 서명해 낸다(TTL 1년 · ⌜관리웹이 QR 로 그려 보이고 기기가 스캔⌝). 없는 것은 **검증**뿐이다(`session-resolver.service.ts:47-54` 는 `typ:'session'` 만 받는다). ⇒ **그 QR 등록 토큰이 곧 API `Authorization: Bearer` 인가**를 계약·화면 어디에도 적지 않았다.
ⓒ 같은 계약 안에서 **required 가 비대칭**이다 — `ProductionResult.terminalId` 는 required 가 **아니고**(I-7 이 그래서 비웠다) `MaterialConsumption.terminalId`·`WorkSession.terminalId` 는 **required** 다.
ⓓ 화면(`M-CO-01`·`P-CO-01`·`M-01-13`)은 ⌜POP·모바일 셸에 **계정 로그인이 없다** — 단말 토큰 + 사번⌝ 인데 서버 `AuthenticationGuard` 는 전 오퍼레이션에 **계정 세션 쿠키**를 요구한다 ⇒ **인증 축이 화면과 서버에서 갈려 있다**. I-7·I-9 가 이미 그 위에 POP 오퍼레이션을 얹었다.
ⓔ ⭐ **그래서 두 슬라이스의 답이 서로 다르다** — 세션 열기만 계약이 ⌜단말 게이팅(`can_start_work`)을 **서버가 강제한다**⌝ 라 적어 토큰 부재를 **403** 으로 막았고, 투입·반출은 그 문장이 **0줄**이라 값을 **비운 채 기록**한다(비우지 않으면 오늘 그 헤더를 보내는 클라이언트가 0이라 `P-02-03`·`P-02-11`·`P-02-12` 투입이 전건 400 = 업무를 없애는 거부다). **두 답이 갈린 이유는 계약 문장 하나**다.
ⓕ 화면 인용 셋이 「토큰이 인증이다」 쪽을 지지한다 — `P-CO-01` §5-4 요청 예시 ⌜`Authorization: Bearer <단말 토큰>` ← **인증** / `X-Worker-No` ← **귀속. 인증 아님**⌝ · `P-CO-01` §5-1 3층표 ⌜인증 = 단말 토큰 = **유일한 보안 경계**⌝ · 그런데 서버 `authentication.guard.ts:24` 는 그 반대에 서 있다.

**⇒ 회신 질문은 하나다. 「단말 인증을 언제 세우나.」** 그때 세션 열기의 403 은 401 이 되고, 투입·반출의 비움은 채움이 된다.

## 지금 서버는

- 마이그 **M-1** `material_consumption.terminal_id` NOT NULL 완화(`20260907700000`) — 세 안(A 완화+키 생략 / B 항상 400 / C 절충) 중 **어느 것을 골라도 토큰 없이 오는 호출을 400 으로 죽이지 않는 한 이 칸은 nullable 이어야 한다**. 투입 응답은 `terminalId` 키를 **생략**한다(`plan.md` §5 규칙 7 · 계약 required 를 못 맞춘다).
- `src/auth/terminal-token.ts` — 헤더가 **없으면 `null`**(던지지 않는다 · 「없음」과 「틀림」은 다르다 · `M-CO-01` §6) · 오면 서명·`typ`·행 존재·`is_active`·`token_version` 을 보고 어긋나면 400 `INVALID`.
- `POST /work-sessions` **하나만** `terminalId === null` 에서 403 `PERMISSION_DENIED`(게이팅 조회 «전») · `work_session.terminal_id` 는 **NOT NULL 그대로**(완화 불요) · `:end`·events 는 토큰이 오면 `work_session_event.terminal_id` 를 채우고 없으면 비운다.
- ⛔ `AuthenticationGuard`·`Session` 타입 **무변경** · `terminal_process` 게이팅은 세션 열기(`can_start_work`)에만 걸고 투입·반출의 `can_input_material`·`can_return_material` 은 **안 건다**(토큰이 «오는 호출에서만» 걸리면 반쪽 게이트 · A-21).
