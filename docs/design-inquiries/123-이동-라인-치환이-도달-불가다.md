# 123. 이동 라인 치환이 도달 불가다 — 400 이 유일한 응답이고 부르는 화면도 0건이다

| 칸 | 내용 |
|---|---|
| **구분** | **통보** — 본질이 아니고(치환 경로), 자물쇠 한 자리라 되돌리는 비용이 낮다 |
| 걸리는 오퍼레이션 | `PUT /logistics/stock-transfers/{stockTransferId}/lines` |
| 구현 상태 | **미구현**(I-13 PR ④ 예정) — 계획은 **자물쇠까지만** 짓는다(404 → If-Match 409 → 400 `STATE_LOCKED`) · 치환 본체를 짓지 않는다 |
| 판정 | `coverage-100/README.md` §2 1단계 **본길**(모든 호출의 결과가 같다) → 계약 문자 그대로 + 문의 |
| 되돌릴 때 | 「반출 전 단계를 되살려라」면 `:depart` 신설 + 상태값 추가 + 치환 본체(`goods-issue-update.service.ts:50-153` 복제 ≈100줄) · 「지워라」면 계약에서 path 하나 삭제 |

## 무엇이 문제인가

ⓐ 계약이 라인 치환을 **반출 전에만** 허용한다 — `StockTransferLineUpsert.description` 「이동 라인 치환 항목. **반출이 끝난 라인은 바꿀 수 없다 — 400 STATE_LOCKED.**」(`contracts/logistics-01자재창고.json:14358` · path description 도 같은 취지 `:5619`).
ⓑ 그런데 같은 계약이 **반출 전 상태를 없앴다.** `StockTransferCreate.description` 「반출 등록. **반출 스캔이 곧 이동 문서를 만드는 행위이므로 생성과 반출이 한 오퍼레이션이다** — 둘로 나누면 오프라인 큐에 반출 전 상태가 남는다. 근거: M-01-10 §5-6」(`contracts/…:14141`), `POST` x-internal-note 「**도출 단계의 `:depart` 를 두지 않는다**」(`contracts/…:5529`).
ⓒ ⇒ 라인은 **태어나는 순간 반출이 끝나 있다** — `shipped_qty = requested_qty > 0`(물리 CHECK `requested_qty > 0`). 자물쇠 조건(`shipped_at IS NOT NULL`)을 **언제나** 지난다.
ⓓ 반출 전 `stock_transfer` 를 만드는 오퍼레이션이 계약 487건에 **0건**이다 — `stock-transfers` path 넷 외에 `stock_transfer` 를 만드는 경로는 `POST /logistics/stock-reinstatements`(재고 재등록 · I-23) 하나이고 그쪽도 「반출·도착을 함께 낸다」(`.design-reference/…/screens/04/W-04-11-재고재등록.md:137` §5-3).
ⓔ **부르는 화면도 0건**이다 — `docs/coverage-100/plan-uiux.md:254` 가 이 오퍼레이션의 화면을 「—」로 적었고, `M-01-10` §5-6 액션 7종에 「라인 편집」이 없다.
ⓕ 그런데 계약은 이 오퍼레이션에 **403 을 선언했다**(`contracts/…:5583` `responses.403`) — 서버 권한 게이트는 403 선언이 있으면 소유 화면 등록을 요구하고, 미등록이면 **던진다(500)**(`src/common/permissions/permission.guard.ts:35-40`). 소유 화면이 없으므로 서버가 `M-01-10` 을 **잠정으로** 적어 넣어야 한다 — 근거 없는 등록이다(문의 **050** 과 같은 형상).

## 지금 서버는

- 아직 이 오퍼레이션을 열지 않았다(`stock-transfer.controller.ts` 에 핸들러 4개 — `GET` 셋 + `POST` 하나 · `PUT` 없음).
- 열 때의 계획은 잠금 → If-Match(**필수** · 어긋나면 409) → `shipped_at IS NOT NULL` 이면 **400 `STATE_LOCKED`**(field `items`) 순서이고, 그 뒤 치환 본체는 **짓지 않는다**(도달 불가 코드를 남기지 않는다). `version_no` 도 올리지 않는다.
- `X-Worker-No` 는 계약이 이 경로에 안 실었으므로 받지 않는다. ETag 도 안 내린다.

⇒ **묻는 것**: 이 오퍼레이션을 계약에 남길 것인가(남기면 소유 화면을 지정해 403 근거를 준다), 아니면 **반출 전 단계(`:depart` 분리)를 되살려 치환이 실제로 닿게 할 것인가** — 어느 쪽도 아니면 path 를 폐기한다.
