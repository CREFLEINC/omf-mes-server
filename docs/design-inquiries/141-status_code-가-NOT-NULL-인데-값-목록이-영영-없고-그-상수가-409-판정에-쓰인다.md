# 141. `handling_unit.status_code` 가 NOT NULL 인데 값 목록이 「영영 오지 않는다」로 닫혔고, 그 자리를 메운 서버 상수가 **거부 판정(409)에 쓰인다**

> 첫 줄에 적어 둔다. **문의 053 의 파생**이다 — 「값 목록 없는 NOT NULL 코드를 서버가 잠정 문자열로 메웠다」는 모양이 같다. 다만 053 은 ⌜상수를 **판정에는 쓰지 않는다**(조회도 이 값을 대조하지 않는다)⌝ 로 위험을 닫아 두었는데, **여기 상수는 `:pack` 의 409 판정과 두 화면의 목록 필터에 쓰인다.** 값 목록이 나중에 오면 저장 데이터가 아니라 **거부 동작과 화면 목록**이 바뀐다 — 그래서 053 에 합치지 않고 새 번호로 연다.

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /inventory/handling-units/{handlingUnitId}:pack` · `POST /inventory/handling-units` · `GET /inventory/handling-units`(질의 `statusCode`) |
| 구현 상태 | **구현 예정(I-16 · 계획만 병합됨 · 오늘 코드 0줄)** |
| 판정 | `coverage-100/README.md` §2 **1단계 본길**(계약이 규칙은 문장으로 줬고 값만 안 줬다 → 계약 문자 그대로 + 문의) → **2단계 기준 3**(스키마를 안 늘린다 — 칸은 이미 있다 · 마이그 0) **· 기준 4**(값을 조용히 도출하지 않고 이름을 붙여 한 파일에 모은다) |
| 되돌릴 때 | 값 목록이 오면 `src/inventory/handling-unit/handling-unit-status.ts` **두 줄**. ⚠ 다만 값이 셋 이상으로 오면 `:pack` 의 409 조건과 e2e 4건이 함께 바뀐다 |

## 무엇이 문제인가

ⓐ **칸은 NOT NULL 인데 계약이 값 목록을 「영영 세우지 않는다」로 닫았다.** 물리는 `status_code app.code_t NOT NULL`(`prisma/migrations/20260727000000_baseline_physical_model_v3/migration.sql:1244`)이고, 계약 `x-no-code-key` 원문은 두 곳에 같다(`contracts/logistics-01자재창고.json:1239` 질의 파라미터 · `:8547` 스키마 프로퍼티):

> 「코드 그룹을 세우지 않는다 — 이 리소스는 «전표»가 아니라 «물건»(팔레트·박스 같은 담는 그릇)이다. … 담긴 것의 진행은 :pack · /contents · /repack-events 가 이미 담고, 라벨 발행 여부는 boolean 축이면 충분하다(InboundReceiptLine.labelIssued 선례). ⚠ P-02-08 §8-4 가 「포장 해체 화면이 없다」고 적어 뒤쪽 값이 업무에 없다 — 해체 업무가 서면 그때 세운다(A-21 · 사용자 결정 2026-09-02).」

nullable 로 물러설 수도 없다 — 계약 `HandlingUnit.required` 4칸에 `statusCode` 가 들어 있다(`contracts/logistics-01자재창고.json:8485-8489`).

ⓑ **그런데 같은 계약이 그 칸으로 «거부»를 요구한다.** `:pack` description 원문(`contracts/logistics-01자재창고.json:1585`): 「포장 단위와 내용물 N행을 한 트랜잭션으로 확정한다(공유계약 B-8). 내용물이 비면 400 이다. **이미 확정된 포장은 409 다.** …」 ⇒ 「확정 전」과 「확정 후」를 가릴 축이 데이터에 있어야 하고, 그 축은 이 칸뿐이다. **상수 하나로는 못 선다.**

ⓒ **두 화면이 이 칸으로 목록을 거르는데, 넣을 값이 정해지지 않았다.**

- `P-04-01-Packing실적등록.md:172` — 「`GET /inventory/handling-units?warehouseId={배분 응답의 warehouseId}&statusCode={포장 가능}`」. 「포장 가능」의 문자열이 없다.
- `P-04-04-재구성신규라벨발행.md:175` — 「대기 목록 조회 | 항상 — **상태 = 라벨 발행 대기**」 · `:108` 「① 발행 대기 목록이 **그 상태 값으로 걸러진다.** 값 목록이 정해질 때까지 **자리표시 상수**를 쓴다(G-2)」 · `:106` 「⛔ **넘기는 상태를 담을 자리가 없다** — 재구성 이벤트 테이블이 0건이라 `handling_unit.status_code` 값으로 물러났다」.
- ⚠ 그런데 그 「라벨 발행 대기」 퇴로는 **설계가 스스로 철회했다** — `M-04-03-포장재구성스캔.md:234` 「⛔ **그 퇴로가 닫혔다(2026-09-03)** — 계약이 그 칸을 「코드 그룹을 세우지 않는다」로 판정했다(미결 3). 중간 상태를 담는 자리는 이 칸이 아니라 **재구성 이벤트**(`/repack-events`)다」. ⇒ 서버는 셋으로 늘리지 않았고, 그러면 `P-04-04` ①이 걸 값이 **한 개도 남지 않는다**(그 결과가 문의 145 다).

## 지금 서버는

- **아직 없다.** 계획이 정한 동작은 **상수 «둘»** 이다 — `HU_STATUS_OPEN = 'OPEN'`(등록됐고 아직 확정 전) · `HU_STATUS_PACKED = 'PACKED'`(`:pack` 이 닫았다). 한 파일(`handling-unit-status.ts`)에 `// 설계 미정 — 문의 141` 주석과 함께 둔다.
- `POST /inventory/handling-units` 초기값 = `'OPEN'` · `:pack` 이 `'PACKED'` 로 올린다 · `PUT …/contents` 는 **상태를 안 옮긴다** · **되돌리는 전이는 0**(문의 142).
- ⛔ 053 과 달리 **판정에 쓴다** — `:pack` 이 `status_code === 'PACKED'` 이면 409 를 낸다. `GET` 질의의 `statusCode` 는 대조하지 않고 문자를 그대로 넘긴다(없는 코드로 물으면 빈 목록이 정상).
- `mdm.code_group` 에 이 축의 그룹은 **0건**이다(DB 실측 · `HANDLING_UNIT_TYPE` 3값 BOX·CART·PALLET 은 별개 축).

⇒ **묻는 것**: `'OPEN'`·`'PACKED'` **둘**이 맞는가(값 목록 없이 서버가 이름을 짓는 것이 맞는가) · 두 화면 필터(`P-04-01` 「포장 가능」 · `P-04-04` 「라벨 발행 대기」)에 각각 어느 값이 들어가는가.
