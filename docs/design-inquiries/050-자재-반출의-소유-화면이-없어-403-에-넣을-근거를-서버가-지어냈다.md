# 50. `POST /production/material-returns` 의 소유 화면이 없어 403 게이트에 넣을 근거를 서버가 지어내야 한다

| 칸 | 내용 |
|---|---|
| 걸리는 오퍼레이션 | `POST /production/material-returns` |
| 구현 상태 | **구현함(I-10 · `manual-permissions.ts` 에 `P-02-03` 하나로 임시 등록 · 근거 주석 동봉)** |
| 판정 | `coverage-100/README.md` §2 **0단계 선례**(부르는 화면이 0건이어도 가드가 등록을 요구하는 같은 형상 셋 — `PUT /logistics/goods-issues/{id}/lines` · `PUT /logistics/inbound-receipts/{id}` · `…/lines` ⇒ **넷째**) · 인가 정책이라 1단계 **본길** → 2단계 기준 5(새 권한 0) + 기준 2(가장 좁은 문) |
| 되돌릴 때 | 소유 화면이 정해지면 `manual-permissions.ts:192` **한 줄**을 그 화면 코드로 바꾼다(마이그 0 · 넓히는 것은 완화). 관리웹 화면으로 정해지면 `X-Worker-No` 400 `REQUIRED` 도 `plan.md` §5 규칙 9 대로 푼다 — 그 400 은 「소유 화면이 POP」을 전제로 선 것이다 |

## 무엇이 문제인가

ⓐ 계약이 스스로 ⌜2026-08-26 … 부르는 화면이 아직 매핑되지 않았다 — **소유 화면이 정해지면 근거를 다시 적는다**⌝ 라 적었고, screens 118장 전체 grep 에서 `material-returns` 가 **0건**이다.
ⓑ 그런데 계약이 **403 을 선언**했고 우리 권한 가드는 미등록 오퍼레이션에서 `Error` 를 던져 **500** 을 낸다(`permission.guard.ts:47-53`) — 「등록하지 않음」이 선택지가 아니다.
ⓒ 빈 배열(= 아무도 못 한다)도 `operation-permissions.spec.ts` 가 막는다(빈 권한 목록 금지 · 실측).
ⓓ ⇒ 서버가 **인가 정책을 임의로 지었다**. 오늘 이 W/O 의 자재를 만지는 유일한 POP 화면이 `P-02-03` 이고 `derived-permissions.ts:229` 가 투입에 이미 준 권한이라 **새 권한을 만들지 않는 쪽**을 골랐을 뿐, 「업무가 비슷해서」가 아니다.
ⓔ 잔재 하나 — 같은 자원의 `GET /production/material-returns`·`GET …/{id}` 는 description 이 아직 ⌜근거: `M-02-02` §3⌝ 다(2026-08-26 에 철회된 것은 `POST` 하나). 한 자원의 세 오퍼레이션이 서로 다른 근거를 든다.
ⓕ 화면 물증 둘: `W-CO-06` §4-B 의 **`can_return_material`(자재 반납)이 POP 단말 8플래그의 하나**인데 그 플래그를 소비하는 화면이 0건이고, `plan-uiux.md` 57행 U23 표의 화면 열도 `P-02-03` 하나다.

## 지금 서버는

- `manual-permissions.ts:192` 에 `'POST /production/material-returns': ['P-02-03']` 한 줄 + ⌜설계 미정 — 문의 050. 계약이 소유 화면을 비워 두었다(2026-08-26). 회신이 오면 이 한 줄을 그 화면으로 바꾼다⌝ 주석.
- `permission.guard.ts` 는 **고치지 않았다** — 「403 선언 오퍼레이션을 가드가 통과시킨다」는 인가를 넓히는 코어 변경이다.
- e2e `무권한 사용자는 403` 이 이 등록이 살아 있음을 증명한다(미등록이면 500 이 난다).

흔적: `docs/coverage-100/slices/I-10.md` §4-1 · R-10 · §8-1 #6 · `manual-permissions.ts:192` · `material-return.controller.ts:26`.
