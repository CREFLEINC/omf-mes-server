# 기존 구현에서 건져낸 도메인 규칙

> 출처: `3adb46e` 의 `src/master-data` 와 README. 삭제([ADR 0001](./adr/0001-mdm-api-rewrite-on-spec.md))
> 전에 옮겨 둔 것으로, 재작성 시 여기서 규칙을 가져온다.
> 계약 문서는 이들을 `400 ErrorItem{code}` 형태로만 말하고 규칙 내용은 담지 않는다.

## 전 마스터 공통

| 규칙 | 내용 |
|---|---|
| 삭제 = 사용 중지 | 정본 모델에 소프트 삭제 컬럼이 없다. `is_active=false` 가 수명주기 플래그이며, 마스터는 타 테이블이 FK 로 참조하므로 물리 삭제하지 않는다 |
| 참조 무결성 | 사용 중(`is_active=true`) 하위 행이 남은 상위 마스터는 사용 중지를 거부한다 |
| 유효기간 | `code_value.effective_from/to`. DB 의 `ck_code_value_dates` 제약과 같은 규칙을 앱에서 먼저 검사해 메시지를 준다 |
| 감사 컬럼 | `created_at/by` · `updated_at/by` 에 인증된 주체의 `app_user_id` 를 기록한다 |
| 낙관적 잠금 | 수정 시 `version_no` 를 증가시킨다. 클라이언트가 기대 버전을 보내 충돌을 거르는 부분은 미구현이었다 — 계약의 `If-Match`/`ETag` 가 이 자리다 |

## 마스터별

| 마스터 | 규칙 |
|---|---|
| 창고 | 외부창고(`is_external=true`)면 거래처가 필수다 — `ck_external_warehouse_partner` |
| 창고 | 사용 중인 하위 로케이션이 남아 있으면 사용 중지를 거부한다 |
| 로케이션 | 상위 로케이션 지정 시 순환을 막는다 |
| 로케이션 | 수용량과 수용단위는 쌍이다 — 한쪽만 오면 거부한다 |
| 창고·생산라인·설비 | `(plant_id, code)` 로만 유일하다. 전역 유일이 아니므로 코드만으로 조회하면 여러 공장에 같은 코드가 있을 때 조용히 첫 건을 고르면 안 된다 |
| 코드그룹 | 사용 중인 코드값이 남아 있으면 사용 중지를 거부한다 |
| 전 마스터 | 코드 필드는 `code_value` 에 등재된 값인지 검사한다 (창고: `WAREHOUSE_TYPE`·`MANAGEMENT_LEVEL`, 로케이션: `LOCATION_TYPE`·`QUALITY_ZONE`·`STORAGE_CONDITION` 등) |

## 정본 모델과 요구사항 사이의 미결

| 항목 | 내용 |
|---|---|
| 다국어 (ko/vi) | 정본 물리 모델에 다국어 컬럼이 없다 (`code_name` 단일). 모델링 문서 전체에 다국어 언급이 없고 이연 목록에도 없으나, REQ-PR-0012·QA #33 은 "전범위 확정(UI+마스터 명칭 한/베+출력물)"이다. 정본을 임의 변형하지 않고 두었다. 계약 문서도 창고 스키마에 "미착지: 다국어(한/베) 명칭 — #64"로 같은 문제를 적고 있다 |
| ERP 연계 출처 마커 | 정본에 ERP/MES 출처 컬럼이 없다. "연계 원본 필드 읽기 전용" 규칙을 걸 지점이 없다. **계약의 `editability.reason: RECEIVED_FROM_ERP` 를 판정할 근거가 이것이다** — 없으므로 테이블 단위로 코드에 박거나, 출처 컬럼을 정본에 요청해야 한다 |
| 물리 삭제 행위자 미기록 | 매핑·이력 테이블(품목 환산·외부코드·사업부매핑, 거래처 역할, 단말-공정, 작업자 자격, 역할 권한·배정, 접근범위)은 물리 삭제라 감사 컬럼이 없다. "누가 지웠나"가 남지 않는다 |
| 트랜잭션 참조 검사 | 금형·작업자·거래처는 참조처가 대부분 트랜잭션이라 "미결 작업지시/발주가 쓰면 막는다"를 판정할 수 없다. 단순 존재 검사를 걸면 한 번이라도 쓰인 마스터가 영영 사용 중지되지 않는다. **계약의 `referenceCount` 가 이 문제를 그대로 물려받는다** |
| 변경 이력 미연결 | 정본에 `audit.audit_event` 가 있으나 쓰지 않았다. 계약도 개별 `/history` 엔드포인트를 미루고 횡단 `GET /audit/events` 하나로 받는다 — `target_id` 가 FK 가 아니고 `before_value`/`after_value` jsonb 의 키 규약이 없기 때문 |
